# 旧 loop 总结解析器（仅兼容与离线回放）

当前 CLI/daemon 不调用此组件，不再读总结出卡。当前事件接入见 `core/loop-intake.ts`、托管链路见 `core/managed-loop.ts`，配置和替身用法见[使用说明](../../../使用说明.md)。以下只说明保留的旧格式解析行为，不是当前运行协议。

- **能让它做什么**：无。

- **读取**：只认显式 `sources.loop` 下 `<项目目录>/<UUID>.md`，文件名可有 `claude-`、`codex-` 前缀。只列根及项目内一层，逐行提取核心字段、不整份加载，不递归；根文件、评审输入、验收材料、日志、状态文件，以及根下 `resources`、`projects`、`pipelines` 都不读。不跟随文件或目录符号链接；无读权限的文件跳过、不计失明。
- **配置改动**：不改 loop 的任何配置。
- **调用**：只供兼容测试、历史回放的显式库调用；当前 `detect` 不从 `sources.loop` 读取总结。
- **保留**：不改动任何总结或旧数据；当前停用事件接入用 `inboxDir:null`。
- **产出**：一轮运行一条 `loop_run` 记录；工具、开发会话标识、总结路径/SHA-256、**「- 项目：」行的项目路径**、状态结论、评审/返修次数、「需要你做的事」「小问题汇总」「验收额外发现」及全文 `[人工]` 欠项清单、最后轮次时间。没有开工指令时意图明确标为缺失，不从验收标准伪造用户原文。批名只取总结明确的批次/任务字段，不再扫描开发聊天补全；当前步骤与关联开发/评审/验收会话单独存放，展示字段不改变旧总结去重键。
- **状态**：`完成` → 已完成；`暂停（原因）` → 在等我；`进行中` 只呈现总结状态，无可靠活动证据时不按总结年龄判停滞或搁置。暂停/完成提醒由 core 应用原有首次历史抑制/暂停已搁置规则，并非读到旧完成/暂停就补发。暂停原因和待办都进入证据；合并提取各欠项段与 `[人工]` 行，排除表头/分隔行、明确的无和已勾完成项，去重后列出；没有任何欠项写「还欠什么：无」。
- **时间**：最后一个「第 N 轮」的无时区时间按运行机器当地时区解析（OS/TZ，含夏令时），不再当 UTC。没有轮次时间时使用该原件的文件修改时间（mtime），不因此报失明；这是本轮真实回放后用户补充的规则。本段不再扫描 AI 会话目录，保留总结所见时间供兼容展示，但轮次开始/mtime不能作为实际活动证据，不据此生成或重试停滞卡；本段立即执行这一保护，不等待后段事件/查状态。阶段仍来自总结中的开发/评审第几轮/验收，不把验收条款当作进度。缺少状态/项目/次数等真正总结核心字段仍报文件故障，不伪造；普通权限跳过不计为非会话跳过率异常。
- **过滤/失败**：`ignoreProjectPrefixes` 按总结内项目路径过滤；坏总结按来源合并数量和至多 3 例、提醒正文不超过 4 KB，其余照常。只有根目录读不了或核心信号整体取不到才报来源失明。
- **回去看**：`open <总结路径>`，只输出命令，不启动工具，也不把目录名当项目名。
