# loop 来源组件

- **能让它做什么**：无。

- **读取**：只认显式 `sources.loop` 下 `<项目目录>/<UUID>.md`，文件名可有 `claude-`、`codex-` 前缀。只列根及项目内一层，逐行提取核心字段、不整份加载，不递归；根文件、评审输入、验收材料、日志、状态文件，以及根下 `resources`、`projects`、`pipelines` 都不读。不跟随文件或目录符号链接；无读权限的文件跳过、不计失明。
- **配置改动**：不改 loop 的任何配置。
- **安装**：在 personal agent 配置中填写总结目录，运行 `detect`，见[使用说明](../../../使用说明.md)。不需要运行 loop。
- **卸载**：`sources.loop=null`，不改动任何总结。
- **产出**：一轮运行一条 `loop_run` 记录；工具、开发会话标识、总结路径/SHA-256、**「- 项目：」行的项目路径**、状态结论、评审/返修次数、「需要你做的事」清单、最后轮次时间。没有开工指令时意图明确标为缺失，不从验收标准伪造用户原文。
- **状态**：`完成` → 已完成；`暂停（原因）` → 在等我；`进行中` 按活动规则判断。提醒由 core 统一应用首次历史抑制/已搁置规则，并非读到旧完成/暂停就补发。暂停原因和待办都进入证据；缺「需要你做的事」段时写「总结里没写」，仅明确写无的总结才说没有待办。
- **时间**：最后一个「第 N 轮」的无时区时间按运行机器当地时区解析（OS/TZ，含夏令时），不再当 UTC。没有轮次时间时使用该原件的文件修改时间（mtime），不因此报失明；这是本轮真实回放后用户补充的规则。缺少状态/项目/次数等真正总结核心字段仍报文件故障，不伪造；普通权限跳过不计为非会话跳过率异常。
- **过滤/失败**：`ignoreProjectPrefixes` 按总结内项目路径过滤；坏总结按来源合并数量和至多 3 例、提醒正文不超过 4 KB，其余照常。只有根目录读不了或核心信号整体取不到才报来源失明。
- **回去看**：`open <总结路径>`，只输出命令，不启动工具，也不把目录名当项目名。
