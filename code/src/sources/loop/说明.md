# loop 来源组件

- **读取**：显式 `sources.loop` 下的 Markdown 总结；不读会话、不读运行数据库。明确排除 `交付记录.md`、`README.md`、`说明.md`；其余文件应是某次运行的总结，不可解析就报警。
- **配置改动**：不改 loop 的任何配置。
- **安装**：在 personal agent 配置中填写总结目录，运行 `detect`，见[使用说明](../../../使用说明.md)。不需要运行 loop。
- **卸载**：`sources.loop=null`，不改动任何总结。
- **产出**：一轮运行一条 `loop_run` 记录；工具、开发会话标识、总结路径/SHA-256、**「- 项目：」行的项目路径**、状态结论、评审/返修次数、「需要你做的事」清单、最后轮次时间。没有开工指令时意图明确标为缺失，不从验收标准伪造用户原文。
- **状态**：`完成` → 已完成并发「有空看」交代；`暂停（原因）` → 在等我并发「现在就要你」；`进行中` 按活动规则判断。暂停原因和待办都进入证据。
- **时间**：取总结最后一个「第 N 轮」时间，不用复制后的文件修改时间；当前摸底格式的轮次无时区，本批明确按 UTC 解读。缺少轮次时间或次数的格式报失明，不伪造时间。将来接入真实来源前需核对时区和格式。
- **回去看**：`open <总结路径>`，只输出命令，不启动工具，也不把目录名当项目名。
