# Pi 来源组件

- **能让它做什么**：无。

- **读取**：显式 `sources.pi` 下的 `.jsonl`，及显式 `inboxDir/pi.jsonl`。只读逐行，不跟随符号链接，不打开推送中另指的文件。树索引仅保存节点定位和有限核心内容，不保留思考/图片/工具输出/自定义大正文。
- **配置改动**：不改 Pi 配置，不装扩展或权限钩子。
- **安装**：无需 Pi 插件；在 personal agent 配置中填目录，运行 `detect`，见[使用说明](../../../使用说明.md)。
- **卸载**：`sources.pi=null`；如停用全部推送再设 `inboxDir=null`，不动会话。
- **产出**：统一记录中的工具、会话标识、原件路径/SHA-256、首行 `cwd` 起始项目、按原件保留的结构化目录历史（仅供推送对账）、当前分支的开工原文/追加要求、最近步骤、未返回调用、助手收尾事实和最后活动时间。
- **适配规则**：支持 v2/v3 树形 JSONL，树形核心字段兼容时不因版本号新增就拒绝整份；语法完整的 v1 老格式明确跳过，不迁移、不报失明；即使版本预筛提前返回，也会逐行校验剩余 JSON，损坏尾行仍是文件故障。从最后有效消息/已知分支节点沿 `parentId` 走到根，只读当前分支，不平铺废弃分支。未知记录可作必要的树连接点，但不抢占当前叶子、不校验无关时间/字段。用户意图来自 `message.role=user`，排除已标记的系统输入；`custom_message`、`custom`、`branch_summary`、`compaction` 等都不是用户要求。保留压缩前同一分支上的用户原文，不用压缩摘要代替本人指令。工具调用和 `toolResult` 按 id 配对；`stopReason=stop` 且无未返回调用可判本轮答完。
- **跳过/失败/限制**：完整可解析但无 `session` 身份、无核心消息，或 v1 文件，跳过并计数、不算读不了。仅当文件恰有一条助手消息指向从未写入的父编号，且紧邻前行是 toolResult 或 context_edit 时，将其接到前行继续解析；其他断链、多个缺口、成环、有效节点重复或文件不完整仍计该文件失败，按来源合并、至多 3 例、正文 <=4 KB；其他会话不失明。目录不可读、真正核心整体不可用或跳过率明显高于健康基线才报失明；阈值见[使用说明](../../../使用说明.md)。`ignoreProjectPrefixes` 可过滤项目及推送。尚未写入文件的纯 `/tree` 导航无法从 JSONL 观察；按最后有效持久化节点判断，下一次写入后更新。
- **格式参考**：Pi 安装文档 `docs/session-format.md`、`docs/message-types.md`；没有引入 Pi SDK 运行依赖。
- **失败提案**：`stopReason=error/aborted` 的助手消息中的 `toolCall` 没有实际执行，不登记为未返回工具；之后重试正常答完可完成。其他真正发出的调用仍须等对应结果。
- **推送生产者**：独立的 [message-listener 扩展](../../hooks/pi/说明.md)。
- **回去看**：`<commands.pi> --session <sessionId>`，只生成命令文字。
