# Codex 来源组件

- **读取**：显式 `sources.codex` 下的 `.jsonl`，及显式 `inboxDir/codex.jsonl`；只读，不跟随来源符号链接，不跟随推送的 `transcript_path` 去打开未配置文件。
- **配置改动**：不改 Codex 配置、钩子或 `notify`。
- **安装**：无需 Codex 插件；在 personal agent 配置中填写目录和 `commands.codex`（可执行文件路径，不是带参数的命令串），运行 `detect`。本批只配样本，见[使用说明](../../../使用说明.md)。
- **卸载**：`sources.codex=null`；如停用全部推送再设 `inboxDir=null`。原件原样保留。
- **产出**：统一记录中的工具、会话标识、原件路径/SHA-256、`session_meta.cwd` 项目、意图、最近步骤、未返回调用、完成/结束事实、最后活动时间。子代理的路径、活动和工具调用并入父会话，不把派给子代理的任务当作用户追加要求。
- **适配规则**：开工和追加要求只取 `event_msg/user_message`，不重复取 `response_item` 用户副本；排除明确标记为系统/loop/通知的输入。支持 `task_started`、`task_complete`、`turn_aborted`、`response_item` 和 `item_completed` 的调用/结果。`commentary` 不算完成；完整助手答复无未返回调用可按本批规则判完成。调用自身的 `status=completed` 不等于工具结果已返回，仍按 `call_id` 配对。
- **子代理**：支持 `session_meta.parent_session_id` 或 `source.subagent.thread_spawn.parent_thread_id`；找不到父会话或关系成环就报失明，不编造父任务。父记录保留各成员独立的会话 ID、项目、原件、活动时间与工具事实。推送先按实际成员对账，再归到根父记录判断：子成员等待会让父记录显示「在等我」，回看命令定位实际等待的成员；父/兄弟的新动静不解除它的等待，子成员结束不会误结束父成员或其他会话。
- **推送信任边界**：收到原始推送不等于对账通过。只有追加过明确 `push_validated` 结果的推送参与判断；匹配成员自己的原件，不只检查父记录的聚合路径。旧日志中未经校验的推送不会因故障恢复自动生效，参见使用说明的兼容与备份步骤。
- **失败**：格式变化/坏文件按 Codex 来源合并报警，不妨碍其他来源；新格式需补样本后更新适配。
- **回去看**：`<commands.codex> resume <sessionId>`，路径有空格时自动 shell 引用；从不启动 Codex。
