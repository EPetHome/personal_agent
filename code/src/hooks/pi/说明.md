# Pi message-listener 扩展

- **能让它做什么**：无。
- **读取**：`session_start/session_switch` 的会话元数据（仅 `cwd`、`getSessionId()`、`getSessionFile()`）和事件参数；`message_end` 中已传入的最终助手文本。不读会话文件，不调用 `getBranch/getEntries`，不读权限扩展配置，不连网。
- **配置改动**：只在目标 `<home>/.pi/agent/settings.json` 的 `extensions` 里增加独立扩展文件路径；不修改现有扩展、工具或权限处理器。所有运行资源只使用 Node 内置模块，不依赖 Pi SDK 安装副本。
- **安装**：`node code/src/hooks/main.ts install --tool pi --home <绝对目标主目录> --inbox <绝对推送目录>`。先备份目标设置原始字节和权限，再生成 `<home>/.message-listener/pi/message-listener.ts` 及内部模块，包自带 `type: module`。无真实安装时可用 API 替身直接触发扩展事件；见[使用说明](../../../使用说明.md)。
- **卸载**：`node code/src/hooks/main.ts uninstall --tool pi --home <同一主目录>`；恢复设置的精确字节、移除安装包，保留 `.message-listener-backups/pi.json.removed`。安装后另有修改时拒绝覆盖。停用扩展后不删任何推送/事实数据。
- **安装失败与恢复**：共用带原子状态记录的安装器；已经回滚的失败安装只清理包/归档备份，不再次覆盖用户设置。安装/恢复未完成或缺少指纹的旧备份拒绝自动恢复，须先备份并人工核对。
- **产出**：权限扩展事件总线 `permissions:ui_prompt` → `waiting_permission`；`agent_settled` → `turn_end`（detail 为本轮最后助手回复）；`session_shutdown` → `session_end`。写入 `<inbox>/pi.jsonl`，字段与 CC/Codex 相同。等待通知没有 stdin 也无需派生子进程。
- **边界**：不监听 `tool_call`、不返回 `block/continue` 或工具结果、不通知终端、不更改会话。写入失败一律吞掉，事件处理返回 undefined。中枢不运行仍能正常使用 Pi。loop 的 `pi-dev --no-extensions` 不会发现这个扩展，本段不改 loop、不让当前开发会话加载它。
