# feishu 飞书渠道

- **能让它做什么**：无。只发给用户本人、记录反馈与经验确认，不派活、不回话给 AI、不叫停工具。
- **读取**：中枢的 `Notice`；配置数据目录的发件、消息映射、入站队列/处理记录和经验；真实模式才读显式 `.env` 或 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`。不读任何来源工具的配置或密钥。
- **配置改动**：personal agent 配置中的 `feishu`；`mode`、唯一用户 `receiverId`（open_id）、超时和可选 `envFile`。凭证不能放 JSON、样例、日志或提交；`.env` 已由根 `.gitignore` 忽略且必须在数据目录外。无配置不启用，旧渠道行为不变。
- **安装**：`npm ci --ignore-scripts` 安装锁定的官方 SDK。假模式无需账号、不联网；真实企业自建应用需用户发布机器人并配置长连接订阅 `im.message.receive_v1` 和 `card.action.trigger`。完整运行/人工步骤见[使用说明](../../../使用说明.md)。
- **卸载**：停止常驻，在配置中删 `feishu` 或置 null；保留日志、反馈和映射，不删除事实。不改来源配置，也不替用户删除应用。
- **发送**：同一 `Channel.send(notice)`，声明 `levels: ['现在就要你', '有空看']`，两级都发送。JSON 2.0 卡片第一屏依次交代谁（工具、项目、意图或批次轮数）、出了什么事、要不要你管、具体会话恢复命令或 loop 总结；时间用本机当地口语，内部路径/行号/原文仅放折叠证据。正确/误报按钮与本机通知共享文案；意图跳过图片/附件占位，无文字写「意图不明」；动作引子后跟列表时压成一行带上，时间后留空格；每条复盘标题只展示一次。经验复盘提供同意/改一下，隐藏值绑定发件快照中的经验审阅版本；回调在经验写锁内再核验当前版本，过期/旧格式无版本卡片不改状态，并提示查看最新复盘或用本机命令。机器关联键仅在隐藏 value，给人看的确认不含编号。
- **接收**：统一 `receive(ChannelReply)` 经独立反馈短锁落原 `feedback.jsonl`，检测持锁时也能马上记录和确认；读反馈/核对发件都有短锁，不能读到追加中的半行。卡片 API 与确认发送锁分开、共享映射只短锁读写；长连接只确认 2.5 秒内持久化的最小入站事实，超时返回失败让平台重投；后续队列落反馈/发确认，不在回调里跑模型。仅校验通过的本人私聊/按钮生效，引用精确映射提醒，未知引用不退回最近一条。直接「漏了 + 说明」不关联提醒。平台重投使用事件键去重，反馈与确认分别幂等；退出/重启重放队列。`create_time` 识别秒/毫秒/微秒，异常值回退收到时间并留 `timeNote`；单条处理失败按提醒缺失、反馈格式、锁异常、记录损坏、不安全文件、存储空间/权限/读写及未知问题等受控类别回一句人话，不记录原始错误，继续下一条。处理结果先追加，确认投递失败用独立 `replyCategory`，只重试确认、不覆盖处理原因；所有已有处理记录均不重新处理（包括已失败的、仅含 id 的及人工核销的旧点击）。
- **产出**：数据目录 `feishu-inbox.jsonl`、`feishu-receipts.jsonl`、`feishu-sent.jsonl`。假模式完整卡片和确认写 sent；真实模式 sent 只留消息/提醒关联元数据。所有盯防提醒、小结、复现、重启告警也进共用 `outbox.jsonl`；外部投递由 `channel_delivery` 单独确认，不拿文件成功冒充飞书成功。
- **可靠性与边界**：超时/失败总览标出，下轮重试；消息发送以固定 uuid 幂等，成功消息映射落盘。外部 API 和本地确认不是原子事务，平台幂等窗口之外或成功后本地确认前故障仍可能重复一次；不声称严格 exactly-once。SDK 原始日志不输出；连接失败只留受控类别与固定短说明，追加 `feishu_connection` 事件和 `service.log.jsonl` 记录，总览单列实际握手/重连/失败/停止状态。状态写入抢不到数据锁时独立每秒重试最新状态，不等待数据锁或挡住收件/检测；类别与字段见[使用说明](../../../使用说明.md)。不输出凭证或上游报文。自动验证只用文件假渠道和 transport 替身；真实卡片呈现/账号权限/长连接断网恢复仍留用户人工验收。
