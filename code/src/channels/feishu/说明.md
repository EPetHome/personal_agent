# 飞书渠道：当前托管卡与旧兼容

- CLI/daemon 用 `feishuChannel(config, transport?, {managed:true})`；新状态、消息映射、卡片版本、处理回执和连接状态唯一存于 `ledger.jsonl`。`feishu-sent.jsonl` 只作渠道审计，fake 模式另保留完整内容，不拿它恢复新事情。
- 新托管卡由 `managedCard` 渲染，`deliverManaged` 首发或更新账本指定的原 messageId；同批次一张卡。发送前由账本待发围栏放行。模型不能改问题原文、回调目标或硬红线。
- 本人点击先登记，核对消息、卡片版本、派工和意图版本；按建议、原选项、原话、继续、再给一轮只写待写，worker-adapter 才发送。未知引用/旧按钮不猜最近一件事。红线没有按建议一键；手写红线还需明确确认。
- 原卡已送到/已读/不确定、输入框、恢复状态只更新，不再次弹本机。明确拒收最多5次，之后仅给本机一次故障说明；结果不确定不新发第二张卡，更不重投 worker。
- 最小入站原件只追加到 `feishu-inbox.jsonl`，处理与回复确认在新账本；卡片API/回话API分锁，收件不等模型或 worker。秒/毫秒/微秒兼容，坏时间回退并说明。失败只记安全类别，不复制 SDK 原报文或凭证。
- fake 不联网、不读凭证；真实模式只从环境或数据目录外的已忽略 `.env` 取凭证。只接受 receiverId 本人的私聊/按钮。
- 原有反馈词只入账观测，不生成报告/复盘。旧卡反馈与显式 CC 转达保留旧格式兼容入口；不制造聊天新卡、不扫描聊天。普通飞书问答/派活留给后段。
- 默认不带 managed 选项的库调用仅供旧 Notice/旧 CC 卡兼容与历史回归；当前运行入口不据此恢复旧 loop 队列。
- 外部 API 与本地确认没有原子事务，不承诺严格 exactly-once。配置、替身收发、备份恢复、真实手机未验证范围见[使用说明](../../../使用说明.md)。
