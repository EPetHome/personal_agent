# local 本机渠道

- **能让它做什么**：无。
- **读取**：中枢传入的 `Notice`，不读会话或工具全局配置；收回复时仅读显式数据目录的发件记录来关联提醒。
- **配置改动**：只在 personal agent 显式配置中添加 `localChannel.executable` 和可选 `timeoutMs`；系统通知使用 `/usr/bin/osascript`，开发/门禁必须换测试替身。没有配置就不启动通知进程。
- **安装/卸载**：无需第三方软件；配置 `localChannel` 开启，删掉该项或设为 `null` 停用。系统通知权限由用户自行允许。本段不在真实环境装卸或弹通知。
- **发送**：统一接口 `send(notice: Notice): Promise<void>`。只对「现在就要你」调用通知可执行文件；固定 AppleScript，经 argv 传标题和摘要，不使用 shell，不执行材料。正文先用「这件事」写当前任务和卡点，再用「要你做」写问题或动作，最后写当地时间和回看命令，与飞书相同；不含项目路径、表格/代码块或模型理由，证据留在发件记录；模型的「可能」保留在标题。内部编号不放进标题/正文。「有空看」仅保留在文件发件记录。
- **接收**：`receive({ noticeId?, content, at }): Promise<string>`。`content` 为「正确 / 误报 / 漏了 / 看不懂」及可选说明；正确/误报省略编号关联最近一条盯防提醒（跳过周报/经验/服务消息），看不懂默认最近一张卡片（含周报/复盘）；`noticeId: null` 仅允许「漏了」明确不关联。本机入口 `node code/src/cli/main.ts feedback ... --config ...`，详见[使用说明](../../../使用说明.md)。检测占锁时仍用独立 `.feedback.lock` 随点随记，完整追加并同步落盘后回复「已记下」及效果（同会话同原因不再叫你，或已进本周问题汇总），不等整轮检测。反馈读取也经此短锁；只有反馈锁本身异常占用才有最多 30 秒的有界等待，超时说尚未记下、请检查本机服务，不清未知锁。正确只算有用、不收问题；误报立即按同会话同原因抑制，不影响其他会话。原卡片、原话和时间随反馈只追加留存，不会转发给来源 AI。
- **产出**：文件渠道始终写 `outbox.jsonl`；本机通知队列/结果以 `channel_delivery` 事件持久化，反馈追加 `feedback.jsonl`（日期、渠道、提醒编号或 null、结论、说明）。`notices_delivered` 仍仅代表文件交付，不代表本机通知成功。
- **失败与幂等**：通知超时/失败不丢发件，默认总览显示失败条数，下次检测重试；成功后按内部编号去重。开启新渠道不补发已完成文件交付的历史提醒。系统通知没有事务确认，进程在通知后、写确认前崩溃时仍可能重复一次，不能保证外部通知严格 exactly-once。
- **渠道接口**：类型统一在 `core/types.ts`；中枢 `detect` 的组件参数可注入 `channels: Channel[]`，不需要改来源和判断器。飞书实现同样的收件契约，通过可选 `Channel.levels` 声明两级提醒；未声明的本机/旧测试渠道仍仅交付紧急级。外部消息通道不暴露内部编号。
