# personal agent：推送判断、渠道与常驻（闭环 1）

四个只读来源/推送 → 统一记录 → 规则优先、可选模型判断 → 文件发件、本机通知与飞书私聊；支持本机/飞书反馈、macOS launchd 常驻、周五小结与经验集。**不替用户回复或启停 AI，不自动执行经验对策。** 开发与自动验证只用构造/脱敏样本、假飞书/模型/通知和临时目录；不读取真实个人目录，不安装真实钩子或 launchd，不连接真实账号。

## 段 2：飞书（先用假渠道）

在下文已有完整配置中加入以下字段即可；旧配置没有这些字段，仍维持段 1 行为，不会悄悄联网或常驻：

```json
{
  "feishu": { "mode": "fake", "receiverId": "ou_test", "timeoutMs": 5000 },
  "service": { "intervalMs": 60000, "restartWindowMs": 300000, "restartThreshold": 3 }
}
```

`receiverId` 是唯一接收用户的 `open_id`，同时校验入站操作者；只接受这个用户的私聊，忽略其他人和群聊。`fake` 永不加载 SDK 连接、不读凭证，只往配置的数据目录写 `feishu-sent.jsonl`。记录含 `messageId`、内部提醒关联和完整卡片 `content`，外观为 JSON 2.0 卡片：标题（谁 + 出了什么事），分开的「这件事」「要你做」「时间 / 回去看」三块；「要你做」逐件一句，标「回复会话 / 你去做 / 要你定·红线 / 不用管」，有建议就附上（最后输出中的建议优先）。时间与直达命令占两行，段名加粗、块间留白。原文、判断依据、完整长文、loop 欠项与经验审阅放在默认收起的证据里。下面默认收起的「给 personal agent 的反馈」区放正确/误报/看不懂按钮；小结、复盘及服务告警只有看不懂（经验审阅按钮在证据内）。没有输入框，也不会把话送进会话。内部提醒/经验编号仅在隐藏按钮 value 和 JSON 元数据中，不出现在人看的正文/确认中。

- 「现在就要你」→ 文件 + 本机（若开启）+ 飞书；「有空看」→ 文件 + 飞书，本机不弹。同证据和已成功渠道不重发，失败渠道在总览标出并下轮重试。新启用渠道不补已交付的历史提醒。
- 飞书引用某张卡片回复「正确 / 误报 / 看不懂 [说明]」才关联那张；未知引用或未引用不会退回最近一条。直接发「漏了 + 一句话」明确不关联提醒。误报的回话写明「这个会话之后不会再因为等你回复或授权叫你」等效果；正确回话说明提醒有用、不算问题；漏了/看不懂回话说明已进本周问题汇总。不转给任何 AI 或别人。
- 假渠道入站：向 `$DATA/feishu-inbox.jsonl` **追加**官方事件 envelope（每行一个完整 JSON 并带换行）。`detect` 一轮或 `feishu-poll` 处理；常驻独立轮询收件，不等整批模型。测试可注入 `FeishuTransport`，不需账号。
- 两类事件是 `im.message.receive_v1`、`card.action.trigger`。长连接回调只持久化最小入站事实，入站读写短锁争用时最多等 2 秒（不等检测锁），整体仍在 2.5 秒内确认；逾时拒绝让平台重投，反馈、模型、发确认均在后续队列执行。反馈和确认按事件键幂等，重启后重放未完成队列。事件必须有稳定 `header.event_id`；也兼容 SDK 展平字段，按钮缺 event_id 时用 token/动作/时间的哈希，不保存 token。

构造的私聊事件示例（`DATA` 是显式数据目录，不是仓库）：

```json
{"schema":"2.0","header":{"event_id":"demo-miss-1","event_type":"im.message.receive_v1"},"event":{"sender":{"sender_type":"user","sender_id":{"open_id":"ou_test"}},"message":{"message_id":"om_demo_reply","message_type":"text","chat_type":"p2p","content":"{\"text\":\"漏了 loop 暂停没叫我\"}"}}}
```

按钮和文字事件的 `create_time` 接受秒、毫秒、微秒；缺失、早于 2000 年或超过收到时间一天的异常值改用收到时间，在最小入站/处理记录的 `timeNote` 留说明。单条处理失败追加 `status=failed`、受控 `category` 和固定人话 `response`；区分 `notice_not_found`（提醒找不到）、`invalid_feedback`（反馈格式/关联不对）、`lock_busy / lock_timeout`（独立记录锁异常占用/等待超时）、`data_corrupt`（记录不完整/损坏）、`unsafe_file`（链接或特殊文件）、`storage_full / storage_permission / storage_readonly / storage_io`（存储空间/权限/只读/读写错误）、`unexpected`（未知问题）；既有按钮/经验不匹配类别保留。不给用户或日志写凭证、模型原文、上游原始错误。继续处理后面的收件，不拖垮检测。处理结果与确认投递分别追加到 `feishu-receipts.jsonl`：确认发送失败记 `replyCategory=reply_delivery`，不覆盖处理失败的类别，只重试回话、不重复记反馈。**所有已有处理记录，包括失败的、仅含事件 id 的和人工核销的旧点击，都不重新处理或自动补记。**

三路反馈共用独立 `.feedback.lock`，不等检测的 `.detect.lock`；写入和去重完成、同步落盘后才回「已记下」。检测/统计也经反馈短锁读取，不会读到写了一半的行。发件核对用 `.outbox.lock` 短锁，只覆盖完整 JSONL 的读写，不涵盖模型、通知或 API。飞书确认与卡片 API 使用不同发送锁，共享消息映射另以 `.feishu-sent.lock` 短锁保护，慢卡片发送不把反馈确认排在后面。

按钮回调 envelope 的 `event` 使用：`operator.open_id`、`context.open_message_id`（发出记录的 messageId）、`action.value`（卡片按钮原样复制，例如 `{action:"feedback", verdict:"误报", noticeId:内部关联}`）。引用回复在 `message` 中加 `parent_id: 原卡片的messageId`。这两个关联键仅测试/机器使用。处理命令：

```bash
cd '/Users/Admin/Desktop/personal agent-dev分支'
node code/src/cli/main.ts feishu-poll --config "$CONFIG"
node code/src/cli/main.ts detect --config "$CONFIG" --now '2026-10-20T10:03:00Z'
```

**[人工，开发未执行] 真实飞书**：用户建立企业自建应用并启用机器人、发布到本人，授予发消息/接收私聊及卡片交互所需权限，订阅上述两个事件，接收方式选长连接。将 `mode` 改为 `real`，填写本人的 `receiverId`；凭证只能由进程环境 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 或显式 `feishu.envFile` 指向的已忽略 `.env` 提供（环境变量优先）。文档不提供任何凭证值；配置 JSON 不接受 App ID/Secret 字段。`.env` 须在数据目录之外，不入提交，且不使用来源工具的密钥文件。假渠道不读它。登录常驻不能依赖交互 shell 的环境，宜显式指定这份 `.env`。SDK 原始日志不输出；长连接失败只记录受控类别与固定短说明，不输出请求或凭证。未以真实账号验证卡片呈现、权限、30 天按钮有效期与网络重连体验。

## 段 2：前台常驻与 launchd

```bash
cd '/Users/Admin/Desktop/personal agent-dev分支'
node code/src/cli/main.ts daemon --config "$CONFIG"
# 前台运行；另向已配置 inbox 追加编的 waiting_permission 事件。
# 预期：按分钟检测；在等你（含授权等待）先等五分钟，仍未处理才发卡。
# 最近十分钟任一被盯会话有真人输入时，只弹本机、不推飞书；Ctrl-C 正常退出。
```

`service.intervalMs` 默认 60000（检测不重叠，较长一轮完成后再续）；收件独立轮询，至多每秒一次。常驻不隐式加载个人配置。`service.log.jsonl` 写固定类别的启动/检测/收件/停止日志，不记录原始事件、上游错误或凭证。每轮 `scan_completed` 或 `scan_failed` 都带 `durationMs`（整轮检测耗时）和 `storeLockHeldMs`（该轮规则、模型结果落盘、复盘等阶段实际持有 `.detect.lock` 的累计时长，含锁内初始化/释放、不含等待获取锁和锁外模型等待），单位毫秒、单调时钟计量；失败轮次也记录已发生的持锁时间。本批只计时，检测原有加锁范围不变。飞书连接失败为 `feishu_connection_failed`，只留 `credentials`（凭证）、`permission`（权限）、`network`（网络）、`configuration`（配置）或 `unknown`（无法细分）和固定短说明；SDK 拒绝、错误回调及仅记日志的启动失败均覆盖。总览另列「飞书长连接」：握手成功才显示已连接，连接中/重连中/失败/停止均显示未连接；假渠道明确不连接真实飞书，文件或消息投递成功不等于长连接已建立。JSON 总览与可重建状态提供 `feishuConnection`。展示状态写入抢不到数据锁时，每秒独立重试最新状态；收件轮询及检测释放锁后的收尾也会独立唤醒待写状态，避免固定重试与连续检测同相争锁。只唤醒、不等待状态写入或数据锁，不阻塞收件，也不保留会反复抛错的失败 Promise。默认 5 分钟内 3 次未正常退出后重启，单独发一条飞书告警，日志路径仅放在证据里；成功/失败投递仍有独立事实与重试。正常 Ctrl-C/SIGTERM 记停止，不计崩溃；系统睡眠唤醒后继续检测。

安装目标目录必填，默认只生成 plist，不执行 launchctl。以下**只能使用临时目录和假配置**：

```bash
TARGET=$(mktemp -d "${TMPDIR:-/tmp}/personal-agent-launchd.XXXXXX")
node code/src/cli/main.ts service-install --config "$CONFIG" --target "$TARGET"
# 检查 $TARGET/local.personal-agent.plist：RunAtLoad、失败退出 KeepAlive、固定 Node/程序/配置 argv、日志路径。
node code/src/cli/main.ts service-uninstall --config "$CONFIG" --target "$TARGET"
# TARGET 恢复原有空目录；原本不存在的目标及安装创建的空父目录则移除。
```

不覆盖已有同名 plist；卸载只删除本程序安装且指纹仍吻合的文件，其他文件/权限不动。安装后用户改过 plist 则保留现场拒绝删除。已激活时先用 `launchctl print` 核实当前服务的 plist 归属，不能确认或同名服务已被其他安装接管则不停止服务。bootstrap 失败/超时时保留未确认的 plist，不按同名 label 误停原有服务；这类失败现场须先人工核对，不能当作安装成功。登记保留在数据目录 `launchd-installations.jsonl`，不是目标目录。目标须与数据/来源/推送目录分离。激活/停用可用 `--launchctl <测试替身路径>` 验证，自动测试不调用真实 launchctl。

**[人工，开发未执行] 登录启用/重启验收**：在实际运行代码目录，以真实配置执行 `service-install --target <用户明确选择的LaunchAgents绝对目录> --config <绝对配置> --activate`，才会 `launchctl bootstrap gui/<uid>`；卸载会按登记 `bootout`。plist 登录运行，异常退出自动拉起，重启节流 10 秒。plist 仅写入可控 PATH（当前 Node 可执行文件所在目录优先，再加固定系统目录），不复制交互 shell 的环境或凭证；子进程入口也补齐当前 Node 目录，绝对路径的 Pi 即使用 `#!/usr/bin/env node` 也不依赖登录 PATH。常驻的 Pi 等组件应使用绝对可执行路径。移动代码/Node/配置位置前先卸载再安装。真实登录、重启电脑、通知权限及飞书账号均未在开发中操作。

## 段 2：小结、统计与经验集

配置飞书即默认开启本节功能；也可不接飞书而显式设 `learning: true`（只写文件）。`learning: false` 停用新的收集/小结。周五本机当地 18:00 发一份「有空看」小结；本次数据运行期内错过时间点会在恢复时补一次，不补初次接入前的周报，重复检测/重建不重发。

```bash
node code/src/cli/main.ts stats --config "$CONFIG"                 # 任意时刻最近七天
node code/src/cli/main.ts stats --config "$CONFIG" --now '2026-10-23T18:00:00Z' --json
TZ=UTC node code/src/cli/main.ts detect --config "$CONFIG" --now '2026-10-23T18:00:00Z'  # 构造周五18点
node code/src/cli/main.ts experience list --config "$CONFIG" --json
node code/src/cli/main.ts experience confirm "$EXPERIENCE_ID" --config "$CONFIG" --layer '盯防自身' --countermeasure '先核对证据再调整阈值'
node code/src/cli/main.ts experience revise "$EXPERIENCE_ID" --config "$CONFIG" --reason '补充归因' --countermeasure '修改后的建议'
node code/src/cli/main.ts experience obsolete "$EXPERIENCE_ID" --config "$CONFIG" --note '由新经验替代'
node code/src/cli/main.ts experience revoke "$EXPERIENCE_ID" --config "$CONFIG" --note '撤销依据必填'
node code/src/cli/main.ts experience export --config "$CONFIG"      # Markdown 到 stdout，可保存到数据目录
```

统计从 outbox/feedback **每次现算，不保存统计表**。按工具 × 类型列发出量、正确/误报、准确率、漏报、回应率、日均与逐日次数；同条提醒以统计时刻前最后一次正确/误报为准，看不懂单独计数、不覆盖准确率分类，不重复膨胀分母，无回应不算正确。准确率=正确÷(正确+误报)，回应率=有反馈的提醒数÷发出数，漏报逐条计；不足20条分类反馈只列数字、不评价好坏。无关联漏报仅从明确提及的工具/问题类型归格，不能辨明的列「未指定」，不强行编造分类。周报、复现和服务告警不混入盯防准确率。

问题只来自误报、漏了、看不懂，以及 loop 到上限或返修 ≥2 次；正确只算提醒有用，不收问题、不调归因模型、不触发复盘。旧版误收的正确问题/经验仍保留原日志，但不进入问题、经验导出和复盘投影。同条提醒的重复误报只算一次问题；每次独立的看不懂反馈都留存，平台重投仍按事件去重；loop 同一运行只收集一次。反馈当场在原 `feedback.jsonl` 保存问题事实（标题、原第一屏、回看命令、卡片时间、原话、反馈时间），下一轮检测在 `learning.jsonl` 追加归因和经验；旧反馈缺快照时从原发件读取，不改旧行。周报按「反馈类型 × 工具 × 提醒原因」归并计数，看不懂单列一栏。模型用现有 `judge` 配置、无工具 Pi 参数，共用每日额度与同一轮模型总预算；四层归因加「归因未定」，模型草案状态为「待确认」。没有模型、失败或无额度时明确记归因未定，不冒充模型结论。规则先比较类型+归因层+工具或项目，不确定再由模型只答是/否；未定且事实不同、无模型时不武断合并。

第一次开启复盘，将开启时刻追加到 `learning-baseline.jsonl`，历史问题只收集计数、不推复盘；只有之后发生的新问题可以提醒。这个时刻不随重启/重建移动，周报也不复盘接入前的旧事；若历史已有多次同类问题，开启后第一次再出现仍单发一张。复盘第一屏只用一句话说明这是什么问题，不嵌旧卡片正文；轮数、归因、对策、同类依据与确认按钮收在证据中；能定位时回到该 loop 总结或原提醒的具体会话，不给经验数据文件。

同类第2次或已有**已确认**对策又出现，即时单独发「有空看」确认；首次问题攒到周五。周报按「有对策又出现 > 反复出现 > 新的」排序，附次数、上次日期和上次已定对策；每项带同意/改一下。`同意`→已确认，`改一下`→待确认并提示用本机命令修改。按钮隐藏值与发件快照绑定经验审阅版本，写锁内再核验当前版本；归因/对策/备注或状态的显式修改都会换新版本，旧卡片不能确认或退回新版本，改走再改回也不复用旧版本。过期或旧格式无版本卡片只提示查看最新复盘/使用本机命令，不写经验；已成功事件重投仍幂等。四状态为待确认/已确认/已过时/已撤销，过时/撤销不删、不参与比对，旧卡片不能复活失效记忆；撤销必须留原因。只管理本产品经验，不自动执行对策、不写任何项目规则、不接 LLM Wiki。

“上次已定对策”按问题发生时间，从追加的经验版本历史中取当时有效且已确认的版本；问题记录后才确认/修订的当前对策不能回填历史。时间戳完全相同、没有跨文件先后证据时不宣称对策事前已定。已收集问题事实不因后来的确认/修订改写。

新增数据均在显式 `dataDir`（强制在仓库外）：`feishu-inbox.jsonl`（最小入站）、`feishu-receipts.jsonl`（处理确认）、`feishu-sent.jsonl`（消息关联；假模式含卡片/确认、真实模式仅元数据）、`learning.jsonl`、`learning-baseline.jsonl`（首次复盘边界）、`service-runs.jsonl`、`service.log.jsonl`、`launchd-installations.jsonl`；真实 launchd 另有 stdout/stderr 日志。不要删发件映射来解决关联问题。

### 减负与封存 · 甲段：提醒、逐件动作与回话引用

- **等候**：AI 回合停下后等 5 分钟，期间同一成员有新真人输入或授权等待被推进解除，不发等待卡，也不作等待模型调用；单独的收尾问句不会绕到跑偏判断里额外花调用。独立的执行跑偏、loop 暂停、看不见了仍立即处理。步骤以可选 `kind` 区分助手文本、工具、工具结果；工具和说明同时间也不套等待窗口，只有实际结束回合的最终回复才受窗口约束。
- **在场**：只用被盯会话的真人输入时间（含「继续」和纯媒体），不读系统空闲时间、键盘或屏幕。Codex 子代理自动接任务不算真人，只有消息级明确 `origin.kind=human` 且未被系统/合成标记拒绝的输入才计在场；旧缓存中无该依据的子任务也不算。发新卡时，最近 10 分钟内任一被盯会话有真人输入即在场：「现在就要你」只弹本机，不推飞书；不在场则两边照旧。「有空看」仍只发飞书。`outbox.jsonl` 的可选 `delivery` 留下在场/不在场、所选出口、决定时间和最后真人输入时间；重试沿用原决定，不给在场时的旧卡事后补推飞书。
- **逐件快照**：原八项快照不变，新快照追加 `actionItems: [{text, label, suggestion?}]`，至少一件；模型在原判断/起草调用里顺带给出，不另增调用。删除、合入、推到远端、对外发消息、花钱、授权由规则在清理和截短前硬判红线，不能被模型降级。本机只写第一件和总件数。
- **影子对照底子**：会话的 `humanRequestRefs` 只记时间、成员和已有原文索引（纯媒体 index=-1），不复制真人正文；检测到发卡后该成员的第一句真人输入时，追加 `notice_reply_observed {noticeId, reply}`，每卡一次。事件投影的 `notices[].snapshot.nextHumanReply` 和 `noticeReplies` 可查这份引用；`reply.index` 指该成员的 `[intent.initial, ...intent.additions]`。原发件行不改，本段不打分、不代答。
- **升级/回退**：只加可选字段和事件，不做原地迁移，旧卡/旧快照照读，已交代事实不重发、不重新起草。升级前由获准操作者备份完整数据目录（开发未操作真机）。旧代码不认识新事件；回退必须先停所有新版写入、保留新版完整现场，再让回退代码指向升级前整目录备份的独立副本，不删除新事件凑兼容，也不混跑两个版本。

```json
    "executable": "/绝对路径/到/pi或测试替身",
    "model": "opencode-go/deepseek-v4.1-flash",
    "dailyLimit": 240,
    "timeoutMs": 30000,
    "cycleTimeoutMs": 60000

  "localChannel": {
    "executable": "/绝对路径/到/通知测试替身",
```

把这些字段加入下节的完整配置。省略或设为 `null` 即停用；可执行文件是一整个路径/文件名，不是 shell 命令。每日上限可为 0（纯规则），缺省 240，按 UTC 日期统计，失败也计调用；时间参数缺省如例。真实本机通知命令为 `/usr/bin/osascript`，**本段开发/自动验收不填这个真实命令**。这两个组件不增加额外运行依赖。

### 判断器

- 状态判断接口 `Judge.judge(JudgmentRequest, options?: {signal?: AbortSignal}): Promise<JudgmentResult>`，独立起草接口为可选的 `Judge.writeSnapshot(TaskSnapshotInput, options?): Promise<TaskSnapshotDraft>`，见 `src/core/types.ts`；第一版 `src/core/model.ts` 调配置中的 Pi。固定参数含 `-p --no-tools --no-session --no-extensions --no-context-files --mode json`，另禁用 skills、prompt templates、项目配置和自动联网更新；不会给模型工具。`--offline` 只关后台更新，不禁止显式的模型请求。
- 跑偏**判断**仍读取有界 JSON：意图原文（≤1000 码点）、较新的本人追加要求（共约 2000 码点）、上次做到哪了（≤500 码点）、新步骤（最多 8 步、每步≤220 码点），提取方式与引文核验不变。**起草**每份材料只有四项：总目标、最后输出之前的当前这件、最后输出、规则事实状态。等待用 `snapshotInput`，不带步骤/过程摘要；跑偏在同一次判断调用中，先核验 `stepQuote`，再仅使用 `snapshotInputsByStep` 中与该步同索引的一份四项材料（最多8份候选，非起草过程步骤），不默认取末步。模型文案和规则兜底均绑定已核验步骤及当时要求，不增加调用。独立起草也不带步骤。最后输出保留已有的有界首尾，loop 只给项目/批次、结论和欠项数，不把验收条文塞进去。材料里的指令只当证据。
- 正常检测只问「是 / 否」，并输出依据。跑偏答是必须提供 `intentQuote` 与 `stepQuote`，两者都须匹配实际送入的意图和新步骤；缺失或捏造即按否。不覆盖来源失明、不可用子成员或已搁置状态；原有授权等待/loop 规则优先。每个根会话跑偏检查至少间隔 10 分钟、有新步骤才调用；首次接入 1 小时窗口之前的历史完成记录不耗模型额度，超过 24 小时无动静也不新调；成功判断后的空跑、总览、重建都不调用模型；失败的判断下一轮可重试。先前模型判等待/跑偏的会话超过 24 小时无动静，同样只进「已搁置」。
- 助手答完、没有未返回工具、没有明确会话结束且等候已满五分钟时，问是否在等用户回复；期间已接话则不问。是 →「在等我」，否 →保留规则的「已完成」。Codex 子成员单独判断等待，不会把父/兄弟活动当成它回复了用户。
- 等待/跑偏判断同一次调用顺带输出 `situation`（这件事：整体任务与进展，两句内约100字）、`action`（要你做：一句问题或动作）、`actionType`（回答问题/做个决定/去看一眼/不用管），不增加模型调用。任一文案字段缺失时整份规则兜底，用总目标和当前这件交代事情、从最后输出取问题；跳过「合入。」等操作词、媒体占位、`ide_opened_file`/`ide_selection`/`system-reminder`/`file` 等注入块。已配置的判断器失败、超时或超限时，助手最后明确的问题可作规则等待兜底；下一轮模型重试仍保留，但不能重发同一事实。完全未启用 `judge` 时仍保持既有纯规则状态判断。标题保留「可能」，本机与飞书同样先交代这件事，再写要你做；内部路径、行号、判断原文只放证据，时间用本机当地口语写法。表格/代码块不塞进通知正文，重复句和叠标点会清理；长回复在钩子（含 Pi 的 message_end 缓存）与推送中保留最多 4000 码点的首尾，模型上下文继续保留最多 1200 码点的首尾；再次限长不会退回只取开头，避免表格挤掉末尾问题。通知从同一条已对账推送中提取问题。
- 调用失败、超限均按规则兜底，总览标「仅规则判断」。失败下一轮检测重试（跑偏失败也不启动 10 分钟成功检查间隔），仍计入 UTC 每日上限；成功答案继续缓存去重。`model_checked.check.failure` 可选字段记录超时、退出码、命令无法启动、输出超限、答案解析/字段不合约定等受控类别及短说明，不存 stdout/stderr、模型原文或凭证，旧记录仍可重放。调用前在短锁内按最新日志预留额度，重启不忘已调用次数。
- **交付顺序与时限**：已满五分钟仍未处理的授权等待等不需要独立起草的规则提醒先写发件和投递，不等无关会话的模型。停滞、loop、读取故障的新卡片先在数据锁外起草（失败即兜底），再交付；与后续等待/跑偏判断、复盘共用同一轮预算和每日上限，不另外开一份计数。模型候选按最近证据时间倒序，同一时刻先查等待，再查跑偏；新停下的会话不会被旧完成会话挤到后面。模型等待期间不持 `.detect.lock`，可接收反馈或运行新的规则检测；模型返回后基于最新事件再次判断/交付，不用迟到答案覆盖新会话事实。`timeoutMs` 是单次上限，`cycleTimeoutMs` 是单轮模型阶段总时限（默认 60 秒），到时取消 Pi 子进程；即使替身忽略取消，也不再等待它。总时限未轮到的检查标「本轮模型时限用完，仅规则判断」，不消耗额度、不吞新步骤，下轮可续查；已发提醒和失败渠道重试仍按编号去重，每个渠道每条提醒一轮至多尝试一次。
- Pi JSON 模式替身须接收同样的 argv 和 stdin（prompt），输出 JSONL，其中最终答案形如：`{"type":"message_end","message":{"role":"assistant","stopReason":"stop","content":[{"type":"text","text":"{\"answer\":\"否\",\"reason\":\"依据\"}"}]}}`。最终文本的 JSON 为 `{answer, reason, intentQuote?, stepQuote?, situation?, action?, actionType?}`；独立起草只返回 `{situation, action, actionType}`。调度层可注入 `Judge` 替身，替身省略 `writeSnapshot` 时独立起草仅规则兜底，绝不回落真实模型。参考 `test/judgment-channel.test.ts` 中的完整可执行替身，不能把测试替身指向真实模型。

### 本机渠道和反馈

文件渠道始终保留；本机渠道只对「现在就要你」弹通知，「有空看」仅写发件记录。通知超时/失败不丢文件发件，总览显示未成功条数，下轮重试；成功后去重。外部系统通知与本地确认没有原子事务，进程在通知成功后、确认前崩溃仍可能重复一次。新开启本机渠道不补发已交付历史提醒。

```bash
node code/src/cli/main.ts feedback 误报 '这条不用我处理' --config "$CONFIG"
node code/src/cli/main.ts feedback 正确 --config "$CONFIG"
node code/src/cli/main.ts feedback 看不懂 '段落太挤' --config "$CONFIG"  # 默认最近一张卡片（含周报/复盘）
node code/src/cli/main.ts feedback 漏了 '另一个会话刚才在等我' --unlinked --config "$CONFIG"
```

检测占用数据锁时，反馈不等待检测，使用独立反馈短锁追加，成功输出「已记下」和实际效果。误报只屏蔽这个实际会话的同一种提醒原因（等待、跑偏、停滞等），不会影响其他会话或该会话的其他原因；没有定位到具体会话的故障提醒不会屏蔽整个工具。查询立即标「因你的误报没提醒」，检测投递前也重新核对反馈；已经在外部发送中的请求不能撤回。不会执行或自动调整跨会话规则。反馈短锁的读/去重/写入不包含检测、模型或通知；若这把独立锁本身异常占用，最多等 30 秒后明确说尚未记下、请检查本机服务，不擅自清锁、不重复整个写入操作。可加 `--now <带时区ISO>` 做构造验收。不带 `--id` 默认最近一条发件，`--id <内部提醒编号>` 是机器关联入口；明确不关联的「漏了」用 `--unlinked`，二者不能同用。没有任何提醒时也能记「漏了」；「正确 / 误报 / 看不懂」必须指向真实存在的发件；前两种跳过非盯防消息，看不懂可针对任何卡片。不往给人看的通知或确认文字里写内部编号，亦不执行反馈中的文字。反馈只追加，坏 JSONL/半行会保留现场报错。

**段 2 衔接接口**：`Channel { name; send(notice: Notice): Promise<void>; receive(reply: ChannelReply): Promise<string> }`。`Notice.id`、`ChannelReply.noticeId` 仅内部关联；`content` 是回复文字、`at` 是日期时间，`noticeId=undefined` 默认最近一条、`null` 表示不关联的漏报。`detect(config, now, {judge?, channels?})` 可注入实现；生产本机渠道由配置选择。收到反馈后可复用 `core/feedback.ts` 统一落盘，调用应在检测锁外。渠道通过可选 `Channel.levels` 声明投递级别（省略仍只收紧急级），`ChannelReply.replyId` 做平台事件去重；本批将接收结果放宽为确认字符串，包含实际效果，不再只返回固定的「已记下」。

## 显式配置

CLI 的来源、推送、数据目录和回看可执行文件全部来自 `--config`；不自动找配置文件、不读取工具全局配置、不使用默认个人目录。目录必须是绝对路径，不展开 `~`。四个来源和 `inboxDir` 每一项都必须提供；`null` 表示明确关闭，**非空但不存在/读不进的目录会报「看不见了」，不会当空目录**。

示例仅为构造路径（不要原样运行；下节有可运行的样本配置生成器）：

```json
{
  "sources": {
    "cc": "/tmp/my-samples/claude-projects",
    "codex": null,
    "pi": null,
    "loop": null
  },
  "inboxDir": "/tmp/my-samples/inbox",
  "dataDir": "/tmp/personal-agent-run/data",
  "ignoreProjectPrefixes": ["/private/tmp", "/var/folders"],
  "commands": {
    "cc": "claude",
    "codex": "/sample-tools/codex",
    "pi": "pi"
  }
}
```

- `commands` 的三项也必须显式提供，是可执行文件名或完整路径，**不是带参数的 shell 命令串**。含空格的路径自动引用；这里只生成文字，不检查工具安装、不执行命令。
- `ignoreProjectPrefixes` 是可选的绝对目录路径数组，省略等同 `[]`，不默认过滤。忽略目录本身及其子目录，例如 `/private/tmp` 匹配 `/private/tmp/test`，不匹配 `/private/tmp-other`；不展开 `~`，不读取这些项目目录来做匹配。忽略项目的会话不入总览、不发提醒；Codex 忽略父会话时连带忽略子代理。过滤也适用于已有事件的查询/重建及未交付提醒，历史事实不删。坏文件若仍可提取核心项目身份，也能按配置忽略；身份线索用于过滤和不可用关联，绝不拿来伪造正常状态或给新推送对账。
- 来源文件只读。来源中的符号链接不跟随；数据文件不允许符号链接或硬链接。数据与任一来源/推送目录不能互为祖先或相同，包含可解析的符号链接别名。
- 推送仅按方案格式读取 `cc.jsonl`、`codex.jsonl`、`pi.jsonl`：`tool/event/session_id/cwd/transcript_path/at/detail`；事件为 `waiting_permission`、`turn_end`、`session_end`。`at` 是带时区 ISO 时间。只记录读取行数/指纹并去重，不改、不删 inbox；重复内容不会重复计入推送事实。当前实现为校验只读重扫，游标持久化但不依赖它跳过完整性检查。
- `transcript_path` 只用于对账和定位，不能引导程序打开配置外文件；必须匹配实际成员的工具、会话 ID、原件路径，推送 `cwd` 须在**这份原件**的结构化 cwd 字段中出现过，不能借父/兄弟成员或同号另一份原件的目录。会话项目仍是起始目录，不因 cd 拆行。CC 收集非侧链记录的顶层 cwd，Codex 收集顶层 cwd 及 session_meta/turn_context 的 payload.cwd，Pi 收集会话头及节点的顶层 cwd；不从命令/正文/工具输出推测目录。只用本轮成功读取的原件验证新推送；读取/目录/归并失败只留推送事实、不借缓存对账、不放大局部故障。配置内文件尚未落盘/为空，或同号同路径的 cwd 尚未写到原件时，最多宽限两轮；轮数追加为 `push_deferred`，查询/重建不消耗、重启不重置。第三轮仍对不上报「看不见了」；会话号/文件归属冲突、配置外路径立即报，不享受宽限。
- 空会话仅放过配置来源内 `.jsonl` 的 `session_end`，保留两轮宽限：① 文件仍不存在、且从未在会话文件中见过该工具的会话号；② 文件存在，但读取组件完整校验成功、没有核心消息而跳过，且该身份/路径没有已读取真实会话（含子成员）的历史。第二种允许元数据里出现过会话号，也包括零字节文件；不能把所有“跳过”文件一概当空会话。追加一条 `push_empty`，原因区分“文件仍不存在”和“文件存在但没有核心消息”，不生成会话或提醒；重复检测/重建不重复记空会话。
- 有对话但缺身份/项目、身份或路径冲突、坏 JSON/读取失败、以及读过真实会话后只剩元数据，都不能按第二种放过；原有故障规则不变。只见过身份但文件后来消失，仍受 `session_seen` 的缺失保护；`waiting_permission` / `turn_end` 不适用空会话放过。已被元数据空会话卡住的来源，在升级后的下一轮检测按新规则恢复，不重发旧失明提醒；不迁移或改写旧事件、发件和反馈。
- CC/Codex/Pi 的 `autoreview-` 前缀会话，以及项目目录位于 `.pi-autoreview/` 内（包括 `pipelines/某批/e2e/r1`、普通 UUID 会话号）的会话及推送，一律不入总览、不做模型判断、不发提醒；可识别身份的损坏文件同样忽略，不能读取身份时仅使用工具固定内部会话文件名兜底。历史投影/未交付提醒也过滤，但事件与发件事实不删。loop 来源的总结不受前缀过滤影响，仍正常交代。
- 收到的语法合法推送先以 `push_observed` 留存；只有明确通过对账、另有 `push_validated` 事件的推送才能参与判断。无效推送不会因来源恢复或停用 inbox 而重新生效；原始事实去重包含项目和会话路径，纠正字段后的新推送可以独立对账。旧日志中只有 `push_observed` 的历史推送也保持非判断态；升级后先备份显式数据目录，再运行一轮检测，才能根据当前来源为有效推送追加对账结果，无需改写/删除旧事件。

## 检测、总览与发件

假设 `CONFIG` 已指向配置文件：

```bash
node code/src/cli/main.ts detect --config "$CONFIG"
node code/src/cli/main.ts detect --config "$CONFIG" --now '2026-10-20T10:51:00Z'
node code/src/cli/main.ts overview --config "$CONFIG"
```

`--now` 必须带时区；省略时检测用系统当前时间。总览默认采用最近一次检测时间，保证回看样本结果不会随现实时间漂移；可以给总览 `--now` 做纯查询推算，但查询不发提醒。`--json` 可加在三个命令后，输出机器可读记录（含内部关联键）；面向人的默认总览不显示这些编号。

原有核心持久文件如下（段 2 新日志见上节）：

| 文件 | 内容 |
|---|---|
| `events.jsonl` | 唯一事实源，只追加：模型用量预留/判断、渠道投递队列/结果、统一记录、原始推送/对账、来源健康（会话清单、候选/非会话跳过计数、坏文件数量/至多 3 例）、游标、检测时间、提醒/历史抑制决策和交付确认。只保存必要字段，不复制整份原件或工具返回正文 |
| `outbox.jsonl` | 文件渠道已投递提醒，只追加，包含 `level`、结构化 `content`、给人看的 `text`；新盯防卡片另带 `snapshot`（原八项加 `actionItems`），`delivery` 留下在场判断和所选出口；回话引用在事件旁追加，旧卡片缺字段照读 |
| `feedback.jsonl` | 只追加「正确 / 误报 / 漏了 / 看不懂」反馈：日期、内部提醒关联（或 null）、渠道、说明、可选原话与原卡片快照；误报现算同会话同原因的抑制 |
| `state.json` | 从事件推算的当前状态，可删、可重建，不依赖它去重；单行完整 JSON |

看给人读的发件内容（把 `DATA` 设为配置中的 `dataDir`）：

```bash
const rows = (await readFile(process.argv[1], "utf8")).split("\n").filter(Boolean);
for (const row of rows) { const n = JSON.parse(row); console.log(`【${n.level}】\n${n.text}\n`); }
if (!rows.length) console.log("暂无提醒");
' "$DATA/outbox.jsonl"
```

所有数据文件的非空行均为完整 JSON；`--json` 输出整体可直接解析。意图每段最多保留 1000 个 Unicode 码点（超出追加省略号），步骤为有限摘要，截断不切开表情等多字节字符；短原文保留换行。无新动静时只追加很小的检测时间事件，不重复写会话/健康快照。

提醒标题写清谁出了什么事，第一屏固定按「谁（工具、项目名、意图；loop 为批次和轮数）→ 出了什么事 → 要不要你管 → 回去看」交代；意图跳过结构化图片/附件和文字中的媒体占位，取第一条有文字的本人消息，全无文字写「意图不明」。助手的动作引子以冒号结尾并跟列表时，列表压成一行带上，可截断但不会只剩引子。每条复盘标题只展示一次。时间按本机当地日历写「今晚 23:11 / 昨天 18:00」，时间与后面的字之间留空格。意图原文、本人追加要求、最近几步、内部文件/行号和依据放后面的证据；内部 `id`/去重键只在 JSON 元数据里。回看：Claude Code `claude --resume <id>`、Codex `<配置路径> resume <id>`、Pi `pi --session <id>`；loop 用 `open <总结文件>`。这些命令只作为交代，不会被程序执行。

规则要点：

- 等授权且之后没有新动静 →「在等我」；loop 暂停也在等我。「现在就要你」。Codex 子会话仍归父记录一行，但按各成员自己的活动时间判断等待，父/兄弟继续活动不能掩盖它；提醒用父任务意图、实际等待成员的动作和回看命令。子会话 `turn_end/session_end` 只结束该成员，不能结束仍在工作的父会话。子成员本轮读取/归并失败时，保留其与可读父任务的关联并标 `unavailable`；首次检测即失败，也会用仍可可靠提取的 `session_meta` 父子身份建立不可用关联，而不是把失败成员缺席当作全部完成。身份只用于关联，不取损坏正文的调用/完成前缀，不给新推送对账；无历史活动事实时成员 `lastActivityAt` 为 `null`，不捏造时间。有历史则保留最后事实。没有全部完成证据时保持「进行中」并在判断依据写明本轮读不了，先前已对账的授权等待也不能凭失败期间的新推送解除。其他根会话照常判断；恢复读取后用新事实解除标记，不因失联误报完成或停滞。
- 纯规则配置下，本轮结束/助手答完且无未返回工具 →「已完成」。启用判断器后按上文区分是否在等你回复，并判断跑偏；明确会话结束/loop 完成仍优先使用规则。普通完成和进行中不发提醒。Pi `stopReason=error/aborted` 消息中的工具提案不登记为未返回，正常重试答完可完成；Codex `task_complete` 后的已完成后台 `item_completed` 不重开任务，新输入/新调用/`task_started` 仍重开。
- 可确认仍未结束，最后动静**超过 30 分钟、未超过 24 小时** →「停滞」；「有空看」，同一会话实际停滞提醒终身一次。**超过 24 小时**没有动静且未结束 →「已搁置」，只进总览、不提醒（包括长期等待/loop 暂停）；已完成的旧会话不降级。读取失败造成的状态未知不冒充停滞/已搁置；新活动后按新事实判断。
- 只取核心信号，忽略未知记录类型、内容块和无关字段。Codex 本人输入优先取 `item_completed`（含 `event_msg` 包裹）的 `UserMessage`，兼容旧 `user_message`，不取 `response_item` 用户副本；真人判空先剥离已知 IDE/系统注入块，纯标签不参与新旧消息代际选择或重开状态；再排除仍以 `<` 开头的输入。标签后正文和真实图片/附件输入保留；顶层 `image` / `input_image` 块无需文本占位也算新输入，仍受系统/非 human 元数据拒绝规则约束。图片载荷不进入意图；新版只有结构化图片、没有文字时，不据此屏蔽兼容旧格式的文字要求。媒体占位只在提取意图时去除；支持新工具动作项。CC 本人输入取 `origin.kind=human`；没有 `origin` 的旧版只取清理注入块后非 `<` 开头的文本，任务通知/工具结果不算。Pi 仍沿当前分支，不把 `custom_message` 当本人输入；v1 老文件只跳过，不迁移、不报失明。
- loop 只读 `<来源根>/<项目目录>/<UUID>.md`（可加 `claude-`/`codex-` 前缀）；不递归进资料/验收目录，不进入根下 `resources`、`projects`、`pipelines`，不跟随链接，无读权限的文件跳过。完成发「有空看」交代，含结论、次数、欠项、路径。欠项合并提取「需要你做的事」「小问题汇总」「验收额外发现」及全文 `[人工]` 项，跳过明确无和已勾完成的条目；没有欠项写「还欠什么：无」。缺开工原文不伪造。无时区轮次时间按运行机器的**当地时间**解析（OS 时区，或显式 `TZ`；含夏令时），有轮次时不用 mtime；没有轮次时间时，按拍板使用该原件的文件修改时间。进行中的 loop 还会在已配置的 AI 会话来源中，按总结内开发/评审会话号与对应验收会话号取最近一次写记录的时间；都超过 30 分钟才算停滞。卡片「最后在做」写开发 / 评审第几轮 / 验收，不取总结末尾的验收条款。批名优先取总结明确字段，否则从已读开发任务里的批次或提示词标题提取，不额外读取任务文件。
- 完整可解析但没有会话身份/一条核心消息也没有的 AI 文件、Pi v1，作为非会话跳过并统计，不算读不了；Codex 仅 `session_meta`/噪音的空文件也跳过。截断/损坏 JSON 不能据缺字段假装非会话，仍按坏文件处理，保证 R5 的真正坏文件不被掩盖。即使解析器因缺身份/旧版本提前返回，也要完成全文件逐行 JSON 语法校验再判跳过；完整指纹和语法检查分别记录，收尾不采用损坏前缀作为正常事实。
- 来源目录整体读不了、真正会话核心信号整体取不到，或非会话跳过比例明显高于健康历史 →「看不见了」。跳过统计见 JSON 的 `health[].fileStats={total,skipped}`：`total` 是本轮候选普通文件数（排除已识别的内部会话），`skipped` 是非会话/旧版跳过数；目录遍历故障另报，loop 权限跳过不计为非会话异常。`fileStatsProfile=exclude_internal_v2` 标记同时排除前缀与流水线目录的口径，旧 `exclude_internal_v1` 只排除前缀，缺省为最早口径；只与同口径健康基线比较。升级切换口径时，在首份无其他故障且样本充分的报告建立新基线，不拿旧百分比触发失明；变化以新的 source_health 事件追加，即使文件数量未变也会记录。
- 跳过率初次仅建健康基线，不因首次非会话多就失明。实现阈值集中在 `src/core/health.ts`：至少 10 份候选，较健康基线高至少 20 个百分点，且超基线预期至少 3 份才报警；健康报告以 20% 新比例/80% 旧基线平滑更新，异常期间不学习异常值。此为可校准实现默认值，不冒充真实数据业务验收。连续故障仍只一条，恢复后再坏可再次提醒。
- 推送与会话对不上仍沿用原判断：该工具所有会话的当前状态均标「看不见了」，卡片如实说明这个范围，其他工具继续检测；推送入口整体故障则所有 AI 工具会话状态未知、loop 继续检测。本批只改说明文案，不改判断规则。
- 单文件失败不让整个来源失明：按来源一条「某工具有 N 份会话读不了」，至多 3 个例子、正文至多 4 KB，仍属「现在就要你」盯防异常。好文件照常判断，坏文件不把上次成功读取的状态冒充本轮正常；连续故障去重、全部恢复后可开启新一轮。推送读取/对账安全规则维持第一批，不放宽无效推送。
- 数据目录尚无检测记录的首次接入，以首次 `scan_completed` 为固定初始化时间：其前 1 小时内的事照常提醒，更早的只进总览，提醒栏显示「首次接入历史记录，不补发」。抑制作为 `notice_suppressed` 留在事件日志，不进发件；后续空跑/重建不补发。后来有新动静或新等待证据仍可正常提醒，历史抑制不占实际停滞提醒额度；本轮发现的来源读取故障照常报警。
- 来源以 64 KiB 小块逐行读取，UTF-8 字符跨块完整解码，SHA-256 覆盖完整原件。Pi 树索引只保留定位和有限核心内容，不留工具输出/思考/自定义大正文；内存主要取决于单行大小和必要核心索引，而非整份原件，不承诺任意超大单行。
- 同一证据不重复发；总览的提醒栏标出已提醒与去重。决策已提交但未取得文件交付确认时明确标「待写发件记录」，下一轮幂等补齐确认。这里的「已发」仍只指文件渠道；本机通知由独立的 `channel_delivery` 事实确认，不用文件成功冒充通知成功。

