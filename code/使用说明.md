# personal agent：推送与判断（闭环 1 · 段 1）

一次性命令行检测：四个只读来源/推送 → 统一记录 → 规则优先、可选模型判断 → 文件发件及可选本机通知；可用本机命令反馈。另提供三个工具的通知钩子、临时主目录安装/卸载和评测命令。**不常驻、不接飞书，不替用户回复或启停 AI。** 开发与自动验证只用构造/脱敏样本、假模型和假通知；不读取真实个人目录，不安装真实钩子，不调用真实模型、不弹真实通知。

## 段 1：模型、本机通知与反馈

以下新选项均是显式开启；旧样本配置不含它们，仍然只用规则和文件渠道，不会暗中调用模型或弹通知：

```json
{
  "judge": {
    "executable": "/绝对路径/到/pi或测试替身",
    "model": "opencode-go/deepseek-v4.1-flash",
    "dailyLimit": 240,
    "timeoutMs": 30000,
    "cycleTimeoutMs": 60000
  },
  "localChannel": {
    "executable": "/绝对路径/到/通知测试替身",
    "timeoutMs": 3000
  }
}
```

把这些字段加入下节的完整配置。省略或设为 `null` 即停用；可执行文件是一整个路径/文件名，不是 shell 命令。每日上限可为 0（纯规则），缺省 240，按 UTC 日期统计，失败也计调用；时间参数缺省如例。真实本机通知命令为 `/usr/bin/osascript`，**本段开发/自动验收不填这个真实命令**。没有新运行依赖。

### 判断器

- 唯一模型接口 `Judge.judge(JudgmentRequest, options?: {signal?: AbortSignal}): Promise<JudgmentResult>`，见 `src/core/types.ts`；第一版 `src/core/model.ts` 调配置中的 Pi。固定参数含 `-p --no-tools --no-session --no-extensions --no-context-files --mode json`，另禁用 skills、prompt templates、项目配置和自动联网更新；不会给模型工具。`--offline` 只关后台更新，不禁止显式的模型请求。
- 模型读取现拼的小 JSON：意图原文（≤1000 码点）、较新的本人追加要求（共约 2000 码点）、上次做到哪了（≤500 码点）、上次同类检查后新步骤（最多 8 步、每步≤220 码点）、本轮助手回复（≤1200 码点）。摘要由已读操作摘要滚动拼接，不复制整份会话或工具输出；上下文不会随会话无限增长。材料里的指令只当证据。
- 正常检测只问「是 / 否」，并输出依据。跑偏答是必须提供 `intentQuote` 与 `stepQuote`，两者都须匹配实际送入的意图和新步骤；缺失或捏造即按否。不覆盖来源失明、不可用子成员或已搁置状态；原有授权等待/loop 规则优先。每个根会话跑偏检查至少间隔 10 分钟、有新步骤才调用；首次接入 1 小时窗口之前的历史完成记录不耗模型额度，超过 24 小时无动静也不新调；空跑、总览、重建都不调用模型。先前模型判等待/跑偏的会话超过 24 小时无动静，同样只进「已搁置」。
- 助手答完、没有未返回工具、没有明确会话结束时，问是否在等用户回复；是 →「在等我」，否 →保留规则的「已完成」。Codex 子成员单独判断等待，不会把父/兄弟活动当成它回复了用户。
- 所有模型提醒一句话带「可能」。调用失败、超限均按规则兜底，并在总览提醒栏标出「仅规则判断」。调用前在短数据锁内按最新日志预留额度，重启/重建不会忘记已启动的调用；已经失败的调用没有新动静不会反复重试。配置变更不改历史事实。
- **交付顺序与时限**：检测先完成规则判断、发件记录和本机通知，之后才运行无关会话的模型。模型等待期间不持 `.detect.lock`，可接收反馈或运行新的规则检测；模型返回后基于最新事件再次判断/交付，不用迟到答案覆盖新会话事实。`timeoutMs` 是单次上限，`cycleTimeoutMs` 是单轮模型阶段总时限（默认 60 秒），到时取消 Pi 子进程；即使替身忽略取消，也不再等待它。总时限未轮到的检查标「本轮模型时限用完，仅规则判断」，不消耗额度、不吞新步骤，下轮可续查；已发提醒和失败渠道重试仍按编号去重，每个渠道每条提醒一轮至多尝试一次。
- Pi JSON 模式替身须接收同样的 argv 和 stdin（prompt），输出 JSONL，其中最终答案形如：`{"type":"message_end","message":{"role":"assistant","stopReason":"stop","content":[{"type":"text","text":"{\"answer\":\"否\",\"reason\":\"依据\"}"}]}}`。最终文本的 JSON 为 `{answer, reason, intentQuote?, stepQuote?}`；调度层也可注入 `Judge` 替身。参考 `test/judgment-channel.test.ts` 中的完整可执行替身，不能把测试替身指向真实模型。

### 本机渠道和反馈

文件渠道始终保留；本机渠道只对「现在就要你」弹通知，「有空看」仅写发件记录。通知超时/失败不丢文件发件，总览显示未成功条数，下轮重试；成功后去重。外部系统通知与本地确认没有原子事务，进程在通知成功后、确认前崩溃仍可能重复一次。新开启本机渠道不补发已交付历史提醒。

```bash
node code/src/cli/main.ts feedback 误报 '这条不用我处理' --config "$CONFIG"
node code/src/cli/main.ts feedback 正确 --config "$CONFIG"
node code/src/cli/main.ts feedback 漏了 '另一个会话刚才在等我' --unlinked --config "$CONFIG"
```

输出只有「已记下」。可加 `--now <带时区ISO>` 做构造验收。不带 `--id` 默认最近一条发件，`--id <内部提醒编号>` 是机器关联入口；明确不关联的「漏了」用 `--unlinked`，二者不能同用。没有任何提醒时也能记「漏了」；「正确 / 误报」必须指向真实存在的发件。不往给人看的通知或确认文字里写内部编号，亦不执行反馈中的文字。反馈只追加，坏 JSONL/半行会保留现场报错。

**段 2 衔接接口**：`Channel { name; send(notice: Notice): Promise<void>; receive(reply: ChannelReply): Promise<'已记下'> }`。`Notice.id`、`ChannelReply.noticeId` 仅内部关联；`content` 是回复文字、`at` 是日期时间，`noticeId=undefined` 默认最近一条、`null` 表示不关联的漏报。`detect(config, now, {judge?, channels?})` 可注入实现；生产本机渠道由配置选择。收到反馈后可复用 `core/feedback.ts` 统一落盘，调用应在检测锁外。飞书、本周汇总、经验集在下一段实现。

## 段 1：钩子安装与卸载

每个工具都是独立 `message-listener` 组件；CC/Codex 为本机市场插件，Pi 为扩展。安装/卸载的 `--home` 必填，绝不默认使用真实主目录；CC/Codex 通过官方 CLI 插件命令登记，不直接修改 hooks/settings 添加钩子，也不占 Codex notify。安装前备份所动配置的精确字节和权限；不备份或读 auth、Key、sessions。运行配置的推送目录必须与安装时一致，仍须遵守既有的来源/数据/推送目录分离规则。

仅在新的临时目录验装卸（CC/Codex 需已有对应官方 CLI 或插件管理测试替身；不会因此调用模型）：

```bash

H=$(mktemp -d "${TMPDIR:-/tmp}/message-listener-demo.XXXXXX")
INBOX="$H/inbox"
node code/src/hooks/main.ts install --tool cc --home "$H" --inbox "$INBOX" --command /绝对路径/claude

# 检查生成包及备份；仅把编的事件输入包内 Hook，或用 Pi API 替身触发扩展事件

node code/src/hooks/main.ts uninstall --tool codex --home "$H"
node code/src/hooks/main.ts uninstall --tool pi --home "$H"
```

- 生成包：`$H/.message-listener/<工具>/`；每包有自己的 `package.json type=module`，不受祖先包元数据影响。CC/Codex Hook 定义在 `plugins/message-listener/hooks/hooks.json`；实际命令包含固定 Node、显式 inbox 和事件名。CC 每条 Hook 都是 `async: true`。
- 备份：`$H/.message-listener-backups/<工具>.json`，卸载后保留为 `.json.removed`。CC：`.claude/settings.json`、`.claude/plugins/`；Codex：`.codex/config.toml`、`.codex/plugins/`；Pi：`.pi/agent/settings.json`。会拒绝链接/特殊文件。备份状态以原子替换记录 `installing / installed / restoring / rolled_back / recovery_required`：正常卸载仅在成功安装指纹吻合时移除插件/市场并恢复；失败安装若已回滚，后续卸载只清理自己的包和归档备份，绝不再覆盖后来修改的配置。恢复未完成、状态不明或旧备份缺 `after` 时，保留现场并拒绝自动恢复，须先备份后人工核对；不以缺少指纹放行覆盖。
- 安装后若另有设置/插件/信任配置改动，卸载会拒绝整份覆盖，须先备份并人工合并，不能为了卸载丢掉其他设置。Codex 真实使用时可能要 `/hooks` 信任一次，留后续人工操作。本段不在真实工具安装，不让 loop 的开发会话加载扩展。
- 映射：CC `Notification(permission_prompt)`、Codex `PermissionRequest`、Pi `permissions:ui_prompt` → `waiting_permission`；`Stop/agent_settled` → `turn_end`（detail 为最后回复）；`SessionEnd/session_shutdown` → `session_end`；CC `idle_prompt` 不产事件。
- Hook 只从事件取身份/回复，不读会话；只追加 `<inbox>/<tool>.jsonl`，不连网、不等中枢、写不了也成功退出且无错误输出。输入损坏/超过 1 MiB/500 ms 不结束也退出 0。Pi 不装 `tool_call` 处理器，不返回任何行为控制结果。
- 可直接运行纯构造定向验证：`node --test code/test/hooks.test.ts code/test/judgment-channel.test.ts code/test/settled-regressions.test.ts`；不用真实模型/通知，也不向真实工具安装。

## 段 1：评测样本格式

协调方另编样本；每份为目录中的一个 `.json`，字段示例（全部文字为编造）：

```json
{
  "task": "drift",
  "intentOriginal": "只改 A 文件",
  "additionalRequirements": [],
  "previousSummary": "还没改文件",
  "newSteps": ["Bash：修改不相关的 B 模块"],
  "assistantReply": "",
  "expected": "是"
}
```

`task` 为 `drift` 或 `waiting`；期望是「是/否」，`newSteps` 也可用 `{at: ISO时间, text: 摘要}` 数组。等待分类样本应填写助手最终回复。目录只读、不跟随样本链接；命令只写显式数据目录的调用计数，建议每次评测用独立临时数据目录。

```bash
node code/src/cli/main.ts evaluate --config "$CONFIG" --samples /绝对路径/构造样本目录
node code/src/cli/main.ts evaluate --config "$CONFIG" --samples /绝对路径/构造样本目录 --json
```

使用当前配置的同一判断器，每份分别问「是/否」和「高/中/低」（对问题为是的程度，高映射是，中/低映射否），输出两种各判对几份、调用失败/超限数及 JSON 明细；**只记分，不设通过线**。模型是否有效由这份记录和用户反馈判断。评测也计入同一 UTC 日上限，无真实模型配置时会报错或只用替身。开发/门禁只跑替身，真实 `opencode-go/deepseek-v4.1-flash` 评测由协调方在段 1 后另跑，不代表已完成。

## 显式配置

CLI 的来源、推送、数据目录和回看可执行文件全部来自 `--config`；不自动找配置文件、不读取工具全局配置、不使用默认个人目录。目录必须是绝对路径，不展开 `~`。四个来源和 `inboxDir` 每一项都必须提供；`null` 表示明确关闭，**非空但不存在/读不进的目录会报「看不见了」，不会当空目录**。

示例仅为构造路径（不要原样运行；下节有可运行的样本配置生成器）：

```json
{
  "sources": {
    "cc": "/tmp/my-samples/claude-projects",
    "codex": null,
    "pi": null,
    "loop": null
  },
  "inboxDir": "/tmp/my-samples/inbox",
  "dataDir": "/tmp/personal-agent-run/data",
  "ignoreProjectPrefixes": ["/private/tmp", "/var/folders"],
  "commands": {
    "cc": "claude",
    "codex": "/sample-tools/codex",
    "pi": "pi"
  }
}
```

- `commands` 的三项也必须显式提供，是可执行文件名或完整路径，**不是带参数的 shell 命令串**。含空格的路径自动引用；这里只生成文字，不检查工具安装、不执行命令。
- `ignoreProjectPrefixes` 是可选的绝对目录路径数组，省略等同 `[]`，不默认过滤。忽略目录本身及其子目录，例如 `/private/tmp` 匹配 `/private/tmp/test`，不匹配 `/private/tmp-other`；不展开 `~`，不读取这些项目目录来做匹配。忽略项目的会话不入总览、不发提醒；Codex 忽略父会话时连带忽略子代理。过滤也适用于已有事件的查询/重建及未交付提醒，历史事实不删。坏文件若仍可提取核心项目身份，也能按配置忽略；身份线索用于过滤和不可用关联，绝不拿来伪造正常状态或给新推送对账。
- 来源文件只读。来源中的符号链接不跟随；数据文件不允许符号链接或硬链接。数据与任一来源/推送目录不能互为祖先或相同，包含可解析的符号链接别名。
- 推送仅按方案格式读取 `cc.jsonl`、`codex.jsonl`、`pi.jsonl`：`tool/event/session_id/cwd/transcript_path/at/detail`；事件为 `waiting_permission`、`turn_end`、`session_end`。`at` 是带时区 ISO 时间。只记录读取行数/指纹并去重，不改、不删 inbox；重复内容不会重复计入推送事实。当前实现为校验只读重扫，游标持久化但不依赖它跳过完整性检查。
- `transcript_path` 只用于对账和定位，不能引导程序打开配置外文件；对账必须同时匹配实际会话成员的工具、会话 ID、项目和原件路径，不能借用父记录聚合的其他原件。原件/所在目录读取失败，或子会话归并失败时，推送只留原始事实，既不借旧记录校验、也不把该局部故障放大为整体失明；其他对不上的推送仍按工具报盯防异常。
- 收到的语法合法推送先以 `push_observed` 留存；只有明确通过对账、另有 `push_validated` 事件的推送才能参与判断。无效推送不会因来源恢复或停用 inbox 而重新生效；原始事实去重包含项目和会话路径，纠正字段后的新推送可以独立对账。旧日志中只有 `push_observed` 的历史推送也保持非判断态；升级后先备份显式数据目录，再运行一轮检测，才能根据当前来源为有效推送追加对账结果，无需改写/删除旧事件。

## 检测、总览与发件

假设 `CONFIG` 已指向配置文件：

```bash
node code/src/cli/main.ts detect --config "$CONFIG"
node code/src/cli/main.ts detect --config "$CONFIG" --now '2026-10-20T10:51:00Z'
node code/src/cli/main.ts overview --config "$CONFIG"
```

`--now` 必须带时区；省略时检测用系统当前时间。总览默认采用最近一次检测时间，保证回看样本结果不会随现实时间漂移；可以给总览 `--now` 做纯查询推算，但查询不发提醒。`--json` 可加在三个命令后，输出机器可读记录（含内部关联键）；面向人的默认总览不显示这些编号。

数据目录只有四类持久文件：

| 文件 | 内容 |
|---|---|
| `events.jsonl` | 唯一事实源，只追加：模型用量预留/判断、渠道投递队列/结果、统一记录、原始推送/对账、来源健康（会话清单、候选/非会话跳过计数、坏文件数量/至多 3 例）、游标、检测时间、提醒/历史抑制决策和交付确认。只保存必要字段，不复制整份原件或工具返回正文 |
| `outbox.jsonl` | 假渠道已投递提醒，只追加，包含 `level`、结构化 `content`、给人看的 `text` |
| `feedback.jsonl` | 只追加「正确 / 误报 / 漏了」反馈：日期、内部提醒关联（或 null）、渠道、可选说明 |
| `state.json` | 从事件推算的当前状态，可删、可重建，不依赖它去重；单行完整 JSON |

看给人读的发件内容（把 `DATA` 设为配置中的 `dataDir`）：

```bash
node --input-type=module -e '
import { readFile } from "node:fs/promises";
const rows = (await readFile(process.argv[1], "utf8")).split("\n").filter(Boolean);
for (const row of rows) { const n = JSON.parse(row); console.log(`【${n.level}】\n${n.text}\n`); }
if (!rows.length) console.log("暂无提醒");
' "$DATA/outbox.jsonl"
```

所有数据文件的非空行均为完整 JSON；`--json` 输出整体可直接解析。意图每段最多保留 1000 个 Unicode 码点（超出追加省略号），步骤为有限摘要，截断不切开表情等多字节字符；短原文保留换行。无新动静时只追加很小的检测时间事件，不重复写会话/健康快照。

提醒先写标题、判断、回看命令，再写意图原文、本人追加要求、最近几步和依据；内部 `id`/去重键只在 JSON 元数据里。回看：Claude Code `claude --resume <id>`、Codex `<配置路径> resume <id>`、Pi `pi --session <id>`；loop 用 `open <总结文件>`。这些命令只作为交代，不会被程序执行。

规则要点：

- 等授权且之后没有新动静 →「在等我」；loop 暂停也在等我。「现在就要你」。Codex 子会话仍归父记录一行，但按各成员自己的活动时间判断等待，父/兄弟继续活动不能掩盖它；提醒用父任务意图、实际等待成员的动作和回看命令。子会话 `turn_end/session_end` 只结束该成员，不能结束仍在工作的父会话。子成员本轮读取/归并失败时，保留其与可读父任务的关联并标 `unavailable`；首次检测即失败，也会用仍可可靠提取的 `session_meta` 父子身份建立不可用关联，而不是把失败成员缺席当作全部完成。身份只用于关联，不取损坏正文的调用/完成前缀，不给新推送对账；无历史活动事实时成员 `lastActivityAt` 为 `null`，不捏造时间。有历史则保留最后事实。没有全部完成证据时保持「进行中」并在判断依据写明本轮读不了，先前已对账的授权等待也不能凭失败期间的新推送解除。其他根会话照常判断；恢复读取后用新事实解除标记，不因失联误报完成或停滞。
- 纯规则配置下，本轮结束/助手答完且无未返回工具 →「已完成」。启用判断器后按上文区分是否在等你回复，并判断跑偏；明确会话结束/loop 完成仍优先使用规则。普通完成和进行中不发提醒。Pi `stopReason=error/aborted` 消息中的工具提案不登记为未返回，正常重试答完可完成；Codex `task_complete` 后的已完成后台 `item_completed` 不重开任务，新输入/新调用/`task_started` 仍重开。
- 可确认仍未结束，最后动静**超过 30 分钟、未超过 24 小时** →「停滞」；「有空看」，同一会话实际停滞提醒终身一次。**超过 24 小时**没有动静且未结束 →「已搁置」，只进总览、不提醒（包括长期等待/loop 暂停）；已完成的旧会话不降级。读取失败造成的状态未知不冒充停滞/已搁置；新活动后按新事实判断。
- 只取核心信号，忽略未知记录类型、内容块和无关字段。Codex 本人输入优先取 `item_completed`（含 `event_msg` 包裹）的 `UserMessage`，兼容旧 `user_message`，不取 `response_item` 用户副本、不取 `<` 开头的输入；支持新工具动作项。CC 本人输入取 `origin.kind=human`；没有 `origin` 的旧版只取非 `<` 开头的文本，任务通知/工具结果不算。Pi 仍沿当前分支，不把 `custom_message` 当本人输入；v1 老文件只跳过，不迁移、不报失明。
- loop 只读 `<来源根>/<项目目录>/<UUID>.md`（可加 `claude-`/`codex-` 前缀）；不递归进资料/验收目录，不进入根下 `resources`、`projects`、`pipelines`，不跟随链接，无读权限的文件跳过。完成发「有空看」交代，含结论、次数、欠项、路径。缺「需要你做的事」段时明确说「总结里没写」，不能说没有待办；缺开工原文也不伪造。无时区轮次时间按运行机器的**当地时间**解析（OS 时区，或显式 `TZ`；含夏令时），有轮次时不用 mtime；没有轮次时间时，按拍板使用该原件的文件修改时间。
- 完整可解析但没有会话身份/一条核心消息也没有的 AI 文件、Pi v1，作为非会话跳过并统计，不算读不了；Codex 仅 `session_meta`/噪音的空文件也跳过。截断/损坏 JSON 不能据缺字段假装非会话，仍按坏文件处理，保证 R5 的真正坏文件不被掩盖。即使解析器因缺身份/旧版本提前返回，也要完成全文件逐行 JSON 语法校验再判跳过；完整指纹和语法检查分别记录，收尾不采用损坏前缀作为正常事实。
- 来源目录整体读不了、真正会话核心信号整体取不到，或非会话跳过比例明显高于健康历史 →「看不见了」。跳过统计见 JSON 的 `health[].fileStats={total,skipped}`：`total` 是本轮候选普通文件数，`skipped` 是非会话/旧版跳过数；目录遍历故障另报，loop 权限跳过不计为非会话异常。
- 跳过率初次仅建健康基线，不因首次非会话多就失明。实现阈值集中在 `src/core/health.ts`：至少 10 份候选，较健康基线高至少 20 个百分点，且超基线预期至少 3 份才报警；健康报告以 20% 新比例/80% 旧基线平滑更新，异常期间不学习异常值。此为可校准实现默认值，不冒充真实数据业务验收。连续故障仍只一条，恢复后再坏可再次提醒。
- 单文件失败不让整个来源失明：按来源一条「某工具有 N 份会话读不了」，至多 3 个例子、正文至多 4 KB，仍属「现在就要你」盯防异常。好文件照常判断，坏文件不把上次成功读取的状态冒充本轮正常；连续故障去重、全部恢复后可开启新一轮。推送读取/对账安全规则维持第一批，不放宽无效推送。
- 数据目录尚无检测记录的首次接入，以首次 `scan_completed` 为固定初始化时间：其前 1 小时内的事照常提醒，更早的只进总览，提醒栏显示「首次接入历史记录，不补发」。抑制作为 `notice_suppressed` 留在事件日志，不进发件；后续空跑/重建不补发。后来有新动静或新等待证据仍可正常提醒，历史抑制不占实际停滞提醒额度；本轮发现的来源读取故障照常报警。
- 来源以 64 KiB 小块逐行读取，UTF-8 字符跨块完整解码，SHA-256 覆盖完整原件。Pi 树索引只保留定位和有限核心内容，不留工具输出/思考/自定义大正文；内存主要取决于单行大小和必要核心索引，而非整份原件，不承诺任意超大单行。
- 同一证据不重复发；总览的提醒栏标出已提醒与去重。决策已提交但未取得文件交付确认时明确标「待写发件记录」，下一轮幂等补齐确认。这里的「已发」仍只指文件渠道；本机通知由独立的 `channel_delivery` 事实确认，不用文件成功冒充通知成功。

## 重建与故障恢复

```bash
node code/src/cli/main.ts rebuild --config "$CONFIG"
```

`state.json` 缺失或内容损坏时，`overview` 仍从事件查询，`rebuild` 或下一轮检测会重建它；不会因此重复提醒。不更改 `events.jsonl`、`outbox.jsonl` 和 `feedback.jsonl` 的既有内容。本批没有操作已有真实数据目录，也没有执行原地迁移。

若事实日志损坏/末行未完整写入，程序非 0 退出并保留原件，不擅自截断。**先备份整个指定数据目录**，再人工检查损坏位置、恢复已知完整备份；不要用删除事件来消除提醒。`outbox` 是已发事实；本批的文件渠道在异常中断后可根据已提交的提醒决策补齐未写记录，不因 `state.json` 丢失重新发。

段 1 在原日志上只追加 `model_call_started`（UTC 日用量预留）、`model_checked`（可重放答案/失败、步骤指纹和有界进度摘要）、`channel_delivery`（本机排队/结果）；会话事实加可选 `assistantReply`，状态加「疑似跑偏」，反馈开始写 version=1 的 `feedback.jsonl` 行。旧日志缺新字段仍可重放，无需原地迁移。升级前仍须按下文备份整个显式数据目录；旧程序不认识新事件，回退必须恢复配套备份。开发仅在构造临时目录验证追加/重建，没有操作真实记忆库或执行真实迁移。

第一批已有父子成员事实和 `push_validated` 事件；本批在现有事件中追加可选的文件失败统计、可见会话清单、父成员定位、失败成员的 `unavailable` 标记（无活动事实时其 `lastActivityAt=null`）和 loop 欠项段存在标记，增加 `unreadable` 提醒类型，并把可重建 `state.json` 改为单行 JSON。本轮追加可选 `fileStats`/健康跳过基线，新增 `notice_suppressed` 事件和「已搁置」状态；初始化时刻由既有首个 `scan_completed` 推算。旧事件缺新字段仍可重放；新代码不原地迁移、不删改事实日志。旧代码不识别新事件时必须恢复配套备份，不能删新事件凑兼容。

**升级前先备份整个显式数据目录**（示例：`cp -a "$DATA" "$RUN/data-before-upgrade"`，备份位置须独立且不在来源树）。需要回退时，先停掉该目录的检测进程，保留升级后目录供核对，再用升级前完整备份恢复到新的独立目录，让旧代码配置指向它；不要把新旧日志混拼，也不要删新事件凑兼容。`state.json` 仅是派生缓存，可由相应版本代码重建。开发只验证构造临时目录中的重放，没有迁移或写入真实运行数据。

`.detect.lock` 只保护来源感知、事件/额度短写入及渠道交付；模型调用在锁外，`.model.lock` 仅防重复模型批次，已占用时新检测仍完成规则阶段、不再启动一份模型批次。反馈也用数据锁，不会等待整批模型调用。进程异常退出遗留锁时，只有确认相关检测/模型进程都已退出后才能删除对应锁目录并重跑；不得自动清锁，也不能绕过接口并发写数据。
