# personal agent：感知与总览

本批是一次性命令行检测：四个来源 → 统一记录 → 规则判断 → 文件发件。**不调用模型，不装钩子，不运行常驻进程，不接任何真实通知渠道。** 开发与验收只使用协调样本或 `code/test/` 编造的数据，不能填写真实个人会话目录。

## 环境与门禁

需要 Node.js **22.19 以上**、npm。运行时只有 Node 内置模块；TypeScript 和 Node 类型包仅用于开发检查，版本锁在 `package-lock.json`。无生命周期安装脚本。

在本批工作树根操作（不是协调方的项目根）：

```bash
cd '/Users/Admin/Desktop/personal agent/.worktrees/闭环1-感知与总览'
bash code/deploy/check.sh
```

门禁首次缺少开发依赖时执行 `npm ci --ignore-scripts --no-audit --no-fund`，之后检查 Node 版本、无第三方运行依赖、shell 语法、TypeScript 类型和构造测试。退出码 0 代表本项目技术检查通过，不代表 loop 评审或用户业务验收通过。

外部协调样本没有进仓库。门禁不配置 `PA_SAMPLE_ROOT` 时会明确跳过外部场景测试，**不能把跳过当 A1–A10 通过**。本批跑齐外部场景的命令：

```bash
PA_SAMPLE_ROOT='/Users/Admin/Desktop/personal agent/docs/batches/闭环1-感知与总览-20261025/samples' \
  bash code/deploy/check.sh
```

## 显式配置

CLI 的来源、推送、数据目录和回看可执行文件全部来自 `--config`；不自动找配置文件、不读取工具全局配置、不使用默认个人目录。目录必须是绝对路径，不展开 `~`。四个来源和 `inboxDir` 每一项都必须提供；`null` 表示明确关闭，**非空但不存在/读不进的目录会报「看不见了」，不会当空目录**。

示例仅为构造路径（不要原样运行；下节有可运行的样本配置生成器）：

```json
{
  "sources": {
    "cc": "/tmp/my-samples/claude-projects",
    "codex": null,
    "pi": null,
    "loop": null
  },
  "inboxDir": "/tmp/my-samples/inbox",
  "dataDir": "/tmp/personal-agent-run/data",
  "commands": {
    "cc": "claude",
    "codex": "/sample-tools/codex",
    "pi": "pi"
  }
}
```

- `commands` 的三项也必须显式提供，是可执行文件名或完整路径，**不是带参数的 shell 命令串**。含空格的路径自动引用；这里只生成文字，不检查工具安装、不执行命令。
- 来源文件只读。来源中的符号链接不跟随；数据文件不允许符号链接或硬链接。数据与任一来源/推送目录不能互为祖先或相同，包含可解析的符号链接别名。
- 推送仅按方案格式读取 `cc.jsonl`、`codex.jsonl`、`pi.jsonl`：`tool/event/session_id/cwd/transcript_path/at/detail`；事件为 `waiting_permission`、`turn_end`、`session_end`。`at` 是带时区 ISO 时间。只记录读取行数/指纹并去重，不改、不删 inbox；重复内容不会重复计入推送事实。当前实现为校验只读重扫，游标持久化但不依赖它跳过完整性检查。
- `transcript_path` 只用于对账和定位，不能引导程序打开配置外文件；对账必须同时匹配实际会话成员的工具、会话 ID、项目和原件路径，不能借用父记录聚合的其他原件。对不上会按工具报盯防异常。
- 收到的语法合法推送先以 `push_observed` 留存；只有明确通过对账、另有 `push_validated` 事件的推送才能参与判断。无效推送不会因来源恢复或停用 inbox 而重新生效；原始事实去重包含项目和会话路径，纠正字段后的新推送可以独立对账。旧日志中只有 `push_observed` 的历史推送也保持非判断态；升级后先备份显式数据目录，再运行一轮检测，才能根据当前来源为有效推送追加对账结果，无需改写/删除旧事件。

## 检测、总览与发件

假设 `CONFIG` 已指向配置文件：

```bash
node code/src/cli/main.ts detect --config "$CONFIG"
node code/src/cli/main.ts detect --config "$CONFIG" --now '2026-10-20T10:51:00Z'
node code/src/cli/main.ts overview --config "$CONFIG"
```

`--now` 必须带时区；省略时检测用系统当前时间。总览默认采用最近一次检测时间，保证回看样本结果不会随现实时间漂移；可以给总览 `--now` 做纯查询推算，但查询不发提醒。`--json` 可加在三个命令后，输出机器可读记录（含内部关联键）；面向人的默认总览不显示这些编号。

数据目录只有四类持久文件：

| 文件 | 内容 |
|---|---|
| `events.jsonl` | 唯一事实源，只追加：读到的统一记录、原始推送及对账结果、来源健康、游标、检测时间、提醒决策和交付确认。只保存意图/有限最近步骤等必要字段，不复制整份原件或工具返回正文 |
| `outbox.jsonl` | 假渠道已投递提醒，只追加，包含 `level`、结构化 `content`、给人看的 `text` |
| `feedback.jsonl` | 本批初始化为空，不实现反馈 |
| `state.json` | 从事件推算的当前状态，可删、可重建，不依赖它去重 |

看给人读的发件内容（把 `DATA` 设为配置中的 `dataDir`）：

```bash
node --input-type=module -e '
import { readFile } from "node:fs/promises";
const rows = (await readFile(process.argv[1], "utf8")).split("\n").filter(Boolean);
for (const row of rows) { const n = JSON.parse(row); console.log(`【${n.level}】\n${n.text}\n`); }
if (!rows.length) console.log("暂无提醒");
' "$DATA/outbox.jsonl"
```

提醒先写标题、判断、回看命令，再写意图原文、本人追加要求、最近几步和依据；内部 `id`/去重键只在 JSON 元数据里。回看：Claude Code `claude --resume <id>`、Codex `<配置路径> resume <id>`、Pi `pi --session <id>`；loop 用 `open <总结文件>`。这些命令只作为交代，不会被程序执行。

规则要点：

- 等授权且之后没有新动静 →「在等我」；loop 暂停也在等我。「现在就要你」。Codex 子会话仍归父记录一行，但按各成员自己的活动时间判断等待，父/兄弟继续活动不能掩盖它；提醒用父任务意图、实际等待成员的动作和回看命令。子会话 `turn_end/session_end` 只结束该成员，不能结束仍在工作的父会话。
- 本轮结束/助手答完且无未返回工具 →「已完成」；本批不判「答完还是在问你」。普通完成和进行中不发提醒。
- 仍未答完、最后记录**超过** 30 分钟、无会话结束 →「停滞」；「有空看」，同一会话终身只提醒一次，即使恢复后再次停滞。
- loop 完成发「有空看」交代，含结论、次数、欠项、路径。总结没有开工原文就明确写缺失，不从验收标准造意图。其无时区轮次时间本批按 UTC 读，不拿样本复制时间当活动时间。
- 来源/推送读取或格式失败 →「看不见了」，同一来源连续故障合并提醒，恢复后再坏可再次提醒。其他来源照常处理；旧记录保留但标为状态无法确认，不冒充当前正常。
- 同一证据不重复发；总览的提醒栏标出已提醒与去重。决策已提交但未取得文件交付确认时明确标「待写发件记录」，下一轮幂等补齐确认。这里的「已发」只指文件假渠道，不代表真实通知已送达。

先读只读样本的 `README.md` 和对应 `卡片.md`：

每个场景的配置对应如下，表中目录都在 `$S/<场景>/` 下面；`—` 必须配 `null`，不要创建样本子目录：

以下示例验 01；换场景时替换 `SCENE` 和卡片时间，**每个场景重新 `mktemp`，不要复用上一场景数据目录**：

```bash
SCENE='01-等授权'
RUN=$(mktemp -d "${TMPDIR:-/tmp}/personal-agent-acceptance.XXXXXX")
node code/deploy/sample-config.ts "$S/$SCENE" "$RUN/data" "$RUN/config.json"

printf '本次配置：%s\n本次数据：%s\n' "$CONFIG" "$DATA"
```

生成器只在指定临时位置写配置，不创建/改动样本目录；缺少的来源显式 `null`。Codex 回看路径明确设为演示用 `/sample-tools/codex`，不连接真实工具。查看发件用上节命令：01 应有三条「现在就要你」；03 是 Codex 失明而 CC 正常；04 是暂停原因；05 是完成及 3 次评审/2 次返修/A2 人工欠项；06 无提醒；07 每会话一行；08 的追加要求只包含本人那条。

**02 的三轮必须使用同一份新配置和数据目录**，按顺序操作：

```bash

RUN=$(mktemp -d "${TMPDIR:-/tmp}/personal-agent-acceptance.XXXXXX")
node code/deploy/sample-config.ts "$S/$SCENE" "$RUN/data" "$RUN/config.json"
CONFIG="$RUN/config.json"; DATA="$RUN/data"
node code/src/cli/main.ts detect --config "$CONFIG" --now '2026-10-20T10:49:00Z'

node code/src/cli/main.ts detect --config "$CONFIG" --now '2026-10-20T10:51:00Z'
# 用上节命令看发件：一条有空看，npm test 停 31 分钟，前面改了哪两个文件
node code/src/cli/main.ts detect --config "$CONFIG" --now '2026-10-20T11:00:00Z'
# 发件仍一条，不重复
```


## 重建与故障恢复

```bash
node code/src/cli/main.ts rebuild --config "$CONFIG"
```

`state.json` 缺失或内容损坏时，`overview` 仍从事件查询，`rebuild` 或下一轮检测会重建它；不会因此重复提醒。不更改 `events.jsonl`、`outbox.jsonl` 和 `feedback.jsonl` 的既有内容。本批新建存储，不涉及已有数据库结构迁移。

若事实日志损坏/末行未完整写入，程序非 0 退出并保留原件，不擅自截断。**先备份整个指定数据目录**，再人工检查损坏位置、恢复已知完整备份；不要用删除事件来消除提醒。`outbox` 是已发事实；本批的文件渠道在异常中断后可根据已提交的提醒决策补齐未写记录，不因 `state.json` 丢失重新发。

本次返修新增父子成员事实和 `push_validated` 事件，旧事件只读兼容，不作原地迁移。升级运行前备份显式数据目录；若退回不识别这些事件的旧代码，必须配套恢复升级前的完整数据目录备份，不能删掉新事件凑兼容。开发自测只在构造的临时目录验证新旧日志重放，没有迁移或写入真实运行数据。

检测有 `.detect.lock` 互斥锁；进程异常退出遗留时，只在确认没有检测进程后删除这个锁目录，再重跑。不要自动清锁或并发写同一个数据目录。

## 代码入口与组件

- `src/core/perception.ts`：只读感知；`normalize.ts`：统一记录/子代理合并；`judge.ts`：纯规则和内容；`agent.ts`：一轮流程。
- `src/core/events.ts` / `store.ts`：事件推算、只追加存储、原子写状态。
- 来源说明：[Claude Code](src/sources/cc/说明.md)、[Codex](src/sources/codex/说明.md)、[Pi](src/sources/pi/说明.md)、[loop](src/sources/loop/说明.md)。
- 渠道说明：[file](src/channels/file/说明.md)。其余渠道、模型、钩子、反馈与常驻均未实施。
- 不识别的来源格式会失败告警；本批未验证真实版本/账号，也不宣称覆盖全部工具未来格式。
