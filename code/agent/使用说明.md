## 2. 隔离体验：四个入口

全用临时目录，不读取真实 PA、附件、账号。以下终端均在 `code/agent/`。

**终端一：模型、假飞书、本机通知替身及 Loop 快照**

```sh

M=http://127.0.0.1:实际模型端口
```

**终端二：PA 主进程**

```sh
node dist/src/main.js --config "$T/config.json"
```

**终端三：独立看门狗**

```sh
node dist/src/watchdog-main.js --config "$T/config.json"
```

**终端四：发消息、观察**

```sh
curl -s "$F/inject" -H 'content-type: application/json' -d '{"id":"first","who":"owner","chatType":"p2p","text":"现在还有几个loop在工作"}'
curl -s "$F/messages"
curl -s "$M/requests"
curl -s "$F/notifications"
```

默认脚本先调 `query_loop`，再回复有 3 个批次，不开任务卡。请求里能看到系统提示 → 对话原话窗口（首次为空）→ 任务表/命中卡 → 新输入。后续轮次追加原始工具交互。消息 `id` 用于去重；要发一条新消息就换 id。

正常停止：各终端 `Ctrl-C` / 对**自己启动的确切 PID** 发 `SIGTERM`；先停 PA/看门狗，最后停终端一替身。PA 最多 30 秒退出，未做完的输入及检查点保留；启动同一配置继续。不要按进程名批量杀。替身不是线上服务，不要绑定公网。`sandbox.mjs` 不启动 PA、Pi、真实 Loop 或 launchd。

## 3. 替身接口

### 假飞书与本机通知

- `POST /inject`：简写消息（上例），或原始 SDK event；`who` 默认 `owner`、`chatType` 默认 `p2p`。别人/群聊只记忽略日志。
- 图片/文件：`{"id":"file1","attachment":{"kind":"file","name":"note.txt","key":"asset1","content":"构造原文"}}`；图片用 `kind:"image"` 和 `contentBase64`。附件先持久接收再下载，目标为 `<T>/attachments/`，不在数据目录内。
- 引用：加 `quoteId`；按钮：`{"id":"click1","quoteId":"om_x","button":{"value":{"action":"hold","task":"x"}}}`。原样交 Router，不按按钮文字推断业务。
- `GET /messages`：已发给本人的消息及更新；`POST /send` 按 key 去重，`POST /update` 按 id 更新。
- `GET /notifications`：本机通知替身记录，含 fault/state/key/action；`POST /notify` 按 key 去重。
- `POST /connection {"connected":false}` / `true`：模拟飞书接收断开/恢复。
- `GET /events?after=N`：只增量取后续输入；`GET /assets/<key>` 下载构造附件。
- 沙盒把假飞书状态放在 `<T>/fake-feishu-state.json`，模型请求放在 `<T>/model-requests.json`，方便看证据。这些是替身自己的文件，不是 PA 数据。

### 脚本模型（本地 OpenAI 兼容）

`POST /v1/chat/completions`。`GET /requests` 看调用；`POST /script` 更换后续脚本，不触碰模型配置/凭证。每个输入按 `x-opencode-session` 独立跑 flow；也可用 `turns:[[...],[...]]` 为第几条输入分别指定脚本。已有输入的轮次不因换脚本重置。

```sh
curl -s "$M/script" -H 'content-type: application/json' -d '{
  "requireReasoning":true,
  "flow":[
    {"tools":[{"name":"read_file","arguments":{"path":"/授权项目/构造文件.txt"}}]},
    {"tools":[{"name":"reply","arguments":{"text":"已看构造文件"}}]},
    {"text":"done"}
  ]
}'
```

step 支持 `tools:[{name,arguments}]`、`text`、`reasoning_content`、`delayMs`、`status:503`、`hang:true`（连上但不回）。替身补构造的 reason/plan，真实模型须自己提供简短依据/方案。字符串模板：`{{text}}` 新输入原文、`{{attachment0}}` 首附件路径、`{{loopCount}}` 最近工具回包的批次数。`requireReasoning` 会拒绝未回传 reasoning_content 的 assistant 工具消息，含空字符串也会检查。

替身始终校验消息协议：`tool` 只能带文字，`tool_call_id` 必须一一对应，全部工具回执给齐前不能插入其他角色消息；违规返回 HTTP 400。`read_image` 的内部图片结果由模型适配器转换为**全部工具回执之后的 user 视觉材料消息**，工具回执仍保留调用 ID、路径和指纹；不是把 image_url 塞在 tool 里，也不是新增一条本人指令。并行图片/文字工具和检查点恢复都沿用这一转换。

独立启动单个替身（不是 sandbox 时）：

```sh
node dist/src/stubs/main.js feishu --port 8766 --state /临时目录/fake-state.json
node dist/src/stubs/main.js model --port 8765 --script /临时目录/script.json --state /临时目录/requests.json
```

均只监听 `127.0.0.1`。可加 `--ready-file /临时文件`。

### Loop 状态替身

`<T>/loop.json` 是 v1 查询外壳，沙盒预置 3 个构造批次。修改它即可改变返回值。独立调用：

```sh
node scripts/loop-stub.mjs --state "$T/loop.json" 查询 --all --json
```

只接受上述只读命令，任何开工、启动、送话等一律拒绝；PA 本段也只会追加 `查询 --all --json`。`loop.args` 可带替身的 `--calls /临时文件` 看调用证据。真实查询也必须是 `loop 查询`，不是可能触发恢复的 `loop 状态`。结果按授权项目过滤；证据路径仅登记本项目目录或配置中专属该项目的 `loopRunDirs` 内路径。登记不等于放过黑名单。

### 拉起替身（代替 launchd）

先停终端二的手工 PA，然后：

```sh
node scripts/supervisor-stub.mjs --delay-ms 25000 --pid-file "$T/child-pid.json" -- node "$PWD/dist/src/main.js" --config "$T/config.json"
```

只拉起/结束自己 spawn 并登记的子进程组，不查名字。强杀 `child-pid.json` 的 pid（不是 supervisor），25 秒后拉起；停止 supervisor 会正常结束它的子进程。A6 可先把配置 `watchdog.heartbeatStaleMs` 改成 `20000`、`heartbeatMs` 改成 `500`、`pollMs` 改成 `150`，重启主进程/看门狗读取新配置。应各收到一次“停了”和“已恢复”。

## 4. 验收操作要点

不代替提示词的 A1–A10；这里只解释如何操纵已提供的入口：

- **A2**：`/inject` 分别设置 `who:"other"`、`chatType:"group"`；`/requests` 不增加。
- **A3**：用上述 attachment 格式，检查 `<T>/attachments/` 与新输入中的路径。`read_image` 将授权图片作为视觉内容送给模型；是否真看懂真实截图留给实际模型/业务体验验证。
- **A4**：只在 T 内造白名单外文件、假 `.ssh/id_rsa`、项目内链接及普通文件。给模型 flow 排三次 `read_file`，再看后续请求的工具回包；仅普通文件产生 `file_read` 事件。图片同样过读权限检查。
- **A5**：放文件到 `<T>/inbox/`。关通知：配置 `intake.watch:false` 后正常重启 PA；第二个文件在 `fallbackMs` 内进入模型。文件通知失效也保留兜底。
- **A7**：脚本 `{"flow":[{"hang":true}]}` 就是只连不回的本地端口；配置 `watchdog.inputStaleMs:30000`。如要观察两分钟持续卡住，把 `model.timeoutMs` 和 `queue.inputTimeoutMs` 均设为 `240000`。看门狗不调模型、不终止主进程。
- **A8**：`windowTokens:2000`，发 30 个不同 id。窗口采用保守的 **UTF-8 字节 token 上界 + 每条 8 token**，不以字符数/4低估中文或 emoji；超过上限一次淘汰到不高于 60%，单条超大原话会整个退出窗口，不截断/摘要。事件日志保留原文。
- **A9**：门禁里的 `system.test.ts` 真实构造 10001 条事件、200 张已关卡，空闲运行 180 秒；只测主进程最后 120 秒 CPU，不把替身 CPU 算进去，打印比例；同时核对例行检查没有新增事件日志。空闲不扫描日志全文；队列、卡、游标有索引。
- **A10**：脚本 step 可设 `delayMs:1000`；发 3 条，在第一条处理时正常停。重启继续剩余两条，`/messages` 每条只回一次。`SIGKILL` 后也从 SQLite 图检查点接着走，已经发过的回复不再执行。

## 5. 配置与硬边界

所有配置只在启动时读；运行中不改写、不自动重载，改后正常重启。完整键见 `config.example.json`，沙盒自动填入实际临时路径/端口。

- `projects[].root/loopRunDirs`、`inboxDirs`、`attachmentDir` 定最大读范围；`readAllow:[]` 表示沿用这些范围，非空只做进一步收窄，不扩到其他目录。`readDeny` 追加绝对路径黑名单，不能删除内置底线。Loop 运行目录务必只填**属于该授权项目**的部分，不能填整个全局运行目录。
- 内置拒绝：`.env*`（`.example/.sample/.template` 例外）、私钥/证书常见后缀和 PEM 标记、`.npmrc/.pypirc/.netrc/.git-credentials/.git/config`、带 auth/session/cookie 的 JSON/数据库、`.ssh/.aws/.gnupg`、钥匙串/密码管理器/私人聊天、备份目录/文件、eval 三类个人数据目录、当前/旧 PA 数据目录、配置和凭证源文件。先看黑名单，再按**真实路径**比白名单；目录链接、`..` 不能扩权；多硬链接文件保守拒绝。
- 飞书附件在数据 KV 中先登记**未改动的原始名称 → 真实保存路径**；即使保存名带 hash、经项目内链接访问或重启，仍按原名再过一次黑名单。尚无原名元数据的旧式 hash 附件保守拒读，可重新发送；正在恢复的输入会从已保存输入登记原名。不会靠改名把 `.env/.npmrc/.netrc` 变成可读文件，`.env.example` 等示例仍可读。
- `read_file` 是限长分段读（每次最多 64000 字节），`read_image` 只读受限图片格式，`evidence:true` 也只能读登记且归属正确的证据。内部任务/事件只能走 `get_task/search_closed_tasks/read_events` 专用工具，不能读 SQLite/日志文件。
- `model`：url/name/auth/headers 可换。`auth.type:none` **只允许本地替身**，不读任何密钥文件；`env` 只读指定环境变量；`pi` 运行时读 auth.path（默认 `~/.pi/agent/auth.json`）的 provider（默认 opencode-go）.key，不复制、不输出。默认真实模型地址/名称按本批约定；除兼容探测外本批未再调用真实模型。请求带固定会话头、完整回传 reasoning_content，不自动重试；关闭 LangSmith/LangChain 外部 tracing。
- `dailyTokenLimit:0` 默认不限；正数为达到上限后拒绝下一次模型调用（单次调用可能跨过上限）。每次用量与调用结果留痕。
- `queue`：本人私聊优先，Router 固定并发 1；`busyMs` 后发一次“在处理”；`inputTimeoutMs` 超时告知，不自动重试；`stopMs` 最大 30000。其他并发/派工审批键仅预留给后两段，红线开关即使设 false 也强制 true。
- `feishu.mode:real` 才读取飞书凭证，来自环境或显式 envFile；本段未连接真实飞书。只认配置的 open_id 和私聊。按钮无 chat_type 时还须能核对为 PA 已发的私聊消息。`feishu.timeoutMs` 是一次操作从鉴权到 REST 响应/下载流结束的绝对上限（不仅是握手或空闲超时）；输入超时/停机取消也传给鉴权、HTTP 与流管线，半成品会清理。SDK HTTP 适配按实例注入，不修改 SDK 全局默认值、不新增依赖。
- `watchdog` 五类阈值和心跳频率都可调。每类分别恢复，恢复一类不解除其他故障；同一故障持续不重复，再犯更新原通知/消息，恢复另报一次。看门狗只读主数据库/心跳，不调模型，自己的去重状态另存。每次通知也有独立超时/取消保护；飞书发送超时视为不确定并记录该轮通知键，不重复发送，不妨碍本机通知、其他故障和恢复。
- 原始用户内容/文件是材料，不是权限配置。模型不能用工具开任务、改文件、执行命令、联网、派 Pi、运行 Loop 动作或改权限。

## 6. 存储、恢复与进程

`dataDir`（默认 `~/.personal-agent-v2/`）新建，完全不打开旧 `~/.personal-agent/`：

- `state.sqlite`：输入队列/去重、当前窗口、任务卡与订阅、发送前账目、事件索引、来源游标、用量、健康机械字段。SQLite WAL + FULL 同步。
- `checkpoints.sqlite`：LangGraph SQLite 检查点。只保留最近 `checkpointKeep` 个已完成输入线程（默认 8），每个线程还有 `maxToolRounds` 上限；未完成线程保留，防止裁掉恢复点。
- `events/YYYY-MM-DD.jsonl`：只追加原始输入、调用材料路径/指纹、模型/提示词版本、简短判断依据/方案、工具与实际结果；不记录密钥、例行心跳或“我还活着”。原话不因窗口淘汰而删除。
- `heartbeat.json`：主进程默认每分钟原子更新；`watchdog-state.json/watchdog-owner.json`：看门狗自己的去重/单实例身份，不改主数据。

无账户/数据库迁移。本批测试全为新建临时库。未来需迁移时先停进程并整体备份该目录（包括 SQLite 的 wal/shm 文件）；恢复也整体还原，不能只拷一个 sqlite 文件。

**发送说不清时不重发**：先记 sending，再发，再记 sent。若恰好在网络发送期间断电/强杀，无法证明飞书是否收到的项标为不确定，日志明确记录；不会为了追求“必送达”造成重复。正常停启和已确认 sent 的回复会去重恢复。外部网络不能提供无限期的严格 exactly-once，不冒充能保证。

**仅生成 launchd 配置**：

```sh
node dist/src/launchd.js --config "$T/config.json" --out "$T/generated-plists"
```

生成 main/watchdog 两个 KeepAlive plist，不覆盖已有同名文件，**不运行 launchctl、不安装、不加载**；PATH 是生成时的非秘密 PATH，不复制任何密钥环境变量。开发/验收不要把 out 指向真实 `~/Library/LaunchAgents`。上线、真实账号和用户业务验收均须另行授权。
