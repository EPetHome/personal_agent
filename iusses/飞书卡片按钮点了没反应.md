# 飞书卡片按钮点了没反应

状态：待处理（2026-10-26 发现）。不在「误报修复」批里，排到下一批。

## 问题与影响

【必须修改】用户在飞书里点复盘卡片的「同意」，没有任何反应，经验也没有被确认。所有卡片按钮（同意、改一下、正确、误报）很可能都一样。按钮是飞书里最主要的反馈方式，按了没用，「回复反馈调整判断」这条链路就断了。

## 事实

- 2026-10-27 02:32（UTC），`~/.personal-agent/data/feishu-inbox.jsonl` 收到了这次点击（`action: agree`），但记下的时间是 `+058790-01-30T23:56:10Z`，也就是公元 58790 年。
- `feishu-receipts.jsonl` 里只有同一时间那条文字消息「漏了 测试」的处理记录，没有这次点击的。点击收到了，但没有被处理。
- 文字消息正常：「漏了 测试」回了「已记下」。

## 因果链

```
卡片回调里的 create_time 单位比毫秒还小（推断是微秒，16 位数字）
→ code/src/channels/feishu/index.ts 只区分「秒」和「毫秒」（< 1e12 当秒，否则当毫秒）
→ 微秒被当成毫秒 → 时间算到 58790 年
→ 后续处理大概率因为时间不合法而跳过或失败 → 按钮没反应
```

（来源：协调方读源码和数据推断；回调里 create_time 的实际单位要开发方用真实样本核实。）

## 分层归因

- 产品实现：时间解析只考虑了秒和毫秒；处理失败时没有留下原因，也没有回复用户。
- 验证：开发和验收只用了构造的卡片回调，构造的时间单位和真实飞书不一样；接真实飞书前，没有用真实回调样本验过。

## 处理方向

1. 时间按位数识别秒、毫秒、微秒；明显不合理的时间改用收到时的时间，并记一条说明。
2. 按钮处理失败时，回复用户一句话说明，不要静默。
3. 用这次真实收到的回调格式（脱敏后）做一个样本，加进验收。
