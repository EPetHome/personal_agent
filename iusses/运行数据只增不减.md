# 运行数据只增不减，按现在的速度约两个月占满剩余磁盘

状态：待排批，排在卡片事情快照批之后（用户 2026-10-27 同意）。2026-10-27 协调方核对真机数据时发现，起因是用户问「会不会陷入无限记录」。

## 问题与影响

【建议】事件日志只追加、没有清理或压缩。会话每变一次就把整份会话记录再写一遍，同时盯的任务越多，涨得越快。系统盘现在只剩约 2 GB，照这个速度大约两个月就会写满；写满后检测和提醒都会停。

## 因果链

```
会话每变一次 ──► 整份会话记录追加进事件日志（D27：原始事实只追加）
                      │  没有保留期限、没有压缩
                      ▼
任务越多、越活跃 ──► 日志越快变大 ──► 系统盘只剩约 2 GB ──► 约两个月写满 ──► 检测停
```

## 分层归因

- 设计：D27 规定原始事实只追加，但没规定保留多久、旧事实怎么压缩。
- 实现：「会话观察到变化」存整份记录，而不是只存变化的部分；写状态失败后不清临时文件。
- 运维：备份只建不清。

## 处理方向（排批时再定）

- 定保留期限：例如原始事件保留 N 天，更早的压缩成当时的状态，删除前先归档。
- 会话变化只记差异，或者限制同一会话的记录频率。
- 启动时清掉残留的临时文件；旧备份保留最近几份。
- 与本批「卡片事情快照」无关：快照每张卡只多存约 1–2 KB，规模跟卡片数走。
