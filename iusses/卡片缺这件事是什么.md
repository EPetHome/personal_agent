# 卡片只说要你做什么，不说这件事是什么

状态：修复中（2026-10-27 排进[提示词-反馈闭环与卡片](../docs/prompt/提示词-反馈闭环与卡片.md)）。同源：根子 A「卡片内容靠规则从对话原文抠」，见本页末。

## 问题与影响

【必须修改】用户反馈：卡片给了「要你干什么」，没给「这件事是什么」，看完不知道是什么事，还得回到会话里翻。卡片的作用是不回会话就能判断要不要管，这一条没做到。

## 事实

2026-10-27 07:11–07:12（UTC）的两张「可能在等你回复」：

```
谁：personal agent 的 Claude Code：合入。
出了什么事：今天凌晨 03:11 答完后留下了一个需要你回复的问题。
要不要你管：只问一件事：同意换成这个修法吗？

谁：loop 的 Claude Code：<ideopenedfile>The user opened the file …（编辑器标签）
出了什么事：今天凌晨 03:12 答完后留下了一个需要你回复的问题。
要不要你管：请回到会话确认下一步。
```

- 「谁」的意图取的是第一条有文字的用户消息。这个会话第一条是截图，第二条是「合入。」，于是意图成了「合入。」。长会话里第一句话往往不是任务本身。
- 「出了什么事」只有一句通用话「答完后留下了一个需要你回复的问题」，没有说问题是关于什么。
- 「要不要你管」里的问题脱离上下文（「这个修法」是哪个修法），第二张找不到问题，只剩兜底的「请回到会话确认下一步」。
- 来源：真机 `outbox.jsonl`。

## 分层归因

- 需求：已拍板的四段（谁、出了什么事、要不要你管、回去看）里没有单独一段写「这件事是什么」，默认靠意图一句话带出，长会话里不成立。
- 产品实现：意图、问题都靠规则从原文里抠，抠不出这件事的来龙去脉。

## 处理方向（待排批时和同源问题一起定）

- 卡片加一句「这件事是什么」：当前在处理的事情和卡在哪里，一句话。
- 排版：每段单独成块，段名醒目（加粗或单独一行），段与段之间留空；每段控制在一两行，长内容收进证据。
- 倾向让模型来写：判断「在不在等你」时模型已经读过上下文，顺带写出「这件事是什么」「要你做什么」各一句，规则只作后备。
