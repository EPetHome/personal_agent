# 飞书卡片的「谁」「要不要你管」取错内容

状态：已修复、已核销（2026-10-27，协调方按真机记录核对：被 `b80df82` 新卡片格式取代；摘要质量另见[卡片这件事是照抄不是摘要](../卡片这件事是照抄不是摘要.md)）。

## 问题与影响

【必须修改】新的四段式卡片里，有两段取到了不该显示的内容，用户读完仍不知道这个会话在做什么、问了自己什么，「一眼看懂、要不要管」的目标没达到（飞书体验批 A10 没过）。

## 事实

2026-10-27 06:10（UTC）的卡片，标题「personal agent 的 Claude Code 可能在等你回复」，正文：

```
谁：personal agent 的 Claude Code：[Image: source: 相关文件
出了什么事：今天凌晨 02:08答完后留下了一个需要你回复的问题。
要不要你管：等你核销：
```

- 「谁」后面是会话的意图原文。这个会话的第一条用户消息只有一张截图，意图原文是 `[Image: source: /private/tmp/.../1.png]`，路径被换成「相关文件」后又被截断，剩下半截占位符。
- 「要不要你管」本应是助手问用户的那句话。助手最后一条回复以「等你核销：」加一个列表结尾，程序只取了冒号那一行，列表全丢了。
- 时间和后面的字之间缺空格（「02:08答完后」），评审时已发现。

## 因果链

```
意图取第一条用户消息原文 → 消息只有图片 → 显示图片占位符
助手的问题取最后一行/最后一句 → 那一行只是列表的引子 → 显示「等你核销：」
```

（来源：协调方看真机发件记录 `outbox.jsonl`。取法是对照现象推断的，还没逐行读源码。）

## 分层归因

- 产品实现：意图没有跳过图片、附件这类占位内容；助手的问题按行截取，没有处理「引子 + 列表」的结构。
- 验证：样本里的意图和问题都是一句完整的话，没有截图开头的会话，也没有以列表结尾的提问。

## 处理方向

1. 「谁」：意图跳过图片、附件占位，取第一句有文字的用户消息；都没有时写「意图不明」，不显示占位符。
2. 「要不要你管」：问题以冒号结尾、后面跟着列表时，把列表压成一行摘要带上（超长可截断，但不能只剩引子）。
3. 时间和后面的字之间加空格。
4. 用这两种真实形态（截图开头、列表结尾）各补一个脱敏样本。
