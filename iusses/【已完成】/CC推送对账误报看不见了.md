## 问题与影响

【必须修改】真机上「Claude Code 的盯防看不见了」从 2026-10-26 09:46（UTC）起一直在报，级别是「现在就要你」，但 CC 其实看得见：是钩子推送和会话文件对账时的两类误报。

不修的后果：一周试用里这条误报会一直挂着，用户只要在会话里 cd，或者打开 CC 马上关掉，就会触发；真的看不见时，用户分不出来。这直接破坏「盯防自己看不见了」这类提醒的可信度（需求书「什么时候叫我」），而且会话一 cd，它的「在等你」推送也对不上，可能漏叫。

## 因果链

```
① CC 来源：会话的项目 = 会话文件第一条记录的 cwd           code/src/sources/cc/index.ts
   钩子推送：项目 = 推送当时的 cwd                          code/src/core/perception.ts（parsePush）
   对账：会话号、项目、文件路径三者都要相同                 code/src/core/sessions.ts（pushMatchesMember）
   → 中途 cd 后项目不同 → 被当成「错项目冲突」，不给宽限     code/src/core/agent.ts（detect）
   → 马上报「看不见了」；这条推送也不参与「在等你」判断

② 打开 CC 没说话就关掉 → CC 不写会话文件，钩子照样推 session_end
   → 宽限两轮后仍找不到文件 → 报「看不见了」
```

（来源：协调方读源码推断，开发方以实际代码为准。）

## 分层归因

- **产品实现**：对账规则把「同一会话换了目录」当成错项目；没有区分「空会话的结束推送」和「推送了但文件丢了」。本批修复的主体。
- **需求与方案**：「推送和定时检测互相对账」（方案「在等我主要看推送…两边互相对账」）没写会话中途换目录、空会话这两种真实情况。样本也都是起始目录不变的会话，所以前几批的测试和验收都没覆盖到。
- **验证**：实装验收（2026-10-26）只验了「停下来等你就叫你」，没有覆盖换目录和空会话；这两种情况是升级后在真机数据里才看到的。

## 处理方向（已写进提示词，待用户过目）

1. 会话号和文件路径都对得上、推送带的目录在这份会话文件里出现过，就算对上了；总览里的项目仍按起始目录显示。
2. 只有「会话结束」推送、宽限后文件仍不存在，才当空会话，不报警也不进总览；「在等你」「一轮结束」推送仍照旧报。
3. 防错项目的保护不放宽，宽限仍是 2 轮。
4. 换上新代码后，已经报出的误报按现有的恢复逻辑结束。
5. Codex、Pi 按同样的规则处理。
