## 事实（协调方只读核对真机，时间 UTC）

- 06:37:39，Codex 钩子报「会话结束」（`~/.personal-agent/inbox/codex.jsonl` 第 82 行），会话 `01a18139…`，目录 IDaaS。
- 对应会话文件存在，22 KB，只有 1 行开头信息（`session_meta`），没有任何对话；读取组件把它当无内容跳过（Codex 来源 `skipped` 7）。
- 程序给推送两轮宽限后，只认「文件仍不存在」为空会话（`code/src/core/agent.ts` 第 206–213 行的 `push_empty` 分支要求文件不存在）；这个文件存在，于是落到「推送与已读取会话对不上」，Codex 整个来源记为异常，06:40:51 发出「看不见了」。

## 因果链

```
打开 Codex 又马上关掉 → 会话文件只有开头一行
  → 读取组件跳过无内容会话
  → 钩子的「会话结束」找不到对应会话
  → 空会话判断只认「文件不存在」，这里文件存在 → 不算空会话
  → 判成对不上 → 整个 Codex 来源标为异常 → 所有 Codex 会话状态不再确认
```

## 分层归因

- 实现：空会话只按「文件不存在」认，漏了「文件在、但只有开头信息」这种更常见的空会话。
- 设计：一条推送对不上就让整个工具看不见，影响面过大；应只影响那一个会话。

## 处理方向（排批时再定）

- 「文件在但没有对话」也按空会话处理，不报异常。
- 单条推送对不上只标那个会话，不把整个来源判成看不见。
