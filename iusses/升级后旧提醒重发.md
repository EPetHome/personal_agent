# 升级后，已提醒过的「在等你」被重发

状态：修复中（2026-10-27 排进[提示词-反馈闭环与卡片](../docs/prompt/提示词-反馈闭环与卡片.md)）。同源：根子 A 的下游，见[卡片缺这件事是什么](卡片缺这件事是什么.md)末尾。

## 问题与影响

【必须修改】每次升级只要改了会话文字的提取方式，所有正被判为「可能在等你回复」的会话都会重新判断一次、再发一条「现在就要你」。这次升级重发了 2 条，其中一条是前一天的旧会话。这类提醒正好是用户最在意吵不吵的那一档，也会多花模型调用额度。

## 事实

- 2026-10-27 06:59（UTC）升级后第一轮检测，新增 2 条「可能在等你回复」：会话 `a6ba159a…`（证据时间 2026-10-26 08:16，03:24 已提醒过一次）、会话 `155d37d6…`（06:47 已提醒过一次）。
- 同一会话、同一证据时间，升级前后模型判断记录的指纹不同（`86cdca20…` → `3ca039be…`），提醒的去重键 `model_waiting:<会话>:<指纹>` 随之变了。
- 来源：真机 `events.jsonl` 的 `model_checked`、`outbox.jsonl`。

## 因果链

```
升级改了意图 / 回复的提取方式
  → 喂给模型的材料变了 → 指纹变了
  → 程序把它当成新情况，重新调模型判断
  → 去重键带着指纹 → 和已发的那条对不上 → 再发一次
```

（来源：协调方看真机记录。「指纹由提取后的文字算出」是对照现象推断的，还没逐行读源码。）

## 分层归因

- 产品实现：「这件事提醒过没有」绑在提取文字的指纹上，而不是绑在事实本身（哪个会话、哪一次停下）。上一批对 loop 交代专门处理过「展示字段不改去重键」，模型判断的「在等你」没有同样处理。
- 验证：测试都从空数据开始，没有「用旧版数据升级到新版后跑一轮」的回归。

## 处理方向

1. 「在等你」按事实去重：同一会话、同一次停下（证据时间）已经提醒过，就不再提醒，不管提取文字怎么变。
2. 同一份证据已经判过，不因提取方式变化重新调模型。
3. 补「旧版数据升级后跑一轮」的回归：不新增提醒、不新增模型调用。
