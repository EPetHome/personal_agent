# 方案：在 IM 里回复 AI 会话（转达）

资料核对：2026-10-28。状态：**第一格已定稿**（2026-10-28），摸底两轮做完；第一格的验收标准以提示词为准，第 6 节是讨论稿。依据：需求书 D33、Q8。

## 目标

用户在飞书里直接回复某个 AI 会话：用户写的原话原样送进那个会话，AI 的回复带回飞书。只做「转达」，不做「代答」（D33）。直接操作会话风险大，所以顺序是：摸清能力边界 → 定护栏 → 一次只开一个工具、一种会话状态。

## 1. 能力边界（摸底两轮，2026-10-28 协调方实测）

做法：在临时目录（personal agent 忽略的路径）建一次性会话，用命令行按会话号续话。CC 用 haiku，Pi 用 `opencode-go/deepseek-v4.1-flash`；没碰任何真实会话。测试期间 personal agent 没有因此发卡片，CC、Pi 来源保持正常。第二轮（同日）补 Codex：用 VSCode 插件自带的 `codex` 0.164，推理强度压到 low，在临时目录建一次性会话，同样没发卡片。

## 2. 由摸底得出的判断

- 送话的路选「命令行按会话号续话」：CC、Pi 已证实可用；托管会话、模拟键盘输入暂不需要。
- **先开哪一格（用户 2026-10-28 定）**：CC × 会话闲着（AI 已停、用户不在电脑前），回复入口先只放「在等你」卡片。理由：CC 自带授权关，续话不越权；这一格正好对应「间隔过后才推飞书」的卡片，即用户离开电脑、用手机回的场景。
- Pi 排第二：先补上授权关（续话时加权限扩展，或只开 loop 托管的 Pi）才开。Codex 排第三：实跑一次后再定。
- 最大的风险不是送不到，是**悄悄分叉丢话**；护栏的头一条就是防它。
- **送达走命令行续话，回电脑后重开 VSCode 再接着聊**（用户 2026-10-28 定）：底层是同一个会话文件，重开后窗口读到最新内容，接着聊不分叉；只要别在没重开的旧窗口里直接打字。「直接送进开着的窗口」（会话间互发消息）暂不测。
- 「忙就不送」能落地（2026-10-28 摸底第二轮）：CC 先看在跑进程登记的 `status`，再核会话文件最后一条记录，两者都是「闲着」才送；读不到就不送。开着窗口的会话也能认出来，送之前就能告诉用户「送进去后窗口里看不到，回电脑先重开」。Codex 自带写锁，并发会明确报错，比 CC 安全；但续话默认只读，排第三不变。

## 3. 护栏（每一道都在「能发」之前就位）

| 护栏 | 防什么 | 来源 |
|---|---|---|
| 只认用户本人的飞书账号（已有） | 别人点按钮、机器人被拉进群 | 已有 |
| 原样转达，一个字不改 | 曲解用户的话 | D33 |
| 发送前预览，用户点确认才发 | 误触、发错会话 | D33 |
| **忙就不送**：会话正在被写（AI 在干活、另一个进程在续、用户在窗口里打字）不送；送前再核一次会话最后一条记录还是卡片当时那条，不是就停下问用户 | 悄悄分叉丢话 | 摸底：并发实测 |
| 卡片过期先问：卡片发出后会话已往下走就先问还送不送；不另设时间限制（用户 2026-10-28 定） | 拿旧问题的答案回新问题 | 用户定 |
| 同一次提交只送一次 | 飞书回调重试导致重复送 | |
| **权限只沿用、不抬高**：CC 沿用原设置；Pi 没有授权关的不开；Codex 禁用跳过确认的开关 | 远程一句话让 AI 不经确认就删东西 | 摸底：权限实测 |
| 红线条目二次确认 | 删除、合入、推到远端、对外发消息、花钱 | D33 |
| 远程替用户点「允许」不做 | 风险最高的一步 | 本阶段不做 |
| 送不到就明说，不悄悄重试 | 一张卡重发 654 次的教训 | 问题单 |
| AI 的回复原样带回飞书；回执提醒「回电脑后重新打开这个会话再接着用，旧窗口里没有这一轮」 | 用户回来在旧窗口接着打字造成分叉 | 旧窗口看不到、重开能看到：实测（2026-10-28）；旧窗口打字会分叉：推断，未测 |
| 每次转达全程留痕（谁、何时、发给哪个会话、原文、结果） | 事后查不清 | |
| 一个总开关，默认关（用户 2026-10-28 定） | 出事立即全停 | 用户定 |

## 4. 卡片交互

```
要你做：1【回复会话】…  建议：是    2【你去做】…    3【要你定·红线】…

[按建议回]  [手动输入]
  ├─ 按建议回 → 预览「将发给 <工具>：…」（红线条目不自动带上）→ [确认发送] [取消]
  └─ 手动输入 → 空白输入框（不预填）→ 用户写的内容完全替换建议 → 预览 → [确认发送] [取消]

发出后卡片变成：「已送到，<时间> 它回了：…」或「没送到：原因」
```

输入框要等送达通道就位才上线；在此之前卡片只放逐件标签和建议，不放发不出去的输入框，免得用户以为已经回了。

## 6. 验收标准（暂定，用户 2026-10-28 认同；A3 已按摸底写实，定稿随方案一起过目）

第一格只做 CC × 会话闲着。自动验收用飞书替身和临时 CC 会话，不碰真实账号和会话；真实飞书由用户验。

| # | 操作 | 预期 |
|---|---|---|
| A1 | 用户离开电脑、会话停着；在飞书卡片上点「按建议回」，确认发送 | 原话一字不差进了那个会话；AI 的回复带回飞书，卡片变「已送到，它回了：…」 |
| A2 | 不用建议，自己输入一句 | 送进去的是用户写的原话，不夹带建议 |
| A3 | 会话正在干活（AI 没回完），或别处也在往这个会话里写；以及读不到会话状态时 | 不送；卡片说明原因；会话里没多出这句、没有分叉 |
| A4 | 卡片发出后会话已往下走 | 先问还送不送，不直接送 |
| A5 | 同一次确认，飞书重复回调 | 会话里只出现一次 |
| A6 | 送进去的话要 AI 删东西 | 权限照旧，该要授权还是要授权；红线事项要用户确认两次 |
| A7 | 送不到（会话不在了、命令出错） | 卡片写「没送到：原因」，不悄悄重试 |
| A8 | 关掉总开关 | 任何卡片都送不出去 |
| A9 | 不是用户本人点的按钮 | 拒绝 |
| A10 | 每次转达 | 都留下记录：时间、发给哪个会话、原文、结果 |
| [人工] 1 | 人在电脑前，用手机飞书回一张卡 | 会话里多出这句，AI 的回复回到飞书；重开 VSCode 能看到这一轮 |
| [人工] 2 | 真离开电脑时用一次 | 同上，回来后没有丢话 |
