# LangGraph 重建 · 乙段：派给 Loop

## 目标

在甲段的骨架上，让 PA 能把活派给 Loop、盯着、做完核实后回报，中途卡住主动带方案来找用户，用户点一下就去处理。关键是点头之后不出错：同一个点头只执行一次，点头过期了不照旧执行，送没送到说不清时不重发。

需求依据（只读）：`/Users/Admin/Desktop/personal agent/docs/requirements/需求书-PA-LangGraph重建.md`，本段对应第四、五、七、八节。落地做法：`/Users/Admin/Desktop/personal agent/docs/prompt/方案-LangGraph重建.md` 第二节。结果续写 `docs/batches/LangGraph重建-20261104/结果.md`。

## 已拍板

1. **worker 接口**：所有 worker 统一七个动作：派、查状态、报进展、问用户、答复、交结果（带证据路径）、停。以后加 worker 只要实现这七个动作，Router 不用改。本段实现接口和 Loop 适配；Pi 适配在丙段。
2. **Loop 适配**：派 = 在授权项目的批次目录写提示词和 `批次.json`，调 `loop 开工`、`loop 启动`（可参考旧代码 `code/src/core/loop-worker.ts` 的做法）；查状态 = `loop 查询 --json`（只读）；答复 = `送话` / `续跑`；停 = `loop 停止`；报、问、交 = 读 Loop 的事件目录（文件一变立即收，另加低频兜底）。授权项目和它的批次目录、`scope.allow / deny` 来自配置；目前只有 personal agent，派活范围只改 `code/`。
3. **合入、推送不执行**：Loop 还没有「执行时核对点头的那个提交」和「推送前扫描密钥」。在那之前，合入、推送工具一律不执行；卡片上这类按钮（包括「仍要合入」）由程序标成「当前不可用，请回电脑操作」，不管模型有没有要求这个按钮。
4. **订阅**：每张任务卡登记订阅（哪个 Loop 批次、PA 为它发过的消息）。Loop 事件到达时按订阅归到那张卡：程序先更新状态和派工记录，再把整张卡附给 Router。用户引用 PA 发过的消息、点卡片按钮，同样按订阅归卡。
5. **核实后才叫用户**：Loop 说「暂停」「需要你决定」「做完」时，程序先查状态核对（做完还要核对分支上有这个提交）；对不上就记「核实不了，没叫你」，不叫醒 Router 发卡。
6. **卡片**：同一件活一张卡，状态变了更新原卡；用户不理或点「回电脑再说」，不催第二遍。找用户必须带方案。三类卡的内容按需求书第四节：做完（分支、提交号、核实结果、要人工验收的项）、没全过（哪层没过、为什么、真问题还是误判、建议；按钮：按建议 · 再给它一轮 · 仍要合入（不可用）· 回电脑再说）、卡住（原因、建议）。
7. **点头**：用 `humanInTheLoopMiddleware` 按配置的开关决定哪些工具先问。先问的工具暂停并发卡片（写明打算怎么做、用户确认的是什么），用户点「好」接着跑、点「不要」取消。暂停状态存在检查点里，重启后照样能点。
8. **执行前重核与只执行一次**：放在 worker 接口这一层，不靠中间件或模型。执行前按派工编号去重（连点两下、飞书回调重发都只执行一次）；再核对卡片上记下的点头依据：状态变了、活已取消、批次已经自己恢复，就不执行，更新原卡说明变化，并把变化交给 Router 重新给建议。
9. **先记再送**：送话、续跑、开工、停先记下再调用；结果说不清时标「不确定」，不重发，告诉用户。
10. **开关**：开关只读配置文件，PA 不写。红线类动作（合入、推送等，需求书第八节）在配置里改成不问也无效，照样问。某类被改成不问后，PA 直接做完要在原卡写明「已直接处理」。用户在飞书说「这类以后直接做」时，Router 只告诉用户去改配置的哪一项（写进系统提示词）。
11. **证据路径**：读 Loop 事件里的证据，同样走甲段的白名单和黑名单；不在允许范围的不读，告诉用户。
12. **取消**：用户说「算了」之类，由 Router 判断针对哪件活并取消；取消后这件活还没执行的点头一律作废。

## 边界

- 只改 `code/agent/` 和本批结果文件。不改旧代码、门禁方法、验收标准、需求和方案、`eval/`、历史样本。不新增运行依赖（需要的话先写「需要你决定」）。
- 测试和自验只用 Loop 替身、假飞书、脚本模型替身；不调用真实的 `bin/loop` 对真实项目开工、启动、送话、停止、合入、推送；不连真实飞书；不调真实模型。
- 不读、不改真实的 PA 数据目录和附件目录；不改 `~/.pi/agent/`；不提交、不合入、不推送。
- 判断交给模型，硬规则（只执行一次、执行前重核、合入推送不可用、红线照样问、读的范围）由程序强制。
- 遇到需求书没覆盖的细节按最保守的做法定，写进结果，不停下问；只有需要新依赖时才停下。

## 验收标准

本段自己的验收只用替身（脚本模型替身、假飞书、Loop 替身），不花钱。整批验收在三段做完后另跑。

A1. 操作：让脚本模型替身在收到「帮我在测试项目里把 README 标题改成 Hello」后请求开活并派给 Loop
    预期：假飞书收到一张卡片，写明派给 Loop、改 README，带「好」「不要」；点「好」之前 Loop 替身没收到开工
A2. 操作：A1 的卡片连点两次「好」，并让假飞书把这次回调重发一次
    预期：Loop 替身只收到一次开工
A3. 操作：Loop 替身对这批发「做完」事件（带分支、提交、证据，各项都通过），查状态和分支上的提交都对得上
    预期：这张任务卡由程序更新为「做完」；假飞书收到做完回报；卡上的合入、推送按钮标为「当前不可用，请回电脑操作」
A4. 操作：Loop 替身对另一批发「暂停」事件，查状态也显示暂停；脚本模型替身建议续跑
    预期：Router 被叫醒时上下文里带着那张任务卡全文；假飞书收到建议续跑的卡片；点「好」后 Loop 替身只收到一次续跑
A5. 操作：A4 那类卡片发出后、点「好」之前，Loop 替身对该批发「恢复」事件；然后点「好」
    预期：Loop 替身没有收到续跑；原卡更新为「批次已自己恢复」
A6. 操作：Loop 替身发「暂停」事件，但查状态显示该批仍在正常运行
    预期：没有卡片，模型替身没被调用；事件日志记下「核实不了，没叫你」
A7. 操作：Loop 替身发「做完」事件，评审结论里还有 2 条必修没清；脚本模型替身发一张带「仍要合入」按钮的卡
    预期：卡片上「仍要合入」标为当前不可用；「再给它一轮」可以点，点了 Loop 替身收到一次续跑
A8. 操作：Loop 替身发一条事件，证据路径指向白名单外的构造文件；脚本模型替身请求读这个证据
    预期：读取工具返回不在允许范围；事件日志里没有这个文件的读取记录
A9. 操作：A1 那类卡片待确认时，以本人身份发「刚才那个算了」，脚本模型替身请求取消这件活；然后点那张卡的「好」
    预期：任务卡变为「已取消」；Loop 替身没收到开工
A10. 操作：A1 那类卡片待确认时正常停止并重启 PA，再点「好」
    预期：Loop 替身收到一次开工，只一次
