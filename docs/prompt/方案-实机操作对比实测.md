# 方案：实机操作工具对比实测（草稿）

资料核对：2026-10-26。状态：**要点已定（用户 2026-10-26 同意按方案执行，改由 Codex 跑），待 Codex 执行**。需求依据：[需求书](../requirements/需求书-personal-agent.md) D30；调研依据：[调研-AI实机操作工具](../../wiki/raw/调研-AI实机操作工具-20261026.md)。

## 目的

在 Cua Driver 和 Peekaboo 之间选一个，作为实机操作的「操作与留证据」层（D30 ①）。调研只读了文档，这次在本机按同一套任务各跑一遍，看实际表现。

只测工具本身：每一步由写好的脚本发出固定命令，不让模型规划，所以测的是工具，不是模型能力。护栏和结果核对（D30 ②③）这次不实现，只看工具能不能给它们提供需要的东西。

## 任务与检查

一共 5 项，每项两个工具各跑一次。所有文件都放在临时目录 `~/.personal-agent-spike/<工具名>/`。

| # | 任务 | 怎么算过（由程序检查，不看工具自己报的结果） |
|---|---|---|
| T1 | 用「文本编辑」新建文档，输入一段编的文字，存成纯文本，存到指定路径 | 文件存在，内容和输入一字不差 |
| T2 | 用「预览」打开一张编的 PNG，导出成 JPEG，存到指定路径 | 文件存在；`file` 识别为 JPEG；`sips` 读出的宽高和原图一致 |
| T3 | 点击前先认按钮：在「文本编辑」里关掉一个未保存的文档，弹出「删除 / 取消 / 存储」对话框后，**先不点**，只让工具报出它要点的那个按钮叫什么、是什么类型，然后点「取消」 | 点击前拿得到按钮的名称和类型，而且是机器可读的格式；拿到的名称和实际按钮一致；点了「取消」以后文档还在 |
| T4 | 超时急停：让工具等一个永远不会出现的按钮，限时 10 秒；另外在一个动作执行到一半时从外部把它停掉 | 20 秒内返回，并且明确报的是超时；结束后 `pgrep` 查不到它留下的进程；之后的操作不受影响 |
| T5 | 留证据：T1–T4 每一步的记录 | 每一步都有：动作、目标、时间、动作前后的窗口截图、动作后读回的界面状态，而且是程序能解析的格式；缺了的地方有明确标记；截图里只有被操作的窗口 |

另外记三项观察，不判过或不过：从命令行调用、不需要人交互是否顺手（Pi 会这样调）；装了哪些东西，卸载干不干净；中文界面下按钮名称读得对不对。

## 怎么定

T3、T4 最重要。前者决定护栏有没有可能在点击前拦住危险按钮，后者正是这次 loop 验收卡住 32 分钟的问题。两个工具都过，就看 T5 的证据哪个更容易做程序核对；两个都不过，就说明这一层也要自己补，回来重新讨论。
