# 提示词：渠道与常驻（闭环 1 第三批 · 段 2）

## 目标

段 1 已经给 personal agent 加上推送钩子、模型判断、本机渠道和反馈命令，并定好了统一的渠道接口（发带内部编号的提醒、收回复）。本段让它真正能用起来：

1. **飞书渠道**：照同一个渠道接口接飞书机器人私聊，提醒以卡片发出，用户可以点按钮或引用回复来反馈。
2. **常驻**：做成 macOS 登录即启动的后台程序，定时检测、读推送、收飞书回复；崩了自动拉起。
3. **每周小结与经验集**：每周五推一份小结（反馈统计加复盘），并把出过的问题收集成经验集，同类问题第二次出现时标出来。

本段在段 1 的提交上开工，先读 `code/使用说明.md` 和段 1 写在本批结果里的内容。

## 已拍板

- **飞书**：企业自建应用机器人，和用户私聊；收消息、收按钮回调都走长连接（Node SDK 1.24.0 以上，事件处理器 3 秒内返回，耗时的事放到后面做）。提醒卡片按方案第 5 节的格式：标题、一句话、回去看的命令、「正确 / 误报」按钮，证据折叠在后面。引用某条提醒回复，就按编号对上那条提醒；直接发「漏了 + 一句话」记为漏报。卡片和回复里都不出现内部编号。
- **发到哪**按方案第 7 节：「现在就要你」发本机通知加飞书；「有空看」只发飞书。同一件事没有新证据，不重复发。
- **凭证**：飞书 App ID 和 Secret 只从已忽略的 `.env` 或环境变量读，不写进代码、配置样例、日志和提交。
- **允许一个第三方运行依赖**：飞书官方 Node SDK。门禁里「禁止第三方运行依赖」的检查相应改成只允许这一个。
- **常驻**：macOS launchd 用户级，登录即启动，崩了自动拉起；每分钟检测一轮（可配置）。短时间内反复重启时，发一条飞书消息并附日志路径。安装和卸载命令的目标目录必须能用参数指定；卸载后目标目录恢复原样。
- **每周小结**：每周五 18:00（本机时间）发一份「有空看」小结。反馈统计按「工具 × 提醒类型」分格，从发件记录和反馈记录现算，不另存：准确率 = 正确 ÷（正确 + 误报）、「漏了」条数、回应率、每天叫几次；没回应的不算正确；某格不足 20 条只显示数字、不下结论。用户随时可以用命令要一份统计。
- **经验集**按方案第 10 节：问题记录来自被判「正确」的提醒、「误报」「漏了」、loop 到返修上限或返修两次以上；归因分四层，加「归因未定」，由模型起草，状态是「待确认」；同类比对先用规则（类型 + 归因层 + 工具或项目），拿不准再问模型「是同一类问题吗」，只答是或否。定过对策又出现的、同类第二次出现的，当场单独发一条「有空看」；新问题攒到周五复盘。复盘按「有对策却又出现的 > 反复出现的 > 新的」排序，每条配「同意 / 改一下」按钮。经验按 D27 的四种状态管理，可以导出成 Markdown；不自动执行对策，不改任何项目的规则文件。
- 数据都在配置的数据目录里，不进仓库（D26）。

## 验收标准

A1. 操作：配置假飞书，放入一条会产生「现在就要你」提醒的编的推送事件，跑一轮检测
    预期：假飞书的发出记录里多一张卡片，标题、一句话、回去看的命令和发件记录一致，带「正确 / 误报」按钮；本机通知的测试替身也收到一次调用
A2. 操作：放入一份会产生「停滞」提醒的编的会话样本，跑一轮检测
    预期：假飞书多一张卡片；本机通知的测试替身没有被调用
A3. 操作：向假飞书注入一次 A1 那张卡片上「误报」按钮的回调
    预期：`feedback.jsonl` 多一条指向那条提醒的「误报」记录；假飞书回一条「已记下」
A4. 操作：向假飞书注入一条私聊文字「漏了 loop 暂停没叫我」
    预期：`feedback.jsonl` 多一条「漏了」记录，带这句话
A5. 操作：把常驻服务装进一个临时目录，检查生成的配置，再执行卸载
    预期：装好后有一份登录即启动、崩了自动拉起的 launchd 配置，指向本程序；卸载后临时目录恢复原样
A6. 操作：在前台启动常驻程序，往推送目录追加一条编的 `waiting_permission` 事件
    预期：2 分钟内发件记录多一条「在等你」提醒，假飞书也多一张卡片
A7. 操作：让常驻程序在短时间内连续崩溃几次
    预期：假飞书多一条消息，说明反复重启，并附日志路径
A8. 操作：准备一周的编的发件和反馈记录，以本周五 18:00 为当前时间跑一轮
    预期：假飞书多一份小结，按「工具 × 提醒类型」列出准确率、漏报、回应率和每天叫几次；不足 20 条的格只显示数字
A9. 操作：放入两份编的同类问题记录，前后相隔几天，第一次已经定了对策，以周五 18:00 跑一轮
    预期：小结的「复盘」一栏把这条标为第 2 次，附上一次的日期和对策，排在新问题前面
A10. 操作：在 `.env` 里放一对编的飞书 App ID 和 Secret，跑完 A1 后，在仓库里已跟踪的文件、数据目录和本轮日志里搜索这两个值
    预期：一处都找不到
