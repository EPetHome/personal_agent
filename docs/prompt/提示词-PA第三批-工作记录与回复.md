# PA 第三批：甲·工作记录与回复

## 目标

完成本方案中的工作归属/执行关联、一次性与持续关注、独立 Pi 的 PA 接收侧、本地办公检索，以及旧上下文冒充现状/无关催办修复。五项范围中除 Pi 导出生产者外的共同链路由本任务统一负责，不能只修回复就称整项完成。

阅读顺序：本提示词 → [本批方案](方案-PA分批推进.md)第三、四、六节 → [统一验收](../batches/PA第三批工作跟踪-20261108/整批验收标准.md) → 对应原单和必要源码。只在 Loop 为本任务登记的独立工作区工作，不改项目根、其他任务空间或正式运行目录。

本批已确认的是方案范围，不包含合入、推送、部署、真实 Pi 扩展安装/重载、读取真实会话或新增项目权限。A1/A2/A5 待真实用户另行授权；开发自检只用构造材料、本地模型/渠道替身，不读取凭据文件或试调真实业务模型。程序测试和语义效果分开报告。

保留原 auto/yolo 和明确 deny；read/edit/write/bash 足以完成本任务，不恢复 codex-pi，不安装无关扩展或升级依赖。依赖/准备沿项目 preparation 与既有 lockfile；Loop 测试节点已提供隔离工作区，不在固定测试命令内再创建副本或复制整仓。

原需求：[事项分层与渐进式感知](../../issues/【req】PA事项分层与渐进式感知.md)；原 bug：[明确任务仍重复确认和催办](../../issues/【bug】明确任务仍重复确认和催办.md)。需求的第 1—11 节已恢复；本批范围以方案为准，不将所有候选设计一并实施。

## 已拍板

- 派单是真实任务单元；小事直接处理，多事项才按项目组织。复用现有 TaskCard/Store/WorkerJournal，不造平行任务账。业务归组不扩大资源权限。
- PA 自派与本人独立工作保留不同来源；同一事项可有多次执行，按可靠身份关联，不按同名/同目录并账，不重启独立工作来纳管。
- 现有模型理解查询/一次性/持续关注及混合指令，程序核对真实本人来源、权限、身份、重复和撤销。已明确内容不重复确认；缺项只问缺项，不靠关键词或时长分类，不加独立分类 Agent。
- 关注只覆盖已接入 Loop/Pi 工作来源。暂停或到期停止接收该规则下新工作；未撤销的一次性委托仍回收结果并明确回执。关注不授予提醒、执行或新权限。
- 独立 Pi 首版只读，消费方案第四节固定的版本 1 记录。未接通/部分/失败不能推成无任务；运行停稳不是业务交付。通知 10 秒内开始核对、60 秒兜底、健康来源漏通知 90 秒内补登；导出租约连续三个 30 秒间隔未刷新时标未核实，不判业务失败。
- 办公/检索只用已有授权本地材料；即时查问不建派单，跨轮交付关联原事项和依据，不要求 Git/代码评审。保存沿原 TXT/图片能力，不接公网/外部账号。
- 原话窗口不摘要、不压缩；历史结论不冒充本轮事实。reply 与直接最终文字必须同一处理入口；声明为事项的片段核对真实来源/新鲜度/覆盖/通知条件。不带 taskId 不能绕开程序约束。直接最终文字最多补正一次仍无合法回复时，简短说明未完成，不原文兜底。普通文字语义正确性不能以元数据校验冒充通过。

## 边界

本任务负责 PA 共用 src、相关配置样例和测试的精确卡 scope；乙只新增 Pi 导出脚本/测试，不互相修改工作区或等待未交付源码。对接使用方案唯一记录约定，接收侧独立校验；不得扫描全机会话、以记录中路径扩权或控制独立 Pi。

保留已派出卡、停止回调、Loop 无事件检测、确认/去重、产出保护。保留所有旧 ID、确认、消息、执行与未决占用；迁移前后用构造旧库核对，失败保留原数据与恢复路径，不清库、不重派。本批新来源撤销后停止读取与披露；完整动态授权/长期记忆/token 改造/发布能力仍排除。

新增程序回归集中于 `test/work-tracking.test.ts`、`test/attention.test.ts`、`test/reply-facts.test.ts`；复用既有 task-discovery/core/worker/dispatch-card/pi/outputs 等受影响测试。测试命令由卡维护，不跑旧全量 gate。不得改卡、提示词、标准、权威需求、项目规则或本机配置。

使用说明只修改本任务新增的工作/关注/回复与 PA 接收章节；唯一开发结果为 `docs/batches/PA第三批工作跟踪-20261108/结果.md` 的“甲：工作记录与回复”节，不改乙或协调方段。结果分别写源码、自检、Loop 检查、装配及未验证语义，不把测试替身当真实业务通过。
