# 方案：PA 分批推进

状态：2026-11-07（纽约），用户要求“继续，给我 Loop，用最新的 Loop”，并指出串行、发布后果、验收归属和批次过大的问题。本版据最新本机第 3 步能力调整，正式首批已进入准备；未启动 Pi，未开发、合入、推送或部署。

优先级仍为 P0 3 项、P1 4 项、P2 3 项；清单只在[排期入口](../baseline/尚未完成与后续顺序.md#推荐优先级11-07重排)维护。主需求与各工单的完成边界保留，本方案不重新定义等级。

## 一、恢复并行，按真实依赖分批

新版 Loop 支持同批多任务并行：每项独立开发空间、会话、静态评审和测试，完成后汇入批次，再由独立验收方统一验收；失败只返回责任任务。不是旧 steps 流水线，也不是所有工作塞进一个会话。

| 安排 | 内容 | 关系及完成边界 |
|---|---|---|
| 现在：PA基础适配与排版-20261107 | 任务基础（P0：身份、兼容迁移、新版 Loop 适配）与飞书排版（P1）并行 | 两个明确代码范围，排版不再等 token/日志。先做基础，不混入已派出卡、持续关注或独立 Pi |

## 二、首批职责

**任务基础**复用 SQLite、TaskCard、WorkerJournal、来源关联与原消息记录，保存真实任务和执行身份；适配新卡 `version:1`、查询 `kernel:1` 及第 3 步多任务事实。新派工先支持单任务卡，查询/停止区分整批与子任务。旧记录只在真实身份可核对时关联，旧命令不套新卡。保留已绑定执行的普通状态更新；全来源自动发现、补查、无事件异常检测和渐进上下文另做。

**飞书排版**只动普通回复出口、必要的小转换函数和专用测试，不动 Loop/存储/权限。有限转换优先复用纯文本通道，保留正文和字面符号，不建设完整 Markdown 系统。两个任务源码范围互斥；共享唯一结果文件分节填写，集成冲突由 Loop 保留现场处理，不手动搬未完成代码。

## 三、验证与尚未拍板的时限

本卡 flow 为“开发评审 → 测试 → 验收”。Pi 在各自工作区自检；Loop 独立静态评审；测试节点运行卡上定向命令；两项到齐后独立验收方在汇总树按 A1—A9 检查实际行为和证据；A10 由本人在以后获准部署后体验。不会把开发自述或测试全绿代替独立验收，也不把构造结果冒充真实模型语义和业务通过。

此前建议的“变化后 10 秒开始核对、60 秒补查、90 秒补登、两次核对失败告警”**未被本次继续执行自动批准**，已从首批标准排除。无事件检测方案需明确判定依据与时限后再写正式后续卡。已派出卡的 10 秒发送目标也留其独立任务确认，本批没有暗含该能力。

## 四、最新 Loop 与发布边界

本轮读取本机 `/Users/Admin/Desktop/loop`：发布提交 `5f23127`，第 3 步已支持多任务/统一验收。该目录另有 `loop.ts/merge-queue.ts` 的未提交旧队列修补，原样保留；实际命令使用这份当前工作区，不称完全等于发布提交的干净版本，不回滚或更新他人改动。

旧 PA 配置被 Git 跟踪，新卡要求 `.autoreview.json` 在开工基线中未跟踪。**准备分支从当前 dev 派生，在准备分支移除配置跟踪、添加忽略，并提交本批必要文档；本地 dev/main 都不为准备而前进。** 原配置先备份，运行正式 PA 的配置/进程不改。本机项目配置仅调整本批来源与验收方法，保留模型选择、auto、deny 和旧历史配置；任务从准备分支冻结基线启动，目标仍 dev。

卡上不含“提交”，表示不会自动合入/推送。**以后显式 `loop 合入` 同样会合入 dev 并推送公开 origin/dev，没有本地合入开关。** 本轮没有发布授权；届时须明确取得“合入并推送”的决定，不把单独“合入”静默解释成新增远端授权，也不手工 Git 合并绕过。准备提交中的配置取消跟踪和文档会随第一次正式发布到远端；本机配置文件不随候选上传。

Pi 开发模型沿项目选择 `openai-codex/gpt-6.1-sol`、max，静态评审 `openai-codex/gpt-6-astra`、xhigh，验收 `opencode-go/deepseek-v4.1-flash`。实际型号/路径及权限门禁检查见本批结果。用户自行启动，协调方不代启动。
