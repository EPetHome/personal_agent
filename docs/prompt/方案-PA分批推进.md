# 方案：PA 分批推进

状态：2026-11-07（纽约）。首批任务基础与飞书排版已发布；用户确认“可以。给我 loop 吧，并行的”，并确认时限与 other 标识。本轮准备四任务并行卡，用户自行启动；没有授权自动发布。优先级唯一入口仍为[排期](../baseline/尚未完成与后续顺序.md)。

## 一、本批安排

批次：[PA跟进并行-20261107](../batches/PA跟进并行-20261107/批次.json)。共同基线为已发布本地 dev；准备提交只带必要材料，不改产品代码。四项同时开始，各自独立工作区、Pi 会话、评审与定向测试，汇入后统一独立验收。测试/验收沿 Loop 本机共享槽排队，不把开发并行解释成所有测试同时抢资源。

| 任务 | 交付内容 | 主要职责 |
|---|---|---|
| [已派出卡](提示词-PA跟进并行-已派出卡.md) | 派出回执、原身份停止及回调保护 | cards、worker 派出回执/callback、journal |
| [无事件检测](提示词-PA跟进并行-无事件检测.md) | 独立核对已托管执行；异常去重、恢复 | loop-monitor、App 生命周期；复用 Workers.status |
| [渐进感知](提示词-PA跟进并行-渐进感知.md) | 新 Loop 发现/补查，摘要、分页与按需详情 | intake/store/router、Loop 查询、worker track/ingest |
| [产出文件](提示词-PA跟进并行-产出文件.md) | DOCX 转 TXT、图片保存、项目/other、启用准备 | 文件策略、Pi 写工具/派工、配置样例与产出准备 |

每项基于已发布接口独立实现和验证，不等待其他任务未来接口、不搬其他工作区未完成代码。共用文件只改本任务职责：worker 的回执/callback 归已派出卡，track/ingest 归渐进感知；App 的观察器生命周期归无事件检测，Intake 接线归渐进感知；types 的任务/来源字段归渐进感知，产出字段归产出文件；prompt/capabilities/使用说明只改各自能力段。不得整份重写共享文件。真实集成冲突由 Loop 返回责任任务，不手工合并候选或吸入其他任务整份贡献。

## 二、体验与完成边界

时限和 other 标识以[主需求](../requirements/需求书-PA-LangGraph重建.md)本轮确认段为准，并落实到[统一标准](../batches/PA跟进并行-20261107/整批验收标准.md)。回执从原派工取得可核对接收事实算起；健康通道下完成发送。未知、超时或送达不确定据实留痕，不为凑时限重派/重发。停止按钮是本人对卡上原执行的明确停止指令，程序核对本人、原消息和执行身份，不多问同一停止；不改变全局 approval.stop 或普通聊天停止规则。

异常检测只查已托管原执行，不凭静默时长、进程名、单个 PID 判失败。连续两次查询失败只报告“状态待核实”；正常长任务、排队/等本人不误报。明确退出/失败按可信来源说明，执行结束不等于业务完成。恢复更新原通知，不自动重启/续跑/停止/重派，不解除未核实操作占用。

渐进感知首版覆盖当前 version:1 开发卡及 kernel:1 正式记录（单/多任务卡），包括 PA 自派与本人独立开启的获准任务。先按可信仓库身份定位约定运行索引，再读必要记录；不扫全局会话正文。未登记 Loop 单会话、未知协议、独立 Pi 明示覆盖缺口；旧 v1 维持原兼容。恢复只接当前活动/待决定任务，历史结束记录按需读，不集中推旧提醒。查询不等于建立永久关注；长期关注管理、独立 Pi、非开发新来源、动态授权、长期记忆仍后续，不关闭整张事项分层单。

产出继续沿原委托/红线规则。loop、Promate、IDaaS 的读与产出写按已定范围准备，不能因此派 Loop 改它们代码。开发方交付配置/启用办法并在构造项目验证；真实登记、修改项目 .gitignore 和正式重载留以后获准部署，由协调方执行，不交用户手改。

## 三、检查与发布

开发/测试/验收只用构造或脱敏资料、隔离 Git/Loop 记录、本地模型/飞书替身及本批创建的子进程。允许这些沙盒内的应用/接口检查，不读真实会话、不接真实账号、不调真实业务模型、不终止正式 Loop 或启停 PA。协调方本轮仅准备，不把准备预检说成产品通过。

按当前开发卡显式“测试”节点执行；旧 gate 停用，不调用旧全仓 gate 或 code/agent/check.sh。固定命令先将当前候选归档到临时目录、普通复制已有依赖，再做类型检查/构建/定向测试，避免污染受检工作区。缺依赖沿 lockfile 安装一次，不升级或反复装。无新改动/失败不重复全仓验证。

保留旧任务、操作、确认、消息、游标与检查点；兼容追加优先。确需迁移须在构造旧库验证并交付备份/整库恢复办法，不清空正式库、不用重派掩盖兼容失败。

流程只到开发评审 → 测试 → 验收，不含提交/部署节点；Loop 负责候选提交，Pi 不手工提交/合并/推送。以后授权发布用正式 Loop 入口，仅本地须 --仅本地；缺省合入仍会推送。当前不开放 PA 真实派 Loop。
