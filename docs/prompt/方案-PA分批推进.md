## 三、本轮范围：五项怎样落地

### 1. 工作归属、派单与执行关联

保留现有派单作为真实任务单元，不新增平行任务账。一次性小事可留在个人事项；需要组织多项独立交付时关联业务项目。业务项目可以引用一个或多个既有授权资源，但项目名称、归组、规模都不产生访问权限。首版只做项目/个人事项加派单，不预建任意层级管理树。

每件事保留稳定 taskId；实际执行以来源类型、来源实例/会话、执行回合和版本定位。PA 自派、本人独立开启分别标明来源。同一件事再次执行保留原 taskId 和新的执行引用；无关工作不因同一 Pi 会话或同名标题而自动合并。仅根据明确引用、受管绑定或本人纠正建立关系，无法证明时标“归属待确认”。

复用已有任务、操作、来源关联与事件记录，增加必要索引/字段；具体表布局由开发方决定。旧 subscriptions 继续作为精确来源关联，不能自动变成永久关注。项目汇总从关联事项及来源覆盖取得，单个执行退出不等于项目完成。

### 2. 一次性任务与持续关注

由现有 PA 模型结合本人消息和相关对象理解，不增加分类 Agent，也不靠“盯、持续、关注”等关键词或时长划分。

| 本人要什么 | 保存什么 | 结束或暂停的含义 |
|---|---|---|
| 查一次当前情况 | 查询和依据；不新建派单或关注规则 | 回答结束 |
| 盯着这一次工作直到交付 | 一次性跟踪，关联原工作 | 原委托终点得到核实并回报后结束；其他业务欠项单列 |
| 继续看以后新发生的工作 | 持久关注规则，明确来源/范围、起点、期限或终止条件、提醒约定 | 暂停/到期后不再接收该规则下的新工作，不等于停止外部执行 |
| 先完成一件事，以后继续看变化 | 一张派单加一条关注规则，各自绑定同一条本人指令 | 派单交付不结束持续关注 |

确实缺少会改变责任的信息才问一次；已有指令、引用或有效规则可确定时直接沿用。规则保存、来源实际就绪、提醒和执行分别记录；保存成功但来源未接通，只回“已保存、尚未接通”。本人纠正时更新原规则并保留来源，不重复创建相似规则。

首版关注对象只覆盖已接入的 Loop 与本批独立 Pi 工作记录，不实现公网主题监测或任意周期执行。期限按实际配置的本人时区解释并回显，含糊时补问，不固化开发机器时区。关注不新增写文件、送话、停止、派工或发布权限。

建议的暂停默认：停止该关注规则发现新工作；已经接受的本人一次性委托仍沿原终点回收结果，并在暂停回执中说清楚。若本人要求停止某项执行或撤权，按相应动作处理，不能把暂停关注冒充这些动作。完整动态授权入口仍归 P1；本轮新增记录及读取必须复用现有权限检查，不能把基本校验后置。

### 3. 独立 Pi：只读观察与按需了解

推荐用 Pi 已有扩展事件导出限定范围的记录，由 PA 消费；不扫全机 Pi 历史、不把所有工作改成从 PA 启动。导出扩展在项目代码内交付，真实安装/加载留到明确批准的部署步骤，不改全局 auto/yolo、原 Pi 权限或启动方式。

**首次接入需明确两种范围**：哪些来源可以导出运行信号，以及哪些任务文字/结果引用允许 PA 读取。原项目目录可读不自动等于允许导出会话。默认只导出选定来源的运行元数据；目标/结果按需提供获准的当次内容或文件引用，不复制整段聊天、模型思考、工具全文、附件或环境变量。没有获准业务内容时先交付“运行观察”，保持目标/完成状态未知。

项目归属优先用可信的已登记仓库共用身份；非 Git 目录用已登记资源身份和规范路径，不按目录名猜。已获准接收但暂未归属的信号可以显示“待归属”；这不允许 PA 读取其工作目录。未经来源授权的记录连标题/计数也不泄露。

已运行但未加载扩展的 Pi 不能被称为已接通：部署方仅在本人允许的安全边界加载并核对原 session ID；不能重新启动业务或复制旧会话来假装续接。是否能在活动会话无损加载须在构造环境验证；不能安全接入时保留“原会话未接通”，由获准部署方处理，不要求本人每次转发日志。

状态明确分成：正在处理、等待交互、本轮停稳、会话退出、来源未核实；业务交付另看原目标、结果和证据。agent_end 之后还可能继续，不能据它报完成；agent_settled 也只证明本轮停稳。会话切换、分叉、恢复和多次独立工作均保留对应身份。

本批不给独立 Pi 新增停止、送话、续跑或重派能力。PA 退出观察不结束外部 Pi；来源失联只报告最后可靠事实和未核实原因。

**接收时限建议**：通知后 10 秒内开始核对，复用现有 60 秒有界兜底；健康来源漏通知的新工作 90 秒内补登。导出端默认每 30 秒刷新运行租约；连续三个间隔未刷新标“来源未核实”，不能判业务失败或结束进程。上述数值为待确认目标，不能当成现有实测。

### 4. 办公与搜索首版

推荐先完整支持**已授权本地材料**，复用文件工具、现有只读 Pi 与受限产出工具：

- 即时查询：在获准资料中查信息，回答并保留依据，不为每次读取建派单。
- 跨轮办公：把选定会议材料整理成纪要或比较结论，使用一张派单关联多次执行、文本结果和材料引用，不要求 Git/评审/提交号。
- 保存材料：沿现有 DOCX 转 TXT、图片保存能力办理；此次不借“办公”扩大为任意文档格式生成或通用命令写文件。
- 本地检索：跨选定资料查找、比较、追问来源，沿已有读取能力；公网搜索、云盘/邮箱连接和周期抓取均不在首版。

没有项目归属的小事可先组织为个人事项，但读写仍须落在既有授权资源内；保存产物需要实际目标时再补必要归属。材料中的要求不是本人委托，生成草稿不代表对外发送。

来源覆盖分别报告：某办公项目的本地材料可读，不代表该目录有 Loop 仓库；未配置或不适用的 Loop 来源不能拖垮办公任务，更不能被解释成“没有任何工作”。

### 5. 修复旧对话冒充现状与无关催办

保留原话窗口，不做摘要或压缩，也不删除旧待办来取得安静。模型每轮看到的历史、当前输入、最新权限、已核实事实和未知覆盖必须分清；历史里的模型结论不自动获得本轮实时依据。

调整现有回复入口，普通 reply 和模型直接返回的最终文字必须经过同一处处理。涉及事项状态/催办/交付的回复带原事项或获准源引用、查询版本/核实时间与覆盖；程序核对引用属于本轮可用事实、当前授权仍有效、通知条件未被取消。缺依据时取得必要查询或明确未知，不能让“不填 taskId”的普通文本绕开已有 quietTask 限制。

直接最终文字不再作为未经核对的发信兜底：要求沿原回合补成合法 reply，最多补正一次；仍无法形成合法回复时给出简短的未完成说明，保留原事项。普通问答可以不引用任务；程序只保证声明为事项事实/催办的片段及最终出口不能跳过核对，普通文字是否夹带了未声明的任务断言仍属模型语义检查，不能假称元数据校验能识别一切自然语言。

建议将任务状态、全局数量和待决定请求做成有依据的回复片段，事实由工具结果提供，模型负责解释和组织。普通问答仍可自由表达；不新增一个模型作全量审稿，不做靠固定词删除句子的过滤器。目的字段/引用齐全也不等于模型语义一定正确，这部分必须用不预设答案的模型场景检查。

无关问候/闲聊只回答当前输入。本人重新问起原事项可以查询并回答；真实新变化符合原通知规则时仍可提醒，不能用一刀切禁提醒破坏结果回报。项目/来源只查了一部分、查询失败或未接通时，只说明已覆盖范围，不能把任务表为空或旧回复的“0 个”写成全局现在没有工作。

## 四、两个并行任务的职责与最小对接记录

| 任务 | 负责结果 | 主要改动范围 |
|---|---|---|
| **甲：工作记录与回复** | 工作归属/执行关联、关注规则、独立 Pi 的 PA 接收侧、本地办公与检索贯通、旧事实/催办 bug | PA 的 types/store、task-context、router/prompt/capabilities、worker 关联处、intake/App 的接入；来源读取/配置校验及受影响测试 |
| **乙：Pi观察导出** | 可选择加载的 Pi 观察扩展、导出范围校验、安装/停用/恢复办法、构造来源测试 | 优先使用现有 code/agent/scripts 目录交付扩展及准备工具；不修改 PA 共用任务/消息代码，也不修改 Pi 安装包或 Loop 仓库 |

甲是共用行为的唯一负责方，避免多任务同时重写 router/worker/任务字段。乙与甲只交换文件记录，不依赖对方未交付的代码；任务提示词形成时再按实际文件确定精确 scope。每个任务可以在独立构造数据上完成自身检查；整批必须验证乙真实导出的记录能被甲消费，不能仅用两边各自编的不同样例代替。

记录只需覆盖：协议版本、已登记来源身份、session ID、实例代次、稳定执行回合 ID、来源版本、发生时间、运行状态、租约时间；获准时附目标/结果/产物引用及其内容版本。字段名由开发方统一落实，不在方案里另建一套完整协议平台。

导出采用完整写入后原子替换；每实例独立记录，重启/切换产生新代次。PA 只从批准的导出根读规定大小/类型的记录，核对路径、所有者、来源登记和可读范围；普通文件自报路径/项目名不能扩权。来源变更去重、派单更新与消费位置一致提交，半写/保存失败不推进成功游标。终态及停用区间保留，恢复只补当前事实，不补发整段历史通知。

乙可在沙盒先用固定导出协议做完，不等甲运行；甲可用构造同协议来源实现接收。开发过程中协议需变时，两边同步同一版本并重验受影响部分，不能分别宣布兼容。

### 并行对接约定（准备时固定，不新增业务范围）

双方使用版本 1 的 JSON 记录，不互相导入源码。乙写记录，甲独立校验；完整格式及安全约束在本段唯一维护。导出根由明确本机配置指定，只写自己的记录；本批开发只指向隔离临时目录。

- 文件为导出根内普通 UTF-8 JSON：`session-<sha256>.json` 或 `execution-<sha256>.json`；文件名由 `sourceId/sessionId/instanceId/executionId` 的稳定组合生成，不直接拼接外部路径。以临时文件完整写入后原子替换；不把临时文件作为有效记录。
- 公共必填字段：`version:1`、`kind:session|execution`、`sourceId`、`sessionId`、`instanceId`、`revision`（该记录内递增整数）、`observedAt`（ISO 时间）、`heartbeatAt`（ISO 时间）、`cwd`（规范绝对路径）、`state`。session 的 executionId 为 null；execution 须有非空 executionId。
- `state` 只表达运行事实：`idle`、`running`、`waiting`、`settled`、`closed`、`unknown`；可选 `outcome` 为 `completed|aborted|error`，指运行回合而非业务验收。不得用这些字段直接宣称业务完成。
- sessionId 来自 Pi SessionManager；instanceId 区分启动/重新加载的导出实例；executionId 关联原用户输入/执行回合，内部工具轮次或自动续跑不另造业务任务。切换、分叉、恢复必须保留可证明的来源关系；无原关系就标未知，不按标题猜。
- 可选 `subject:{title,goal}` 与 `result:{summary,refs:[{path,sha256}]}` 仅在本次导出授权允许时提供；不保存模型思考、完整会话、凭证、环境或附件字节。源文件引用不是读取许可，甲再次核对当前权限及内容版本。模型自述的 result 只是来源报告，不等于 PA 已核实的交付。
- 同一记录的旧 revision 不覆盖新版本；每个会话及执行保留自己的当前快照，不将兄弟回合覆盖掉。甲将原来源、收到时间、最后核实时间、业务关联分别保存；没有业务内容时只能展示运行观察。
- sourceId/cwd/项目名不是授权来源：甲先匹配获准导出根和登记来源，再核对路径、普通文件、所有者、大小及身份；拒绝链接逃逸、任意路径自报和越权字段。乙在导出前独立检查准许的来源/字段。单记录上限建议复用现有材料上限中的较小值，不允许无界读取。

此约定不要求新服务、全局日志扫描或新凭据。两任务分别用构造记录验证边界，A7 再核对实际导出与实际接收；不能靠修改验收标准处理格式冲突。

## 五、实施与交付顺序

## 验收标准

以下为本次准备采用的第三批标准，共 10 条。除标注 [授权] 的模型语义项外，均使用构造数据、隔离项目与本地渠道/执行替身；没有新增真实账号权限。语义项只向已配置模型提交脱敏合成材料，消息仍发本地替身；不得读取真实会话、向真实飞书发送测试消息或启动真实业务任务。未授权就保留未验证，不能代本人写授权。

A1. [甲：工作记录与回复] [授权] 操作：向实际配置的 PA 模型提供含旧未决事项、旧失败能力说明和当前能力的合成对话，再发送普通问候或无关问题。
    预期：回复当前问题，不重新催办旧事项、不要求重复选择，也不把旧事项状态称为刚核实的现状；未预设模型回复或工具选择。

A2. [甲：工作记录与回复] [授权] 操作：在合成对话中询问当前工作全貌，并令指定来源分别返回完整成功、部分覆盖和失败。
    预期：回复与本轮实际查到的范围一致；部分/失败明确列出未知，不能拿空任务表或旧回复断言全局没有工作。

A3. [甲：工作记录与回复] 操作：将同一构造项目中 PA 发起与本人独立启动的不同工作纳入记录，并让其中一件事发生第二次执行，再按原事项追问。
    预期：不同工作身份独立，同一事项保留多个原执行引用和正确结果；没有重新派发独立工作，也不因同名/同目录把不同事项合并。

A4. [乙：Pi观察导出] 操作：用本批扩展在构造 Pi 会话中经历启动、处理、交互等待、停稳、切换/恢复和退出，查看实际生成的记录；再尝试未获准来源与不允许导出的内容。
    预期：身份、回合、版本及运行状态对应真实事件；停稳不标业务完成，越界内容不导出；导出失败不影响原工作、不改变原自动执行方式。

A5. [甲：工作记录与回复] [授权] 操作：用实际配置模型处理合成的“查一次”“盯到本次完成”“持续关注未来工作”及“先交结果再持续关注”表达和必要澄清答复。
    预期：产生与明确责任终点一致的查询/派单/关注组合，引用已有对象、不重复确认已知信息；不把关键词或预设分类结果当语义通过。

A6. [甲：工作记录与回复] 操作：建立构造关注规则，结束其中一个任务后新增另一个任务，再重启 PA、暂停或等待规则到期。
    预期：有效规则期间继续接收新工作，重启不丢规则或重复建单；暂停/到期后停止该规则接收新工作，既有一次性委托按回执保留，不停止外部执行。

A7. [甲：工作记录与回复] 操作：让乙实际导出的构造记录进入同一汇总树 PA，分别遗漏通知、重复/乱序写入、半写、停止租约刷新和撤销该观察来源。
    预期：健康通知与补登符合确认时限；无重复派工/事项，失败保留最后可靠状态和时间；失联不误称业务失败，撤销后不继续读取或向模型披露该来源。

A8. [甲：工作记录与回复] 操作：在没有 Git 仓库的获准构造目录中，先即时检索材料，再跨轮完成一份本地材料纪要或比较结论，并追问其依据。
    预期：即时查询不建派单，跨轮交付保持同一事项及真实结果/材料引用；不要求 Git/评审/提交号，不因 Loop 来源不适用阻断办公，也不声称已对外发送。

A9. [甲：工作记录与回复] 操作：从含旧任务、未决确认、既有消息和执行记录的构造旧库升级后查询并继续原事项，再执行交付的恢复办法。
    预期：原任务和结果可找到，旧确认不因迁移重新执行，来源关联未变成永久关注；恢复后仍可按原身份继续，未清库或重派旧工作。

A10. [甲：工作记录与回复] 操作：用构造输入通过 reply 请求发送带过期引用、声明为事项但缺依据、或无关旧催办的结构化片段，并让模型直接返回未经结构化核对的最终文字；对照有有效依据且本人确实问起的回复。
     预期：非法事项片段被拒绝，直接最终文字经有限补正而非原文兜底发送，有效相关回复正常送达；不因省略 taskId 绕过，也不以删除历史或全局禁提醒取得通过。此项只验证程序约束，不能替代 A1/A2 的模型语义结论。
