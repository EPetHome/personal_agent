# PA 基础适配与排版：飞书排版

## 目标

修复普通飞书回复直接露出 Markdown 加粗、表格等标记的问题；发送和更新显示一致，保留信息与原发送可靠性。与任务基础并行开发，不等待 token、日志或已派出卡。

先读本提示词、同批[整批验收标准](../batches/PA基础适配与排版-20261107/整批验收标准.md)，再读 `code/agent/src/channel.ts`、已有官方 SDK 本地替身及发送/更新测试。产品需求见[分批方案](方案-PA分批推进.md)和[主需求](../requirements/需求书-PA-LangGraph重建.md)。

## 已拍板

- 普通回复的标题、强调、列表和简单表格要可直接读；消息类型与实际内容匹配。优先沿现有纯文本通道做有限格式转换，表格可转带字段名的逐项文字，不实现完整 Markdown 引擎、不新装排版库、不调用模型重写。
- 保留正文、数值、链接、路径、换行和代码内容；`a*b`、命令里的 `|`、下划线等字面字符不能被全局删除。未支持格式采用保留内容的明确回退，不悄悄丢字段或改业务含义。
- 同一转换用在普通消息发送及更新；官方 SDK 发出的实际 payload 与本地替身需要一致。任务卡按钮、确认流程、附件接收、本人身份校验、outbox 去重、超时与送达未知不重发保持原行为。

## 边界

仅改 `code/agent/src/channel.ts`、必要时新增的小型 `code/agent/src/feishu-format.ts`、定向测试 `code/agent/test/feishu-format.test.ts`，以及唯一结果中的“飞书排版”一节。不改其他源码/共享测试、包依赖、类型或公共 Channel 接口；不做已派出卡，不改终端日志，不动 Loop 适配或任务存储。

只用构造文本、已有本地 SDK 替身及假凭证。不得连真实飞书、读取真实消息/凭据或调用业务模型；不启动正式服务、不修改配置/标准，不手工提交、合入、推送或部署。依赖缺少时按现有锁文件 `npm ci --no-audit --no-fund`，不升级。

复用现有测试工具，新增一个行为回归文件即可。至少覆盖普通正文、标题/强调/列表/表格、字面符号和实际 SDK 发送/更新载荷，不能只测试没有接入发送路径的转换函数。卡片/附件不属本次实现范围，保留必要兼容检查。

唯一结果入口：`docs/batches/PA基础适配与排版-20261107/结果.md`，只填写“飞书排版”一节：转换策略、构造输入与输出例子、检查结果、未覆盖格式及真机未验。不要修改“任务基础”和协调方记录。

## 验收标准

本任务负责同批整批标准 A8—A9；A10 为本人真实可读性判断。以同批标准为准，不修改标准或另建平行结果。
