# 提示词：空会话不致盲（闭环 1 修复）

依据：问题单（事实、因果链、真机现场，先读）[一个打开就关掉的 Codex 会话，让整个 Codex 盯防「看不见了」](../../iusses/空的Codex会话让整个Codex看不见.md)；需求书 D29「只有核心信号取不到才算看不见了」。

## 目标

一个打开就关掉、没有对话的会话，不能让整个工具的盯防「看不见了」。

现在两处规则对不上：Codex 读取组件把只有 `session_meta` / 噪音、没有核心消息的文件当「非会话」跳过并计数（`code/src/sources/codex/说明.md`「跳过/失败」）；检测里推送对账只在「文件不存在」时才认空会话（`code/src/core/agent.ts` 约 206–213 行的 `push_empty` 分支要求 `presentPaths` 里没有这个文件）。文件存在却被跳过时，这条「会话结束」推送落到「推送与已读取会话对不上」，整个来源记异常，发「看不见了」，所有 Codex 会话不再确认状态。真机 2026-10-28 06:40 UTC 起正处在这个状态。

## 已拍板

- 文件存在、但被读取组件按「非会话」跳过（只有开头信息或噪音、没有核心消息）时，对应的「会话结束」推送和文件不存在一样按空会话放过：记一条空会话事件（原因写明是哪一种空），不报来源异常，不发「看不见了」。
- 真正对不上的照旧报异常：文件里有对话但身份或路径和推送冲突，不能被当成空会话放过；坏 JSON 也不能伪装成空会话（沿用读取组件现有规则）。
- CC、Pi 的同类情况一并覆盖：打开即关、只有元数据的会话文件，加上「会话结束」推送。
- 已经卡在异常里的数据：升级后的下一轮检测，那条推送按新规则放过，来源恢复；已发过的提醒不重发。
- 本批只做「空会话认对」。「一条推送对不上只影响那一个会话、不连累整个来源」另排，不在本批。

## 边界

- 只改 `code/` 和本批结果 `docs/batches/空会话不致盲-20261028/结果.md`。不新增第三方运行依赖。
- 不读写真实的 `~/.claude`、`~/.codex`、`~/.pi`、`~/.pi-autoreview`、`~/.personal-agent`；不连真实飞书，不调真实模型，不弹真实通知；用构造的会话样本和替身。已有场景样本目录（`docs/batches/*/samples/`）只读。
- 已有行为不变（已有测试全部通过）。
- 不做：缩小「看不见了」的影响范围；提醒等候间隔；运行数据封存；失败原因留痕（各有问题单）。

## 验收标准

A1. 操作：放入构造样本：一个 Codex 会话文件只有开头一行（session_meta），钩子报「会话结束」；跑检测，直到过了两轮宽限
    预期：Codex 来源没有异常；发件记录里没有「看不见了」提醒；事件里记了一条「空会话，放过」
A2. 操作：同一份样本里再放一个正常的 Codex 会话，停在等你回复
    预期：照常发出这个会话的「在等你」提醒
A3. 操作：CC、Pi 各放一份只有开头信息的空会话样本，加上「会话结束」报信
    预期：两个来源都没有「看不见了」
A4. 操作：放入构造样本：报信指向的文件里有正常对话，但会话号和报信对不上
    预期：照常报「看不见了」（真正对不上的，不能当成空会话放过）
