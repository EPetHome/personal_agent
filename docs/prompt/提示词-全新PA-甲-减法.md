# 全新 PA 甲：减法

本批共 6 段，这是第 1 段。先读[六段共同约定](../batches/全新PA-20261102/共同约定.md)，那里的已拍板和边界同样适用。

## 目标

真机马上安静：只剩 loop 卡和 PA 故障提醒。对应[方案](方案-全新PA.md)「要做的全部东西」第 2 项。

- 去掉聊天会话（CC、Codex、单独的 Pi 会话）的「在等你」「疑似跑偏」「停滞」卡，以及为它们发起的模型调用（包括「放出智能」的后台分析）。
- 去掉每日汇总、周报、复盘。
- 不再扫 CC、Codex、单独 Pi 的会话文件，看不见这些目录也不报。
- CC、Codex 的 hook 推送收到就丢，不出卡、不调模型；hook 本身留着，后面「转给 CC」要用它找最近的会话。
- loop 的暂停、完成、失败卡，看不见 loop 的提醒，以及 PA 自身故障类提醒（渠道失败、磁盘满、检测失败、异常退出）照旧。

## 已拍板

- 删掉的是行为，不是数据：旧数据文件一个不删、不改。
- 飞书连接、反馈按钮、CC 转达、launchd 常驻照旧可用。

## 边界

- 去掉的功能直接删代码和配置项，不留开关；配置文件里还写着旧配置项时照常启动，忽略即可。
- 下一段要拆掉大循环、换成账本和事件驱动，本段不做，只做减法。

## 验收标准

A1. 操作：放进一个编造的 CC 会话，AI 最后一句在问你，跑一轮检测
    预期：发件记录里没有这个会话的卡片；事件记录里没有为它发起的模型调用
A2. 操作：放进一个编造的 Codex 会话，内容明显偏离开头交代的目标，跑一轮检测
    预期：没有「疑似跑偏」卡，没有为它发起的模型调用
A3. 操作：放进一个编造的单独 Pi 会话，超过 30 分钟没有动静，跑一轮检测
    预期：没有「停滞」卡
A4. 操作：放进一个编造的 loop 批次总结，状态是暂停，跑一轮检测
    预期：照旧出一张「loop 暂停」卡
A5. 操作：放进一个编造的 loop 批次总结，状态是完成，跑一轮检测
    预期：照旧出一张「loop 完成」卡
A6. 操作：把时间推到当地 20:00 和周报时点，让常驻服务跑过这两个时点
    预期：不发每日汇总、周报、复盘
A7. 操作：让 CC 会话目录读不了，跑一轮检测
    预期：不报「看不见 CC」
A8. 操作：让 loop 目录读不了，跑一轮检测
    预期：照旧报「看不见 loop」
A9. 操作：往收件目录放一条编造的 CC「回合结束」hook 推送
    预期：不出卡，没有为它发起的模型调用
