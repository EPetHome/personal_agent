# PA 跟进并行：无事件检测

## 目标

没有 Loop 新事件时仍核对已托管原执行，报告明确退出或无法核实，恢复后更新原通知；正常长任务不能误报故障。

读取：本提示词 → [统一标准](../batches/PA跟进并行-20261107/整批验收标准.md) A3/A4 → [方案](方案-PA分批推进.md) → [原单](../../issues/【bug】Loop无事件失联或停滞未被主动发现.md) → App 生命周期、Workers.status、KernelFacts、TaskMessages/Store 及调用者。只在 Loop 当前任务空间开发。

## 已拍板

- 对仍有跟踪责任的已托管原执行每 60 秒兜底核对，不等事件；只查原身份，不扫全部历史/私人会话。任务终态、等待本人、队列等待和 PA 停止均有相应停止/降频边界，避免无意义重查。
- 连续两次查询失败后，只提示“状态待核实”，带最后成功核实时刻、失败原因和建议；保留最后可靠事实，不写成任务失败。一次失败不叫本人。恢复成功更新原通知，同一连续故障不重复新卡，重启保留去重记录。
- 可信来源明确报告原执行退出/失败时据实提示；活动消失、PID 复用/身份未知不等于业务失败。正常长任务、排队/等本人不误报。没有可靠进展证据只能称“进展待核实”，不以固定静默时长判停滞。
- 不自动重启、续跑、停止、重派，不解除未核实操作占用；与 PA 自身 watchdog、任务 resumed 恢复卡及暂缓后普通催办分别处理。

## 边界

优先新增 loop-monitor.ts，复用 Workers.status/Store/TaskMessages；App 只接本项启动、停止、异常收尾，不抢占本人输入，不允许无界重叠轮询。Intake 来源发现归渐进感知；不重写 Loop 协议/worker callback/watchdog。共享 prompt/capabilities 只改异常检测句；使用说明只改本项。

只改 scope；不改正式/本机配置、标准/权限或外部 Loop 项目，不触碰真实服务。用构造记录、本地通道及本批创建的隔离子进程，禁止杀真实 Loop 制造故障。

新增 code/agent/test/loop-monitor.test.ts，覆盖正常长任务与异常/恢复对照，复用受影响测试。可用可控时钟测边界，默认周期必须是已定值；不为测试加快正式轮询。依赖按原 lockfile 装一次，不全仓重跑。

只写 docs/batches/PA跟进并行-20261107/结果.md 的“无事件检测”段，说明实际证据、时限/去重/恢复与未验证项；替身通过不等于真实故障验证。

## 验收标准

负责统一标准 A3、A4，参与 A9。来源补查成功不等于完成异常检测；不修改标准。
