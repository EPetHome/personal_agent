## 做成什么样

```
你：CC、Codex 头脑风暴（PA 不碰）；放权 = 启动 loop，或在卡片 / 飞书 / 侧边栏上点头
 ↓ 放权动作、飞书打字、指定目录的新文件、日历和会议                ↑ 卡片（核实过的事实 + 方案 + 按钮）、问答、侧边栏、微信
PA：账本（唯一存状态）+ 研判（只读 Pi，想完就退）+ 闸门（只在需要你、做完、红线、故障时打断）
    行动：送话 · 替你执行（推送、合入、停批次）· 派活 · 自动档 · 交接简报 · 转给 CC
    记忆：规则参照、人、偏好、在忙什么（你确认才进）
    自检：watchdog 只报事实 + 独立心跳
 ↓ 派工（过围栏、留痕）
Pi：唯一执行器 —— 查询（只读）、执行（改代码的外面套 loop）
不做：盯你的聊天；判跑偏（暂时靠派单控制）；每日推送、周报、复盘
```

## 要做的全部东西

| 2 | 减法 | 去掉聊天会话的在等你、跑偏、停滞卡和对应的模型调用；去掉每日汇总、周报、复盘；不再扫 CC、Codex、单独 Pi 的会话文件；CC、Codex 的 hook 推送收到就丢（hook 留着给「转给 CC」找会话） |
| 3 | 托管 loop | 接 loop 事件、查状态、读证据；先核实再叫（过 3 分钟还停着才算停）；闸门：需要你决定、暂停、返修到上限、做完马上推，合入队列前两次退回和停滞进「等你」清单；卡片带核实过的事实和方案（写依据）；同一批次一张卡；只由 PA 发通知；记 loop 误报 |
| 4 | 卡片上的动作 | 送话：按建议、选项、我写一句、继续、再给一轮；执行：推批次分支（不推 main、不强推、先查密钥、公开仓库写明）、合入、停批次。都过围栏、留痕、按回执更新原卡，说不清不重发 |
| 5 | 交接简报 | 批次返修到上限或被停掉时写：目标、做到哪、关键决定、遗留问题、代码位置；开新批时带上 |
| 6 | 飞书打字 | 问状态（从账本答）、回某张卡（等同「我写一句」）、「转给 CC：……」（送进你最近用的 CC 会话）、交任务（走第 7 项）；原有反馈词照旧；连续几句接得上 |
| 7 | 派活 | 派之前的检查（做什么、怎样算完成、能动什么，后两样用默认）；缺事实就提议派只读 Pi 去查，你过审；提问单（目标、问题、边界、到位标准、预算），一次派一次交；出派工建议（配方、定义、范围），你点头才派。你中途改要求：意图卡出新版本，记下来源那句话；收紧的立刻暂停有冲突的动作（比如做完卡上的合入），放宽的只放宽点名的那一项。派给谁：改代码的开 loop 批次（按意图卡选配方）；只要事实的派只读 Pi；转写、摘要、沉淀进 wiki 这类固定流程派 Pi 跑对应的 skill |
| 8 | 放权 | 档位按「来源 × 动作」：影子、建议、自动，默认建议；某类够了线，卡片提示「这类可以改自动」，你点了才改；自动处理的事后在原卡写明，带撤回；红线永远不自动；派活同样可以改自动 |
| 9 | 记忆 | 规则参照：从你的一贯选法起草候选，你一键确认才进，带版本，研判出建议时引用；人、偏好、在忙什么：同样候选加确认 |
| 10 | 自检 | watchdog 只报事实：派工停了、会话没了（进「等你」清单），来源看不见、话送不到、PA 故障（马上告诉你）；独立心跳：launchd 下另一个小任务，主进程心跳太久没更新就弹本机通知 |
| 11 | 侧边栏 | 桌面小窗，常驻显示在跑、等你、卡住、做完待推送，外加「今天先做哪件」；能做卡片上已有的动作；不响、不弹 |
| 12 | 工作区 | 只看你指定的目录；新文件进来，研判是什么、和哪件事有关，带 2～4 个选项加「先放着」问你 |
| 13 | 日程和会议 | 读日历和会议纪要；开会时只发红线、PA 故障、需要你决定，其余会后发；纪要里的待办走第 7 项变成派工建议 |
| 14 | 微信 | 飞书之外的第二个渠道，卡片和按钮同飞书。用企业微信智能机器人的长连接模式，不需要公网地址；开发和自动验收先做一个假渠道，和飞书的假渠道一样 |
| 16 | 围栏 | 红线（三条加五条判据，程序判、模型只能加不能减）、不许读名单（沿用现有的读取拦截）、档位、留痕、撤回；每一条送话、执行、派活发出前都要过 |
| 15 | 观测 | 叫错率、漏叫率、按建议的比例、被问回来的比例、问答对不上的次数、「本来不用我」的次数、loop 误报、查询花费；不推给你，协调方要用时去取；评测集判定点按这些改写 |

## 开发怎么排

一个产品，分 6 批连续开发：一批合入、上真机，下一批接着开，不等数据。旧数据不迁移，新结构从上线起记。批 2 引入账本这个新结构，上线前完整备份数据目录，结果里写恢复办法。

| 批 | 内容（对应上面的模块） | 上线后你看到的 |
|---|---|---|
| 1 | 减法（2） | 真机马上安静：只剩 loop 卡和 PA 故障提醒 |
| 2 | 底座和托管 loop（1、3、16，第 4 项里的送话，15 的记录） | loop 卡都是核实过、带方案的，点按钮就能回话 |
| 3 | 替你执行、交接简报、自检（第 4 项里的执行，5、10） | 卡片上能推送、合入、停批次；PA 停了有人告诉你 |
| 4 | 飞书和派活（6、7） | 在飞书里能问、能回、能转给 CC、能交任务 |
| 5 | 放权和记忆（8、9） | 你常按建议的那类开始提示改自动；规则、人物要你确认才进记忆 |
| 6 | 侧边栏、工作区、日程会议、微信（11–14） | 桌面常驻一个小窗；放进收件箱的材料、会议纪要里的待办会变成提议 |

## 验收标准草稿

全部用编造的数据、替身 loop、假飞书渠道（现有的 `feishu.mode: fake`：往收件文件里放消息、从发件记录里看卡片）和测试仓库，不接真实账号；要接真实账号的标 [授权]。

### 批 1：减法

A1. 操作：放进一个编造的 CC 会话，AI 最后一句在问你，跑一轮检测
    预期：发件记录里没有这个会话的卡片；事件记录里没有为它发起的模型调用
A2. 操作：放进一个编造的 Codex 会话，内容明显偏离开头交代的目标
    预期：没有「疑似跑偏」卡，没有为它发起的模型调用
A3. 操作：放进一个编造的单独 Pi 会话，超过 30 分钟没有动静
    预期：没有「停滞」卡
A4. 操作：放进一个编造的 loop 批次总结，状态是暂停
    预期：照旧出一张「loop 暂停」卡
A5. 操作：放进一个编造的 loop 批次总结，状态是完成
    预期：照旧出一张「loop 完成」卡
A6. 操作：把时间推到当地 20:00 和周报时点
    预期：不发每日汇总、周报、复盘
A7. 操作：让 CC 会话目录读不了
    预期：不报「看不见 CC」
A8. 操作：让 loop 目录读不了
    预期：照旧报「看不见 loop」
A9. 操作：往收件目录放一条编造的 CC「回合结束」hook 推送
    预期：不出卡，没有为它发起的模型调用

### 批 2：底座和托管 loop

A1. 操作：替身 loop 写一条「开始」事件
    预期：10 秒内账本里出现这个批次的事情和派工（不等巡检），不发卡
A2. 操作：替身写「需要你决定」，带问题和两个选项；3 分钟后仍停着
    预期：假飞书渠道（`feishu.mode` 为 `fake`）收到一张卡：问题原文、建议及依据、按钮
A3. 操作：替身写「暂停」，2 分钟后写「恢复」
    预期：不发卡
A4. 操作：替身写「暂停：磁盘不足」，给的日志里其实是一条测试失败
    预期：卡片写明「loop 说是磁盘不足，核实是测试失败」
A5. 操作：在 A2 的卡上点「按建议」
    预期：替身收到的话和建议原文一字不差；留痕里有这次送话；回执「已读」后原卡更新为已送达
A6. 操作：送话时替身回执「说不清」
    预期：原卡标「不确定」，替身没有收到第二次
A7. 操作：替身写「做完」，但批次分支和候选里都找不到它报的提交
    预期：卡片写明「说做完了，没找到提交」
A8. 操作：同一批次先后写「暂停」「恢复」「做完」
    预期：飞书上始终是同一张卡在更新
A9. 操作：发卡后重启 PA
    预期：账本里的事情、派工、卡片状态都还在，旧卡不重发
A10. [人工] 操作：看「需要你决定」「暂停」「做完」三种卡
    预期：文案和方案是你想要的

### 批 3：替你执行、交接简报、自检

A1. 操作：在做完卡上点 [推到仓库]
    预期：测试远端多出这个批次分支；原卡更新为已推送和提交号
A2. 操作：测试仓库里放一个带假密钥的改动，点 [推到仓库]
    预期：不推送，原卡写明「发现疑似密钥，没推」
A3. 操作：在做完卡上点 [合入]
    预期：替身 loop 收到合入请求；原卡更新为已合入和提交号
A4. 操作：在卡住的批次上点 [停掉这批]
    预期：替身收到停止请求；原卡更新为已停；账本里多一份交接简报，五栏齐全
A5. 操作：替身 loop 的某一段会话消失，事情还没做完
    预期：「等你」清单里多一条「这件事没人在做了」，不推卡
A6. 操作：让替身的送话通道失败
    预期：马上收到「话没送到」的卡
A7. 操作：让主进程停止更新心跳，超过设定时长
    预期：本机收到一条「personal agent 停了」通知，来自独立心跳
A8. 操作：主进程正常运行一段时间
    预期：独立心跳不发任何通知

### 批 4：飞书和派活

A1. 操作：账本里放两件编造的「等你」事项，在假飞书渠道（`feishu.mode` 为 `fake`）发「现在有什么等我」
    预期：回复列出这两件
A2. 操作：先问「<某批次名>怎样了」，再发「那就先别合」
    预期：第一句的回答和账本一致；第二句的回复明确指向那个批次，这件事的意图卡出新版本，做完卡上的 [合入] 暂停
A3. 操作：引用一张「需要你决定」卡，回复「选 B」
    预期：替身 loop 收到「选 B」，原卡更新
A4. 操作：发「转给 CC：先别动配置文件」，测试用的 CC 会话目录里有一个最近的会话
    预期：那个会话收到这句原话；飞书回执写明送进了哪个会话
A5. 操作：发「给 <测试项目> 的 <某文件> 补测试，门禁过就算完」
    预期：收到一张派工建议卡：做什么、完成条件、范围、配方都齐，没有追问
A6. 操作：发「把三个模块的测试补完」，账本和项目里都定位不到是哪三个
    预期：收到一张卡，写明缺「哪三个模块」，问要不要派只读 Pi 去查
A7. 操作：在 A6 的卡上点 [查]
    预期：替身 Pi 收到的提问单有目标、问题清单、边界、到位标准、预算；交回后收到一张带依据的事实和最多 3 个问题的卡
A8. 操作：在派工建议卡上点 [派]
    预期：替身 loop 收到开批次请求，带配方名和定义；账本里出现这件事的派工
A9. 操作：一天内触发第 6 次补信息
    预期：不再提议去查，只列出缺什么
A10. 操作：发「把 <测试录音> 转写并摘要」
    预期：派工建议卡上的执行者是 Pi 加转写 skill；点 [派] 后替身 Pi 收到这条派工

### 批 5：放权和记忆

A1. 操作：同一类「暂停：环境类 → 继续」攒够 20 条，你按建议的有 18 条以上，没有严重错误
    预期：收到一张「这类可以改自动」的提示卡
A2. 操作：把这类设为自动，替身再写一条同类暂停
    预期：不打扰你，PA 直接送「继续」；原卡写「已按建议处理」，带 [撤回]
A3. 操作：点 A2 卡上的 [撤回]，替身再写一条同类暂停
    预期：这类退回建议档，照常发卡等你点
A4. 操作：替身写一条含红线的「需要你决定」，同类已设为自动
    预期：照样发卡等你确认
A5. 操作：把某一类派工设为自动，发一条这类任务
    预期：直接派，事后收到「已自动派」卡，带 [撤回]
A6. 操作：同一类「需要你决定」，连续 5 次你都选同一个选项
    预期：收到一张规则候选卡；点确认后，下一次同类问题的建议里引用这条规则
A7. 操作：不理规则候选卡，再来一次同类问题
    预期：建议里不引用这条候选
A8. 操作：确认一张人物候选卡「张三：Promate 的产品负责人」，再在飞书问「张三相关的事」

A9. 操作：不确认人物候选卡，再问同样的问题

## 附件：给 loop 的接口格式（PA 提议，交 loop 确认）

字段名、取值以本附件为准；loop 有异议改本附件，不各写各的。

**1. 事件**：写到 PA 收件目录（PA 配置项 `inboxDir`）下的 `loop/` 子目录，每个批次一个文件 `<批次名>.jsonl`，一行一条。

```json
{"schema":1,"id":"7b1c…","seq":3,"at":"2026-11-02T10:00:00Z",
 "project":"/Users/Admin/Desktop/personal agent","batch":"放出智能-20261101","stage":"甲",
 "state":"needs_decision",
 "reason":{"category":"decision","text":"开发方需要你决定"},
 "evidence":["/Users/Admin/.pi-autoreview/…/<会话>.md"],
 "detail":{"question":"门禁里一条旧测试时序不稳，要不要顺手改？","options":["改","不改"]}}
```

| `state` | 中文 | `detail` 里要有 |
|---|---|---|
| `started` | 开始 | `recipe`（有配方以后）、`prompt`（提示词路径） |
| `needs_decision` | 需要你决定 | `question`；有选项时 `options` |
| `paused` | 暂停 | `reason.category` 取 `environment` / `method` / `timeout` / `no_change` / `unknown`；`log` |
| `repair_limit` | 返修到上限 | `mustFix`：剩下的必修清单 |
| `completed` | 做完 | `branch`、`commit`、`gate`、`review`、`acceptance`：`{"result":"passed\|failed\|partial","manual":[],"failed":[],"partial":[]}` |
| `failed` | 失败 | `log` |
| `resumed` | 恢复 | `trigger`：`user_message` / `auto_retry` |
| `queue` | 合入队列变化 | `status`：`ready` / `returned` / `stopped`；`returns`：退回次数 |

**2. 查状态**：只读，不触发恢复或重测，命令名由 loop 定，返回：

```json
{"schema":1,"batch":"放出智能-20261101","updatedAt":"…","lastActivityAt":"…",
 "stages":[{"name":"甲","state":"paused","reason":{"category":"timeout","text":"…"}}],
 "branch":"feat/放出智能","commit":"28de900","queue":{"status":"ready","returns":0}}
```

**3. 送话**：输入和回执：

```json
{"requestId":"pa-…","batch":"放出智能-20261101","stage":"甲","text":"不改，记问题单另开批","source":"user_via_pa"}
{"requestId":"pa-…","status":"delivered|consumed|uncertain|failed","reason":"…"}
```

同一个 `requestId` 只投递一次；`uncertain` 不重试。

**4. 通知开关**：loop 的配置里加一个布尔开关，名字由 loop 定；关掉以后 loop 不弹本机通知，其余照旧。
