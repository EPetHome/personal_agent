# 全新 PA 丁：飞书和派活

本批共 6 段，这是第 4 段，接在「丙 替你执行、交接简报、自检」之后。先读[六段共同约定](../batches/全新PA-20261102/共同约定.md)。

## 目标

在飞书里能问、能回、能转给 CC、能交任务。对应[方案](方案-全新PA.md)第 6、7 项，需求书 7.6「派活」。

1. **飞书打字**：问状态（从账本答）；回某张卡（等同「我写一句」）；「转给 CC：……」（原话送进最近用的 CC 会话，回执写明送进哪个会话）；交任务（走下面的派活）。原有反馈词照旧；连续几句接得上（「那就先别合」指向上一句问的批次）。
2. **改要求**：用户中途改要求，这件事的意图卡出新版本，记下来源那句话；收紧的立刻暂停有冲突的动作（比如做完卡上的 [合入]），放宽的只放宽点名的那一项。
3. **派之前的检查**：做什么、怎样算完成、能动什么，后两样有默认就用默认，不追问。
4. **补信息**：缺事实就提议派只读 Pi 去查，用户点了才派；提问单有目标、问题清单、边界、到位标准、预算；一次派一次交；交回后出一张带依据的事实和最多 3 个问题的卡。每件事最多 1 次、每天最多 5 次、每次 20 分钟，超了只列出缺什么。
5. **派工建议**：配方、定义、范围、执行者齐全，用户点 [派] 才派。派给谁：改代码的开 loop 批次（按意图卡选配方：开发 / 只评审 / 只验收）；只要事实的派只读 Pi；转写、摘要、沉淀进 wiki 这类固定流程派 Pi 跑对应的 skill。开新批时带上丙段存的交接简报。

## 已拍板

- 转给 CC 只在用户说「转给 CC：……」时做，原话一字不改；要 CC 处理的其他事，PA 不往 CC 里送，卡片提示用户自己去说。
- 派活、补信息派出前都过围栏、留痕；本段一律是「建议」档，用户点了才派。

## 边界

- CC 转达沿用现有 `cc-relay` 的通道和护栏；测试用编造的 CC 会话目录。
- 替身 Pi 要能收提问单、按设定交回结果；替身 loop 要能收开批次请求。

## 验收标准

A1. 操作：账本里放两件编造的「等你」事项，在假飞书渠道（`feishu.mode` 为 `fake`）发「现在有什么等我」
    预期：回复列出这两件
A2. 操作：先问「<某批次名>怎样了」，再发「那就先别合」
    预期：第一句的回答和账本一致；第二句的回复明确指向那个批次，这件事的意图卡出新版本，做完卡上的 [合入] 暂停
A3. 操作：引用一张「需要你决定」卡，回复「选 B」
    预期：替身 loop 收到「选 B」，原卡更新
A4. 操作：发「转给 CC：先别动配置文件」，测试用的 CC 会话目录里有一个最近的会话
    预期：那个会话收到这句原话；飞书回执写明送进了哪个会话
A5. 操作：发「给 <测试项目> 的 <某文件> 补测试，门禁过就算完」
    预期：收到一张派工建议卡：做什么、完成条件、范围、配方都齐，没有追问
A6. 操作：发「把三个模块的测试补完」，账本和项目里都定位不到是哪三个
    预期：收到一张卡，写明缺「哪三个模块」，问要不要派只读 Pi 去查
A7. 操作：在 A6 的卡上点 [查]
    预期：替身 Pi 收到的提问单有目标、问题清单、边界、到位标准、预算；交回后收到一张带依据的事实和最多 3 个问题的卡
A8. 操作：在派工建议卡上点 [派]
    预期：替身 loop 收到开批次请求，带配方名和定义；账本里出现这件事的派工
A9. 操作：一天内触发第 6 次补信息
    预期：不再提议去查，只列出缺什么
A10. 操作：发「把 <测试录音> 转写并摘要」
    预期：派工建议卡上的执行者是 Pi 加转写 skill；点 [派] 后替身 Pi 收到这条派工
