# 提示词：卡片事情快照（闭环 1 第八批）

依据：需求书 `docs/requirements/需求书-personal-agent.md` 的 D32（2026-10-27 新增）；方案 `docs/prompt/方案-闭环1-AI工作盯防.md` 第 13 节。
问题单（事实和真机原卡片，先读）：[卡片「这件事」是照抄原话，不是摘要](../../iusses/卡片这件事是照抄不是摘要.md)。

## 目标

用户第二天忘了前因后果，看卡片也要能说清这是件什么事、做到哪、要他做什么。现在「这件事」要么照抄用户最后一句话，要么只写「当下这一步」：在等你、跑偏由判断模型顺带写，但模型拿到的是过程步骤，没有「这件事整体是什么」；停滞、loop 交代、看不见了不经模型，靠规则从原文摘句，还漏过 `<file name=…>` 这类注入标签（`code/src/core/judge.ts` 生成提醒约 95–240 行，`code/src/core/notice-text.ts` 的 `currentTask`、`waitingSituation`、`presentNotice`）。

本批把卡片改成按「事情快照」写：检测时在会话记录里记下输入，发卡片时只用四样输入让模型写一次，输入和结果随卡片存下，供以后的闭环使用。

## 已拍板

- **只用四样输入**（用户 2026-10-27 定）：
  | 输入 | 取法 |
  |---|---|
  | 总目标 | 会话第一条有内容的真人要求（跳过截图 / 附件占位、编辑器 / 系统注入标签含 `<file …>`、「合入」「继续」这类操作词） |
  | 当前这件 | 最后一次输出之前、最近一条有内容的真人要求；和总目标相同只留一层 |
  | 最后一次输出 | 在等你：助手最后的回复；跑偏：触发判断的那一步；停滞：最后一步和已多久没动；loop：总结结论和还欠几项；看不见了：最后看到的内容和读不了的原因 |
  | 事实状态 | 现有规则判定的状态（在等你 / 跑偏 / 停滞 / loop 完成或暂停 / 看不见了），模型不重判 |
  写卡片不读过程步骤。跑偏的**判断**照旧看步骤，不改。
- **输入随检测记下，不等发卡片时再翻**（用户 2026-10-27 定）：真人要求记下时间，才能分出「当前这件」。这一步只用规则，不调模型。新增的记录大小固定（只加时间、不另存全文副本），不随会话变长或会话变多而增长。
- **只在发卡片时调模型**：在等你、跑偏并进原来那次判断调用，不多花；停滞、loop 交代、看不见了每张卡一次。同一事实（同一会话、同一证据时间）已经写过就复用，不再调用。模型等待在数据锁外，守现有的单轮时限和每日上限。
- **输出四项**：
  - 这件事：两句以内、约 100 字，是件什么事 + 做到哪 / 卡在哪；
  - 要你做：一句，要回答的问题或动作；不用管就直说「不用管，只是告诉你」；
  - 要你做的类型：回答问题 / 做个决定 / 去看一眼 / 不用管；
  - 来源：模型 / 规则。
- **规则兜底**：模型不可用、超时或答案缺字段时，「这件事」用总目标 + 当前这件拼出，「要你做」取最后输出里的问题；五类卡片照样发。兜底也不得出现占位、注入标签（含 `<file …>`）、路径、行号。
- **事情快照随卡片存进发件记录**：四样输入、四项输出都存。闭环 2（意图卡填总目标）、3（拿「要你做」转给会话）、4（按快照排必做）以后会用，本批不做它们。
- 卡片版式（D31 定的分块、按钮、证据收起）不变；只把「这件事」一块放宽到约 100 字，仍不超过两行左右；本机通知同样措辞。
- 数据只追加；旧发件记录、旧会话记录缺新字段照常读。升级后已发过的提醒不重发、不重新调模型。

## 边界

- 只改 `code/` 和本批结果 `docs/batches/卡片事情快照-20261027/结果.md`。不新增第三方运行依赖。
- 不读写真实的 `~/.claude`、`~/.codex`、`~/.pi`、`~/.pi-autoreview`、`~/.personal-agent`；不连真实飞书，不调真实模型，不弹真实通知；用构造的会话样本和替身。已有场景样本目录（`docs/batches/*/samples/`）只读。
- 已有行为不变（已有测试全部通过），只按本批改变的卡片文字同步旧断言。
- 不做：闭环 2 / 3 / 4；减少推送条数；代码里模型额度默认值（另有问题单）；检测失败留原因（另有问题单）。

## 验收标准

A1. 操作：放一份长会话样本：第一条真人要求是任务甲，中间改做任务乙，最后一条是「继续」，助手最后的回复在问乙的一个问题；判断器替身答「在等你」并给出这件事、要你做；跑一轮检测
    预期：发件记录里这张卡的快照中，总目标是甲的那句，当前这件是乙的那句（不是「继续」）；卡片「这件事」「要你做」是替身给的
A2. 操作：同 A1，查看替身收到的写卡片材料
    预期：只有总目标、当前这件、最后一次输出、事实状态，没有过程步骤
A3. 操作：同 A1，对比改前同一样本的模型调用次数
    预期：次数相同（在等你不多调用）
A4. 操作：让一个会话停滞超过阈值，替身给出这件事、要你做；跑一轮检测
    预期：发出停滞卡片，「这件事」是替身写的；模型调用次数 +1
A5. 操作：同 A4 之后不改任何事实，再跑一轮检测
    预期：不新增提醒，不新增模型调用
A6. 操作：判断器不可用，分别产生在等你、跑偏、停滞、loop 交代、看不见了五类卡片，其中一个会话第一条消息以 `<file name="…">` 开头
    预期：五类卡片都发出，每张都有「这件事」「要你做」；正文没有占位、注入标签、路径、行号；快照来源标「规则」
A7. 操作：任取一张发出的卡片，查看它的发件记录
    预期：带事情快照：总目标、当前这件、最后一次输出、事实状态、这件事、要你做、要你做的类型、来源
A8. 操作：产生一张 loop 交代卡片（还欠 3 项）
    预期：「这件事」说清项目、批次在做什么和结论；「要你做」写还欠几项；验收标准原文不在第一屏
A9. 操作：拿一份旧版产生的数据目录（已有发过的各类提醒和模型判断记录），用新版跑一轮检测
    预期：不新增提醒，不新增模型调用
A10. [人工] 操作：上真机用几天，隔天再看前一天的卡片
    预期：只看卡片就想得起是什么事、做到哪、要你做什么
