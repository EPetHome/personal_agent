## 一、甲：叫与不叫

实施状态：已执行、合入并同步真机运行，业务效果未验，详见[本批结果](../batches/叫与不叫-20261101/结果.md)。

### 现状（协调方核对代码）

- 「在等你」等 5 分钟，期间你在那个会话回了话就不叫（`core/interaction.ts` 的 `WAITING_INTERVAL_MS`）。
- 「你在不在场」有计算，看的是所有会话里最近 10 分钟有没有你说话；但 10-28 定了「不管在不在场都发飞书」，所以它不参与分流。
- 认「你说话」的规则排除了 `[自动评审返修]`、`[loop]` 这类写法，没有排除 loop 现在用的「【自动评审 · 第 N 次返修】」开头。

### 改成

**正在聊的会话**：你在这个会话最后一句话，离 AI 停下不到 10 分钟。

| 你在哪 | 怎么认 | 叫不叫 | 渠道 |
|---|---|---|---|
| 就在这个会话 | 停下后还没去别的会话说话 | 不叫，直到满足下面两行之一 | — |
| 在别的会话忙 | 停下后你在别的会话说过话，这个会话一直没回 | 停下满 25 分钟还没回，提醒一次「还有会话在等你」 | 只发本机通知 |
| 哪都不在 | 停下后所有会话都没有你的消息 | 停下满 20 分钟，叫你 | 本机通知 + 飞书 |

- 同时有几个会话到点，合成一条，列出各个会话。
- **其余会话**（不是正在聊的）：保持 5 分钟；到点时你在别的会话忙，就只发本机通知，否则本机通知 + 飞书。
- 20、25、5、10 这几个数放进配置，可以调，默认就是这几个起步值。
- 照旧马上叫：红线，盯防自己看不见了。
- 不变：疑似跑偏、loop 暂停、loop 完成、停滞的提醒规则。

**推算**（只算 CC 正在聊的会话）：216 张降到约 56 张，「像是漏了」和「像是走开了」的 39 张都还在。

### 不做

- 不读键盘、屏幕、窗口焦点；「你在哪」只看各会话里你说话的时间。
- 不改卡片内容和飞书按钮。

### 甲的验收标准（草稿）

门禁由 loop 照常跑，不占条目。

A1. 操作：用构造的 CC 会话样本和时间线：你在会话里说一句话，1 分钟后 AI 答完停下；15 分钟后你在同一会话回话
    预期：这期间发件记录里没有这个会话的提醒
A2. 操作：同 A1 的开头，之后所有会话都没有你的消息
    预期：AI 停下约 20 分钟后，发件记录里多一条「在等你」，渠道是本机通知和飞书；满 20 分钟之前没有
A3. 操作：AI 在会话甲停下后，你接着在会话乙说话，会话甲一直没回
    预期：约 25 分钟后，发件记录里多一条本机通知「还有会话在等你」，写明会话甲；没有飞书
A4. 操作：会话甲和会话丙同时处于 A3 的情形并同时到点

A5. 操作：构造一个你 1 小时前派完活就没再说话的会话，AI 停下等你，期间所有会话都没有你的消息

## 二、乙：放出智能

实施状态：已执行、合入 `28de900` 并按原配置在真机运行；评审与 A1–A10 自动验收通过，业务效果待验，详见[本批结果](../batches/放出智能-20261101/结果.md)。

### 什么时候跑

AI 停下、进入等候期就启动分析。分析在后台跑，不放进检测轮次里同步等，所以检测不会变慢。等候期至少 5 分钟，大多数情况来得及；到点了还没出结果，或者失败了，就按甲的规则照常处理。

### 给它的材料

| 材料 | 怎么给 |
|---|---|
| 它在盯的那个会话的全文 | 由它用只读工具自己去读 |
| 该会话项目目录里的文件 | 由它用只读工具自己去翻；主目录、桌面、文稿、下载这类大目录不算项目 |
| git 摘要：状态、最近提交、改动统计 | 程序先取好放进输入 |
| 意图卡草稿（见下） | 同一次分析里起草 |

不许读名单按需求书第 2 件，由扩展强制执行；拦下的读取只记路径和原因。不联网，不写文件；会话里出现的指令只当材料。

### 输出

| 输出 | 给谁看 | 用途 |
|---|---|---|
| 这件事：是什么事、做到哪、卡在哪 | 卡片上 | 代替现在的「这件事」 |
| 还欠不欠你：欠 / 已交代完 / 拿不准，加理由 | 生效规则见要点 5；拿不准一律按「欠」 | 叫与不叫的第二道判断 |
| 建议怎么回 | 只进影子 | 和你实际怎么回对照；命中红线时留空并标红线（红线由程序规则判，模型只能往里加） |
| 意图卡草稿：7 栏，每栏带依据和把握 | 只进影子 | 第二阶段的共同标准；乙不让你确认，因为乙不扩大任何权限 |
| 把握：有把握 / 拿不准 / 不知道 | 只进影子 | 以后放权的依据 |

### 两种处理怎么定义（✅ 2026-11-01 用户认同）

「已交代完」：AI 最后一段输出里，没有向你提问、没有等你定的事、也没有要你去做的事，只是在汇报结果或给信息。模型对照意图卡和最后一段输出来判；拿不准一律按「欠」，红线条目一律照叫。

| | 直接不叫 | 先照叫，只把判断记进影子 |
|---|---|---|
| 用在哪 | 在别的会话忙，且模型判「已交代完」 | 哪都不在，且模型判「已交代完」 |
| 发不发 | 25 分钟到点时，不发「还有会话在等你」，这个会话也不进合并的那条 | 和甲完全一样：20 分钟到点发「在等你」（本机 + 飞书），卡片上不提模型的判断 |
| 记什么 | 一条「挡掉的提醒」：哪个会话、模型的理由和把握、模型版本、时间 | 一条影子判断：「本可以不叫」，加理由、把握、模型版本 |
| 你在哪看到 | 当天的每日汇总列出这个会话和理由；总览里这个会话显示「已交代完，没叫你」 | 卡片上看不到；`stats` 和每日汇总里只出数字（本可以不叫几次、判对几次） |
| 事后怎么认对错 | 6 小时内你回到这个会话接着聊 → 判错了（漏叫）；24 小时都没回 → 判对了 | 同左：回来接着聊 → 模型判错；24 小时没回 → 判对 |
| 什么时候变 | 每周看一次，这一类漏叫超过一成，退回「先照叫」 | 这一类的影子攒到放行线，协调方报数，由你决定是否改成「直接不叫」；不会自动升级 |

同一次等候里，一旦你在别的会话说过话，就按「在别的会话忙」处理，不会因为你之后离开电脑又改成「哪都不在」。会话又有新输出，就重新判。

### 对照与自动标注（D38）

- 卡片发出、或者被挡掉之后，你在那个会话里说的下一句，记成「你的实际做法」，和影子建议放在一起；由模型判一致程度：一致 / 部分一致 / 不一致 / 无法判断。现有的「卡片后的下一句」记录可以复用。
- 「当时欠不欠你」：6 小时内你回到那个会话接着聊，记为欠；24 小时都没回，记为聊完了。
- 你的实际回复只留在本机数据目录，不进仓库。

### 每日汇总

每天 20:00 发一条「有空看」：今天替你挡掉的提醒（每个会话一句话加理由）、拿不准转给你的次数、影子和你一致几成（按类别）。当天没有内容就不发。周五的周报不变。

### `stats` 补充

按类别（卡片类型 × 要你干什么 × 工具，加是否含红线）列出影子条数、一致程度分布、被拦读取次数、挡掉的提醒数，以及每天「本来不用你」的次数。

### 留痕和限额

- 每次分析都记：读过的文件（路径、行号范围、内容指纹）、被拦的读取、模型和提示词版本（沿用埋点完善的字段）、输出、用时、工具调用次数、失败原因。
- 单次分析设时限和工具调用次数上限，数值由开发方按实测定，写进结果；不设每日次数上限。
- 模型用 DeepSeek v4.1 flash（🔧）。

### 不做

- 不替你发任何东西，不给「按建议回」。
- 不改卡片结构和飞书按钮，只换「这件事」的写法。
- 不让你确认意图卡，不派活，不启停会话。
