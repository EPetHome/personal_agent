# LangGraph 重建 · 丙段：派给 Pi

## 目标

在甲、乙段的基础上，让 PA 能把只读查询、技能、写文件这类活直接派给 Pi，并且管得住 Pi：读的范围、写的范围由程序在 Pi 调用工具之前检查，不靠提示词；Pi 卡死、PA 重启、同时派很多个都不出乱子。

需求依据（只读）：`/Users/Admin/Desktop/personal agent/docs/requirements/需求书-PA-LangGraph重建.md`，本段对应第五、七、八、九节。落地做法：`/Users/Admin/Desktop/personal agent/docs/prompt/方案-LangGraph重建.md` 第二节。结果续写 `docs/batches/LangGraph重建-20261104/结果.md`。

## 已拍板

1. **Pi 适配**：实现乙段 worker 接口的七个动作。每次派工起一个 Pi 子进程，独立进程组；PA 记下它的身份（进程号、启动时间、派工编号），结束进程只按这个身份，不按名字猜。结果写文件。可参考旧代码 `code/src/core/pi-worker.ts`。
2. **问用户**：Pi 没法停下来等，它在结果里写「需要你决定」；Router 问用户，用户回答后带着答案重派一次（同一件活下的新派工）。
3. **读写检查**：写一个 Pi 扩展，派工时加载（参照 Loop 用 `-e` 加载权限扩展的方式），在 Pi 调用读、搜、列目录、写、改之前检查：读按甲段的白名单加黑名单（真实路径判断），写只能写派工范围内。拦下的写进扩展日志，并让工具返回拒绝。拦不住就停下写「需要你决定」，不退回「只靠提示词」。
4. **跑命令和联网**：只读派工不给跑命令的工具，也不联网。技能、写文件派工默认也不给；确实需要时，派工卡片上写明要开什么、由用户点头。
5. **并发**：只读查询同时最多 3 个，技能同时 1 个，写文件同一目录同时 1 个，多的排队；上限可配。
6. **超时**：Pi 派工默认最长 20 分钟（可配），超时结束进程、确认没有残留，告诉用户，不自动重派。
7. **PA 停了 Pi 不停**：PA 正常停止时不杀正在跑的 Pi；PA 重启后接上还在跑的 Pi 继续等结果；已经不在的标「中断」并告诉用户，不自动重派。
8. **开关**（乙段已建）：派只读 Pi 默认先问用户；配置改成不问后直接派，做完在原卡写明「已直接处理」。红线类在配置里改成不问也无效。PA 不写配置；用户说「这类以后直接做」时只告诉他改哪一项。
9. **测试用真实 Pi**：验证拦截要用真实的 `pi` 加载扩展，模型指向甲段的脚本模型替身；用 `PI_CODING_AGENT_DIR` 指向临时配置目录，不改 `~/.pi/agent/`。其余用 Pi 替身。

## 边界

- 只改 `code/agent/` 和本批结果文件。不改旧代码、门禁方法、验收标准、需求和方案、`eval/`、历史样本。不新增运行依赖（需要的话先写「需要你决定」）。
- 不改 `~/.pi/agent/` 下任何文件；不读真实的 `~/.ssh/`，需要时在临时目录构造假文件。
- 测试和自验不调真实模型（真实 Pi 也只连脚本模型替身）、不连真实飞书、不调用真实的 `bin/loop`。
- 不提交、不合入、不推送。
- 遇到需求书没覆盖的细节按最保守的做法定，写进结果；只有拦截做不到或需要新依赖时才停下问。

## 验收标准

本段自己的验收只用替身和脚本模型，不花钱。整批验收在三段做完后另跑。

A1. 操作：构造一次已点头的只读派工，由 PA 派给真实 Pi（加载读写检查扩展，模型用脚本替身），脚本先直接读、再请求用命令（cat）读临时目录里构造的 .ssh/id_rsa
    预期：两种读法都没读到；这次派工的工具清单里没有跑命令的工具；扩展日志记下拦截；Pi 进程结束后没有残留
A2. 操作：构造一次已点头的写文件派工（范围：测试项目的 docs/），由 PA 派给真实 Pi（加载扩展，模型用脚本替身），脚本要求写一个 docs/ 以外的文件
    预期：写入被拦下，范围外的文件没有出现；扩展日志记下拦截
A3. 操作：把 Pi 派工时限配成 30 秒，派一次只读查询，Pi 替身挂住不返回
    预期：该 Pi 进程被结束、没有残留；假飞书收到超时的回报；没有自动重派
A4. 操作：派一次只读查询，Pi 替身跑到一半时正常停止并重启 PA，之后 Pi 替身交回结果
    预期：Pi 进程没有在 PA 停止时被杀；假飞书收到一次结果回报
A5. 操作：同时派 5 个只读查询
    预期：任一时刻最多 3 个 Pi 进程在跑，其余排队；5 个都有回报
A6. 操作：派一次只读查询（开关按默认）
    预期：先发卡片问；点「好」之前 Pi 替身没有被启动
A7. 操作：在配置文件里把「派只读 Pi」改成不问，再让脚本模型替身请求派一次只读查询
    预期：没有先发卡片问，Pi 替身直接被启动；做完后原卡写明「已直接处理」
A8. 操作：在配置文件里把「合入」改成不问，再让脚本模型替身请求合入
    预期：照样发卡片要求点头（且按钮标为当前不可用）；没有执行合入
A9. 操作：以本人身份发「派 Pi 查东西这类以后直接做」，脚本模型替身按系统提示词回复
    预期：配置文件没有被改；回复里写明要改配置的哪一项
