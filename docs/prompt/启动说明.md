# Pi 启动说明（personal agent）

本项目自己的选择：模型、工具组合、批次开工和合入步骤。loop 怎么用、批次字段和命令输出只看 loop 的 `工具清单.md`，这里不重复字段表。loop 版本和路径每次使用前都要核对（2026-10-25 对照的是 `3ac9757`）。

## 模型

- 开发：`openai-codex/gpt-6.1-sol`，`max`（`批次.json` 的 `pi`，也是 loop 默认值）。
- 评审：`openai-codex/gpt-6-astra`，`xhigh`（`.autoreview.json` 的 `reviewerModel` / `reviewerThinking`，不写就是这个默认值）。
- 自动验收：`opencode-go/deepseek-v4.1-flash`（`acceptance.model` 的默认值）。
- 写之前用 `pi --offline --list-models <关键字>` 确认型号存在；启动后核对实际加载的模型和档位。

## 工具组合

| 任务 | `批次.json` 的 `tools` | 额外参数 |
|---|---|---|
| 前端、插件、文档、命令行 | `read,edit,write,bash`（默认） | 无 |
| 要跑长构建、起服务 | 再加 `bg_run,bg_status,bg_logs,bg_result,bg_kill` | `args` 里加 `-e pi-background-tasks` |
| 只读调研 | `read,grep,find,ls` | 无 |

权限扩展、loop 和 Ponytail 由 `bin/pi-dev` 固定加载，不用手写。

## 项目固定方法

- 项目配置 `.autoreview.json` 和方法 `.autoreview/methods/` 都在仓库里，每批复用，批次目录不再放 `autoreview.json` 副本或门禁脚本。
- 门禁 `sh .autoreview/methods/gate.sh check`：启用全部已归档的场景样本，再跑 `code/deploy/check.sh`。新批次加了样本目录，在 `gate.sh` 的 `SAMPLES` 和 `self-check.sh` 里各补一行，这一步属于开工前的文档提交。
- 开发空间：项目根外的 `../personal agent-dev分支/`，各批复用，每批切到自己的分支 `feat/<批次>`（新版 loop 只认 `feat`、`fix`、`refactor`、`docs`、`test`、`chore` 开头）。
- 本机文件：只在本机存在、不进仓库的文件，写进 `.autoreview.json` 的 `localFiles` 并加进忽略规则，`bin/loop 开工` 会把它们复制进开发空间。目前没有这类文件。
- 远端：`origin` = https://github.com/EPetHome/personal_agent ，是公开仓库。**当前不推送**（用户 2026-10-25：先在本地开发），恢复推送要用户授权。
- 为什么开工前、合入前要提交文档：`bin/loop 开工` 和 `合入` 要求项目根没有任何未提交的改动或未跟踪的文件。

## 开工（每批）

`P` 是项目根，`B` 是批次目录名。

1. 写提示词 `docs/prompt/提示词-*.md` 和 `docs/batches/$B/批次.json`。一批几段时，每段一份提示词，`steps` 写先后顺序；段的 `scope` 至少禁止改动场景样本（`docs/batches/*/samples`）。
2. 文档提交：项目根必须干净。先确认没有密钥，再在 `main` 上本地提交全部文档改动（说明以「文档：」开头）。不推送。
3. 核对后开工：

   ```bash
   cd "$P" && /Users/Admin/Desktop/loop/bin/loop 开工 "docs/batches/$B/批次.json" --dry-run
   cd "$P" && /Users/Admin/Desktop/loop/bin/loop 开工 "docs/batches/$B/批次.json"
   ```

   方法指纹变了时，它会跑一次方法自测和基线门禁。
4. 在聊天里给用户的启动命令（由用户执行）：

   ```bash
   cd "/Users/Admin/Desktop/personal agent" && /Users/Admin/Desktop/loop/bin/loop 启动 "docs/batches/<批次>/批次.json"
   ```

   单段直接开会话；多段交给流水线，按 `steps` 串行或并行，最后跑整批 e2e。给用户之前先用 `--dry-run` 核对。
5. 运行中查状态：`bin/loop 状态 "docs/batches/$B/批次.json"`。

## 合入（每批）

用户说「合入」后，协调方执行：

```bash
cd "$P" && git status --short          # 有文档改动就先本地提交一次「文档：…」
/Users/Admin/Desktop/loop/bin/loop 合入 "docs/batches/$B/批次.json" --dry-run
/Users/Admin/Desktop/loop/bin/loop 合入 "docs/batches/$B/批次.json"
git branch -d "feat/$B"
```

`bin/loop 合入` 只在本地 `merge --no-ff`，有冲突就中止并恢复原状，然后由协调方报告。暂不推送 `origin`（用户 2026-10-25：先在本地开发）。开发空间保留，下一批 `开工` 时切到新分支。
