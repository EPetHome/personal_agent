# Pi 启动说明（personal agent）

## 模型

- 开发：`openai-codex/gpt-6.1-sol`，`max`。
- 评审：`openai-codex/gpt-6-astra`，`xhigh`（loop 参数 `--autoreview-reviewer-model`、`--autoreview-reviewer-thinking`）。
- 自动验收：`opencode-go/deepseek-v4.1-flash`（`.autoreview.json` 里的 `acceptance.model`）。
- 写之前用 `pi --offline --list-models <关键字>` 确认型号存在；启动后核对实际加载的模型和档位。

## 工具组合

| 任务 | `--tools` | 额外 `-e` |
|---|---|---|
| 前端、插件、文档 | `read,edit,write,bash` | 无 |
| 要跑长构建、起服务 | 再加 `bg_run,bg_status,bg_logs,bg_result,bg_kill` | `pi-background-tasks` |
| 只读调研 | `read,grep,find,ls` | 无 |

权限扩展每次都加，不因为已经装了就把其他扩展全开。

## 开工（每批）

在项目根执行（`P` 是项目根，`B` 是批次名）：

1. 从最新 `main` 拉批次分支和工作树：

   ```bash
   cd "$P" && git switch main && git pull --ff-only
   git worktree add ".worktrees/$B" -b "batch/$B"
   ```

   工作树刚建好时 HEAD 就是开工点，不需要另建外部基线。

2. 放好分支专属文件：`cp docs/batches/$B/autoreview.json ".worktrees/$B/.autoreview.json"`；需要密钥的复制已去掉真实密钥的 `.env`。验收环境脚本（`deploy/acceptance/`）不含密钥，直接进仓库，随 `main` 带过来；本批新增的验收脚本由协调方在开工前提交到 `main`，免得混进开发方的 diff。

3. （建议）在工作树里空跑一次门禁：`bash docs/batches/$B/$B-工具.sh check`。结果应该是通过，或者只剩已知失败。不通过就先修门禁工具，再给用户启动命令。

4. 在聊天里把启动命令给用户：`bash "$P/docs/batches/$B/$B-启动Pi.sh"`（脚本里 `--cwd` 指向 `.worktrees/$B`）。

## 合入（每批）

loop 完成、协调方核对后：

```bash
cd "$P/.worktrees/$B" && git add -A && git commit -m "<批次>：<一句话>"
cd "$P" && git switch main && git pull --ff-only && git merge --no-ff "batch/$B"
git push origin main
git worktree remove ".worktrees/$B" && git branch -d "batch/$B"
```

`main` 在开工后有别的改动时，合入冲突由协调方按三方对比解决，不覆盖别人的改动。
