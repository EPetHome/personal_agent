## 验收标准
A1. 操作：使用当前 Loop 的官方事件出口，将构造批次的开始与需要决定事件写入临时事件目录，PA 从该目录接收
    预期：侧边栏出现该真实格式事件对应的事情和等待状态；重复读取同一事件不增加第二件事
A2. 操作：从 PA 的真实 worker 入口查询临时构造的当前 Loop 批次
    预期：项目、批次、阶段、提交、会话与暂停原因对应官方查询；查询没有启动任务、恢复队列或修改批次状态
A3. 操作：通过假飞书对构造暂停段回复一段含换行的原话，再对整批暂停执行继续
    预期：分别进入 Loop 原段送话和整批续跑入口；原文/请求号正确对应，回执区别已投递、已读、不确定和拒绝
A4. 操作：对同一构造请求重放回执丢失，再在已确认执行前改变候选目标
    预期：不确定请求不重复执行；目标变化的执行被拒绝，测试远端与发布分支均未被错误修改
A5. 操作：在临时构造项目里，对明确的代码任务点派，走真实 Loop 开工/启动入口，模型和宿主用隔离替身
    预期：只创建一个独立批次/分支；原定义、完成条件、允许范围和禁改范围抵达开发入口，未直接改发布分支
A6. 操作：经真实 Pi 入口的协议边界派只读查询，并让隔离替身返回事实与写入企图
    预期：事实按原请求交回，读取范围可核对；写工具、自由 shell 和范围外产物均不可执行
A7. 操作：在临时指定收件箱放构造材料，分别选择转写/摘要/沉淀，使用隔离的模型和转写返回
    预期：请求进入真实执行路径的对应处理器，产物落在本次允许位置，原件字节/身份不变，缺少真实能力时明确报缺项而非伪造成功
A8. 操作：对临时的旧配置和数据执行部署预检、显式应用、重复应用与回退，launchd/外部平台使用隔离替身
    预期：预检无变更；应用保留凭据引用与原数据，服务/侧边栏/独立心跳入口对应新配置；重复应用不覆盖他人文件，回退可恢复原配置和入口
A9. [人工] 操作：用户在真机飞书发出一件明确授权的小任务并确认派出，查看真实执行、结果回卡和侧边栏
    预期：用户能完成一次任务往返，内容和操作体验符合原目标；这一步不由程序代做
A10. [人工] 操作：用户完成自己的飞书日历/妙记授权并核对范围，在真机使用指定材料和会议来源
    预期：用户认可读取范围、会议提醒与材料处理结果；未授权或未验证保持明确标记
