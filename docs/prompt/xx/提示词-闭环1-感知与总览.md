## 目标

personal agent 是跑在用户本机的个人 agent。第一个闭环是「AI 工作盯防」：替用户盯住 Claude Code、Codex、Pi 和 loop 的工作，只在需要用户的时候叫他。

本批先让它「看得见」：把四处来源的会话读成统一记录，按规则推算状态，能给出一份总览，并把规则能判断的提醒写进发件记录。模型判断、钩子、真实通知渠道和常驻进程留到后续批次。

依据（都在项目根，不在工作树里，只读）：需求书 `/Users/Admin/Desktop/personal agent/docs/requirements/需求书-personal-agent.md` 的「第一个闭环」；方案 `/Users/Admin/Desktop/personal agent/docs/prompt/方案-闭环1-AI工作盯防.md` 第 2、3、5、7、11 节。

## 已拍板

- 语言 TypeScript，本批不引入 LangGraph。感知 → 统一记录 → 判断 → 输出，四步各自独立，彼此只通过统一记录交换数据。
- 数据以 JSONL 事件为准，只追加；当前状态从事件推算，删掉后能重建。数据目录里有事件、发件记录、反馈（本批可以为空）、当前状态四样。
- 统一记录：每个 AI 会话一条，含来源工具、原件（会话文件路径和指纹，不复制内容）、类型、项目（工作目录）、意图、当前状态、最后活动时间。loop 的一次运行也是一条记录，用总结里「- 项目：」那一行认项目，不靠目录名。
- 意图 = 开工指令原文 + 用户后来追加的要求。只认用户本人输入的，任务通知、loop 返修消息等系统塞进去的不算。各工具怎么认，见方案第 11 节。
- 状态规则按方案第 11 节「规则判断」表。停滞 = 进行中、最后一条记录超过 30 分钟、且没有会话结束事件。
- 提醒分级按方案第 7 节。本批涉及：在等我、loop 暂停、盯防看不见了，属于「现在就要你」；停滞（每个会话只叫一次）、loop 完成的交代，属于「有空看」；进行中、已完成只进总览，不发提醒。
- 提醒格式按方案第 5 节：标题用大白话写「哪个项目的哪个 AI + 出了什么事」；一句话写判断和关键事实；「回去看」给一条能直接回到那个会话的命令；证据（意图原文、后来追加的要求、最近几步、判断依据）放在后面。内部编号只用来对上回复，不出现在给人看的文字里。
- 回去看的命令：Claude Code `claude --resume <会话id>`；Codex `<配置里的 codex 路径> resume <会话id>`；Pi `pi --session <会话id>`。
- 来源和渠道都做成组件，每个组件目录带一份说明：读什么、改了哪条配置（本批都是「不改」）、怎么装和卸、产出哪些字段。
- 推送事件文件的格式按方案第 11 节。本批只读这个文件，不写钩子。

## 验收标准

A1. 操作：用场景「01-等授权」（Claude Code、Codex、Pi 各一份会话，加对应的推送事件）跑一轮检测
    预期：发件记录里多三条「现在就要你」级别的提醒，工具名分别是 Claude Code、Codex、Pi；每条写有项目目录、开工指令原文、在等你授权做什么、一条回去看的命令；给人看的文字里没有内部编号
A2. 操作：用场景「02-干到一半」（最后一条记录是开始执行命令、没有返回），依次以最后一条记录之后 29 分钟、31 分钟、40 分钟为当前时间各跑一轮检测
    预期：29 分钟那轮没有停滞提醒，总览里它是「进行中」；31 分钟那轮后发件记录多一条「有空看」级别的停滞提醒，写明最后在做什么、停了多久、之前几步；40 分钟那轮不再为它多发
A3. 操作：用场景「03-看不见了」（一份解析不了的 Codex 会话，加一份正常的 Claude Code 会话）跑一轮检测
    预期：发件记录多一条「现在就要你」级别的提醒，写明看不见的是 Codex、从什么时候开始；其他来源的会话照常出现在总览里
A4. 操作：用场景「04-loop暂停」（loop 总结，状态：暂停（开发方需要你决定））跑一轮检测
    预期：发件记录多一条「现在就要你」级别的提醒，写有项目路径、暂停原因、总结文件路径
A5. 操作：用场景「05-loop完成」（loop 总结，状态：完成）跑一轮检测
    预期：发件记录多一条「有空看」级别的交代，写有结论、评审几次返修几次、还欠什么、总结文件路径
A6. 操作：用场景「06-正常做完」跑一轮检测，再要一份总览
    预期：总览里这个会话是「已完成」；发件记录里没有它的提醒
A7. 操作：用场景「07-全部正常」（四个来源各有会话）跑一轮检测后要一份总览
    预期：每个会话占一行，写有工具、项目、意图、状态、最后活动时间
A8. 操作：用场景「08-追加要求」（既有用户后来追加的要求，又有系统塞进去的任务通知）跑一轮检测，触发停滞提醒
    预期：提醒证据里「你后来追加的要求」只有用户本人那条，没有任务通知
A9. 操作：记下样本目录里所有文件的指纹，用任一场景跑一轮检测，再比对一次
    预期：所有样本文件都没有变化
A10. 操作：不提供任何来源和数据目录配置，直接跑一轮检测
     预期：报错说明要先配置，以非 0 退出；没有生成任何数据文件
