## 目标

personal agent 要开始建评测集：拿当时的输入重跑一次判断，和用户的标注对比；同时用运行记录查漏报。现在的记录不够用。

从现有记录的字段名看，至少缺下面六样（协调方只看了字段名，没有读代码，**开工后先逐条对照代码核实**）：

1. **模型判断缺版本和输入**：`model_checked` 里有结果和摘要，但看不出用的是哪个模型、哪版提示词，也还原不出当次发给模型的完整输入。
2. **抑制推送不记原因**：`notice_suppressed` 只有 `dedupeKey`，分不清是去重、5 分钟内回了话、额度用完，还是首次接入不补发。
3. **不记代码版本**：事件里没有当时运行的代码提交，升级过很多次后，分不清一个判断出自哪个版本。
4. **规则判定不记依据**：不经过模型的状态判定（停滞、完成、loop 暂停等）只记了判成什么，没记是哪条规则判的。
5. **「漏了」反馈缺对象**：用户回「漏了」只留下一句话，对不到当时的会话和时间。
6. **卡片不留原会话指纹**：原会话 7 天后会被封存。卡片要记下判断所依据的那段原会话在哪个文件、哪几行，以及内容的 sha256，过期后仍能核对当时的依据。

核实下来已经有的，不要重复加，在结果里写明在哪；核实下来缺口不止这些的，不扩大本批范围，写进结果的「另发现」一节。

## 已拍板

- 只**新增字段或事件**，不改已有字段的含义，不删字段。旧数据文件不迁移，照常读取；新旧记录混在一起时，所有读取方都不能报错。
- 「能还原完整输入」的要求是：只凭记录，就能确定当次发给模型的全部内容。存原文还是存可确定重建的引用，由开发方按现有存储方式决定，并在结果里说明理由和每条记录增加的大小。
- 抑制原因用固定的几个值，每个值对应需求书「什么时候叫我」里的一条规则；需求书里找不到依据的抑制路径，也要单独给一个值，不能归进「其他」。
- 本批不加任何新的用户可见功能：不改卡片内容，不改推送规则，不改飞书交互。每周推待标注卡片不在本批。

## 边界

- 只改 `code/` 和本批 `docs/batches/埋点完善-20261031/结果.md`。不改场景样本、需求书、方案和项目根的 `eval/`。
- 开发、门禁和自动验收只用构造的样例数据，不读用户真实的 `~/.personal-agent/` 和会话目录，不停止或重启真机服务。
- 数据格式有新增：在结果里写清楚上真机前要备份什么、出问题怎么恢复。
- 不读取、不记录任何密钥；新字段里不能出现凭据。

## 验收标准

A1. 操作：用构造数据触发一次模型判断，查看事件记录
    预期：这条模型判断记录里有模型名、提示词版本（或哈希）、输入的 sha256，以及能还原完整输入的原文或引用
A2. 操作：按 A1 记录的内容还原输入，计算 sha256
    预期：与记录里的输入 sha256 一致
A3. 操作：构造「AI 停下后 5 分钟内用户在该会话回了话」的场景
    预期：抑制记录写明对应的抑制原因
A4. 操作：分别构造重复提醒、模型额度用完、首次接入一小时以前的事件
    预期：三条抑制记录各自写明不同的原因
A5. 操作：启动服务后各触发一次模型判断和一次推送，查看事件记录
    预期：两条记录都能对应到当时运行的代码提交号
A6. 操作：构造一个由规则判定为停滞的会话
    预期：记录里写明命中的规则
A7. 操作：模拟飞书回复「漏了」加一句话
    预期：反馈记录除了原话，还带有当时的时间，以及能对应到当时各会话状态的引用
A8. 操作：发出一张卡片，查看卡片记录
    预期：有原会话文件路径、行号范围和这段内容的 sha256；按路径和行号重新计算的 sha256 一致
A9. 操作：用本批之前格式的数据文件启动服务，执行总览和 `stats`
    预期：正常输出，不报错
