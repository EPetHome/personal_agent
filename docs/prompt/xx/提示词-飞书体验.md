## 已拍板

- **卡片格式**（用户 2026-10-26 反馈「看不懂，不能快速定位问题」）：第一屏固定回答四件事，顺序如下，每件一两句话：
  1. **谁**：工具 + 项目名（目录最后一段即可）+ 这个会话在干什么（意图一句话）；loop 写「哪个项目的哪一批，第几轮」
  2. **出了什么事**：一句人话，不用「推送」「对账」「transcript」「来源」这类程序术语
  3. **要不要你管**：要管就写怎么做；不用管就直说「不用管，只是告诉你」
  4. **回去看**：能直接打开那个会话的命令（如 `claude --resume <会话号>`、`codex resume <会话号>`、`pi --session <会话号>`），loop 就给总结文件；不给整个目录，也不给本程序的数据文件
  - 时间一律用本机当地时间的口语写法（如「今晚 23:11」「昨天 18:00」），不用 UTC 的 ISO 格式
  - 内部文件名、行号、判断依据原文、编号只放进折叠的「证据」里
  - 标题一句话说清「谁 + 出了什么事」
- **按钮反馈都要回话**：点了按钮，和发文字一样，要回一句确认或失败原因，不能没有动静。
- **反馈数据只追加**：不改写、不删除已有的收件、处理记录、反馈和经验记录。协调方已经把 3 条时间算错的点击追加标记为已处理（`feishu-receipts.jsonl`），其中两次「误报」已在本机补记，不要再重复记一次。
- **复盘默认开着**：用户 2026-10-26 决定不关复盘；本批只改「第一次不翻旧账」和卡片可读性。

## 验收标准

A1. 操作：用飞书替身送入一次卡片按钮点击（对某条提醒点「误报」），`create_time` 是 16 位的微秒数；跑一轮收件处理
    预期：反馈记录多一条指向那条提醒的「误报」，时间是今天；飞书替身收到一句「已记下」之类的确认
A2. 操作：用飞书替身送入一条处理会失败的收件（例如按钮指向一条不存在的提醒），后面再跟一条「漏了 测试」；启动常驻跑两轮检测
    预期：两轮检测都完成；「漏了 测试」被记下并回了「已记下」；失败那条回了一句说明原因的话
A3. 操作：常驻运行时，让一轮检测长时间占着数据锁（超过 30 秒），期间飞书替身报告「已连上」；之后再送入一条「漏了 测试」
    预期：之后的检测照常完成；「漏了 测试」被记下；总览显示飞书「已连上」
A4. 操作：放入一份停下来问用户的 CC 会话样本（项目 `/demo/shop`，意图「给商品列表加缓存」），判断器替身答「是」；跑一轮检测
    预期：飞书替身收到的卡片：标题写明「shop 的 Claude Code」和「在等你」；第一屏依次有谁、出了什么事、要不要你管、回去看；回去看是 `claude --resume <会话号>`；正文里没有 UTC 的 ISO 时间、没有本程序数据文件路径和行号
A5. 操作：放入一条让 Codex 盯防「看不见了」的情况，跑到提醒发出
    预期：卡片正文用人话说清是哪个项目的哪个会话出了什么事、要不要管；「回去看」不是整个 `~/.codex/sessions` 目录
A6. 操作：在没有任何复盘记录的数据目录里，放入 5 份历史 loop 总结，每份都返修 2 次以上，且同类；第一次打开复盘跑一轮检测；再放入 1 份新的同类总结，跑一轮
    预期：第一轮不推复盘卡片；第二轮推一张，写明是哪个项目的哪一批、返修了几次、为什么算同类
A7. 操作：放入一份 loop 总结样本，最后更新在 40 分钟前，状态「进行中」；同时放入它的评审会话样本，5 分钟前还有记录；跑一轮检测
    预期：不发「没动静了」
A8. 操作：同 A7，但评审会话也在 40 分钟前就没有记录了
    预期：发一条停滞提醒，「最后在做」写的是 loop 当前在哪一步，不是验收标准的文字
A9. 操作：放入一份 Pi 会话样本，项目目录在 `~/.pi-autoreview/pipelines/某批/e2e/r1`，会话号不以 `autoreview-` 开头；跑一轮检测
    预期：总览里没有这份会话，也不对它做判断、发提醒
A10. [人工] 操作：修好后在飞书里看几张真实卡片，点一次按钮
    预期：一眼看懂是谁、出了什么事、要不要管；点了按钮有回应
