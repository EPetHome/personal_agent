# 全新 PA 丙：替你执行、交接简报、自检

本批共 6 段，这是第 3 段，接在「乙 底座和托管 loop」之后。先读[六段共同约定](../batches/全新PA-20261102/共同约定.md)。

## 目标

卡片上能直接动手；PA 停了有人告诉你。对应[方案](方案-全新PA.md)第 4 项里的执行、第 5 项、第 10 项。

1. **执行按钮**：做完卡上 [推到仓库]、[合入]；卡住的批次上 [停掉这批]。都是红线动作：用户点了才做，过围栏、留痕，按结果更新原卡（已推送 / 已合入 / 已停，带提交号）；结果说不清就标不确定，不重发。
2. **推送**：只推批次分支，不推 `main`、不强推；推之前查改动里有没有疑似密钥，有就不推并在卡上写明；远端是公开仓库时卡片按钮上写明。
3. **交接简报**：批次返修到上限或被停掉时写进账本：目标、做到哪、关键决定、遗留问题、代码位置五栏；之后开新批时带上（开批次是第 4 段的事，本段先把简报存好、能查到）。
4. **watchdog**：只报机械事实。派工停了、会话没了 → 进「等你」清单，不推卡；来源看不见、话送不到、PA 自身故障 → 马上发卡。
5. **独立心跳**：launchd 下另一个小任务，主进程心跳太久没更新就弹本机通知「personal agent 停了」；主进程正常时什么都不发。

## 已拍板

- 合入只在用户点 [合入] 后触发；推送、合入、停批次一律不进自动档。
- 推送、合入、停批次通过 worker-adapter 交给 loop 执行（约定见共同约定），PA 不自己跑 git push 或 git merge。

## 边界

- 测试和验收只用测试仓库和测试远端（本机的裸仓库即可），不碰本项目的 `origin`。
- 独立心跳的 launchd 安装沿用现有 `service` 的写法；测试和验收不安装到用户真实的 LaunchAgents，用临时目录或注入。

## 验收标准

A1. 操作：在做完卡上点 [推到仓库]
    预期：测试远端多出这个批次分支；原卡更新为已推送和提交号
A2. 操作：测试仓库里放一个带假密钥的改动，点 [推到仓库]
    预期：不推送，原卡写明「发现疑似密钥，没推」
A3. 操作：在做完卡上点 [合入]
    预期：替身 loop 收到合入请求；原卡更新为已合入和提交号
A4. 操作：在卡住的批次上点 [停掉这批]
    预期：替身收到停止请求；原卡更新为已停；账本里多一份交接简报，五栏齐全
A5. 操作：替身 loop 的某一段会话消失，事情还没做完
    预期：「等你」清单里多一条「这件事没人在做了」，不推卡
A6. 操作：让替身的送话通道失败
    预期：马上收到「话没送到」的卡
A7. 操作：让主进程停止更新心跳，超过设定时长
    预期：本机收到一条「personal agent 停了」通知，来自独立心跳
A8. 操作：主进程正常运行一段时间
    预期：独立心跳不发任何通知
