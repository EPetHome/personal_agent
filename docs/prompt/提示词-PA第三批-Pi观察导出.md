# PA 第三批：乙·Pi观察导出

## 目标

交付可选择加载的独立 Pi 只读观察扩展：按明确范围导出可信的会话/执行回合记录，供甲消费。附隔离验证和真实部署时可用的预检、启用、停用与恢复办法；本次不实际安装到本人 Pi 或导出真实内容。

阅读顺序：本提示词 → [本批方案](方案-PA分批推进.md)第三、四、六节 → [统一验收](../batches/PA第三批工作跟踪-20261108/整批验收标准.md) → 对应原单和必要源码。只在 Loop 为本任务登记的独立工作区工作，不改项目根、其他任务空间或正式运行目录。

本批已确认的是方案范围，不包含合入、推送、部署、真实 Pi 扩展安装/重载、读取真实会话或新增项目权限。A1/A2/A5 待真实用户另行授权；开发自检只用构造材料、本地模型/渠道替身，不读取凭据文件或试调真实业务模型。程序测试和语义效果分开报告。

保留原 auto/yolo 和明确 deny；read/edit/write/bash 足以完成本任务，不恢复 codex-pi，不安装无关扩展或升级依赖。依赖/准备沿项目 preparation 与既有 lockfile；Loop 测试节点已提供隔离工作区，不在固定测试命令内再创建副本或复制整仓。

原需求重点：[事项分层单第 9.1—9.2 节](../../issues/【req】PA事项分层与渐进式感知.md#91-用户独立启动的-pi新增场景方案待确认)。先定向核对当前本机 Pi 安装包扩展事件/SessionManager 的公开声明；目录名不当版本结论。实现和验证只在构造 Pi 会话内，不读取本人历史日志或凭据。

## 已拍板

- 采用方案第四节固定的版本 1 JSON 记录，生产者与 PA 消费者不互相导入源码。session/instance/execution/revision 明确；普通字段变化原子替换，租约每 30 秒刷新，不无界复制历史。
- 读取源与导出字段分别许可。默认有限运行元数据；任务定义/结果引用按明确范围导出，不写思考过程、完整会话、工具全文、凭据、附件或环境。来源自报项目名、路径不构成授权。
- 依据真实 session_start、agent_start、交互等待、agent_settled、session_shutdown 等能力；agent_end 之后可能续跑，不能据其报完成；settled/closed 也不代表业务完成。切换、分叉、恢复和同会话多件事保留身份，不凭标题猜关联。
- 观察扩展不改变原工作、原 auto/yolo、权限、模型、命令或网络能力；导出失败不得阻塞/终止原任务。PA 停止观察不能停止用户 Pi。没有获准业务内容时只导出运行观察。
- 旧会话未加载扩展时保持“未接通”；只在构造环境核对受支持的安全加载/恢复方式，不重启或重派真实工作凑接入。

## 边界

实现放在 `code/agent/scripts/pi-observer.mjs`，必要部署准备放 `code/agent/scripts/prepare-pi-observer.mjs`，生产者检查放 `code/agent/test/pi-observer.test.ts`；可以在上述文件内复用必要小函数，不引入通用插件平台/新依赖或修改 Pi 安装包。只改卡上的范围，不动 PA 共用源码、配置样例、甲测试、Loop 仓库或任何正式配置。

部署准备默认只预检并给出具体变更；显式 apply 才写指定目标，变更前备份，按已知前后摘要恢复，不覆盖后续改动；不将启动器/权限环境强改为逐工具确认，也不以本次准备为授权加载真实扩展。演练一律在构造目录和本地渠道/模型替身完成。

使用说明只追加“独立 Pi 观察导出”章节；结果只写 `docs/batches/PA第三批工作跟踪-20261108/结果.md` 的“乙：Pi观察导出”节。说明哪些原生模式已构造验证、未接通的旧会话怎样显示，不以扩展存在或可解析冒称真实安装成功。

不得改卡、提示词、统一标准、需求、规则或本机配置。开发完成后原会话交付，由 Loop 程序提交；不手工提交、合并、推送或部署。

## 验收标准

负责统一标准 A4，配合 A7 的实际记录对接；A7 在汇总树归甲核实，若根因在导出则依证据返修乙。操作和预期只认统一标准。构造会话中真实触发事件，不能只手写最终 JSON 代替生产者行为验证。
