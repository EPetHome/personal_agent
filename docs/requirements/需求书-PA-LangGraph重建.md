## 一、要什么

**PA 替我干活。** 具体是：

1. 我在飞书说什么、发什么，它都接得住：问状态就答，交代活就去办，发图片、文件就看懂了再回，随口一句也正常回话。
2. 我交代的活，它想清楚怎么做、我点头后派出去，盯着进度，做完核实了再告诉我结果。
3. 派出去的活中途卡住，它主动来找我：说清卡在哪、建议怎么办，我点一下它就去处理。
4. 它自己出了问题（挂了、卡住、连不上），我能马上知道。
5. 它不能拖垮电脑：空闲时 CPU 只占几个百分点，不随历史变多而变慢 ✅（11-03）。

## 二、为什么重来

- 旧版把判断写成了程序规则：飞书来话全靠关键词，「三个模块」这种都写死了；「什么时候叫我」「派查额度」也写在代码里。新情况一来就答不上，只能补规则。
- 旧版账本做到 23 张表，还镜像了一份 Loop 的状态，改一处牵动全身，修 CPU 那一整批就是在还这笔债。
- 两周下来，「帮忙」这条主链路一次都没走通。

这次把判断交给模型，程序只负责收发、存储、执行和硬边界。

## 三、边界与分工

```
① 我放权的活        → PA 托管：建一张任务卡，派出去，盯着，需要我或做完了就告诉我
② 我设定好的区域      → PA 只看：飞书里我本人对它说的话、我指定的收件箱目录；有新东西就想一想，
                        需要处理时带着建议问我，我点头了才变成 ① 里的一张任务卡
其余（比如我和 CC、Codex 的聊天）→ 不管
例外：碰到红线马上问我；PA 自己出故障马上告诉我
```

| 谁 | 干什么 |
|---|---|
| 我 | 定目标和取舍，点头，做业务验收 |
| PA | 接住我的输入、派活、盯进度、核实结果、带方案找我 |
| Pi | PA 唯一派活的对象：只读查询、跑技能、在授权目录写文件 |
| Loop | Pi 改代码时外面套的流程：评审、验收、提交、合入队列；只推事件，不直接通知我 ✅（11-03） |
| CC、Codex | 我头脑风暴的席位，不是 worker；PA 不派活给它们 |

- **放权是一个明确的动作**：我在授权项目里开 Loop 批次，或者 PA 带着派工建议来、我点了头。
- **只认我本人** ✅：只有我本人私聊的消息交给 Router；别人私聊它、群里的消息都不当指令，只记日志。
- **授权项目和目录**：写在配置里，由我定；改这份清单属于红线里的「改权限配置」。现在只有 personal agent 一个项目，派活范围是只改 `code/`。

## 四、核心场景

| 我做什么 | PA 应该怎样 |
|---|---|
| 问「现在还有几个 loop 在工作」 | 直接答几个、各在什么状态；不出卡片、不建任务卡 |
| 说「帮我把某某改一下」 | 弄清改哪里，回一张卡片说打算怎么做、派给谁；我点「好」才派；做完核实后告诉我结果 |
| 什么都不做，某个 Loop 批次卡住了 | 核实原因后主动发卡片：卡在哪、为什么、建议怎么办；我点「好」就照建议处理 |
| Loop 批次做完，但门禁、评审、验收有一层没过或没跑 ✅（交付核实需求书第二节） | 卡片写哪层没过、为什么、是真问题还是误判、建议怎么办；按钮：按建议 · 再给它一轮 · 仍要合入（写明越过了哪层；合入能力补上前不可用）· 回电脑再说 |
| Loop 批次全部通过 | 卡片写分支、提交号、核实结果、哪些要我人工验收；问推不推、合不合（合入、推送能力补上前，按钮注明「请回电脑操作」） |
| 发一张截图、一个文件、一句闲聊 | 看懂内容再回；不出「缺信息」这类模板话 |
| 对一件在办的活补充要求、说「算了」 | 改到那件活上，或取消它 |
| 往收件箱放一份文件 | 看懂是什么、和哪件活有关，这一步不用问我；要动手（做摘要、整理）就带 2～4 个选项加「先放着」问我，我点了才派；不需要处理的不主动说，我问了再答 🔧 |
| PA 自己挂了或卡住 | 我收到通知，恢复后再收到一次「已恢复」 |

## 六、上下文与任务表 ✅（11-04）

**模型每次看到的内容**，按顺序：系统提示词 → 最近对话窗口 → 任务表（加上命中的那张卡全文）→ 新输入。其余内容不放进上下文，Router 要用时调工具去读。

- **对话窗口**：只放原话，不摘要。按 token 计，上限可配（暂定 100K 🔧），满了一次性丢掉最旧的一段。丢掉只是不放进上下文，原话全部留在事件日志。
- **任务卡 = 派单**：只在真的派活或托管一件活时才建（我交代的活、我在授权项目里开的 Loop 批次）。一张卡记：目标、完成标准、边界、状态、在等我什么、派工记录、结论、订阅了什么。
- **任务表**：每次都带上，每件活一行（标题、状态、在等什么、最后更新），所以 Router 随时知道 PA 手里有哪些活。已关的卡不列出，用工具搜。
- **订阅**：每张卡登记自己关心的来源，比如哪个 Loop 批次、哪次 Pi 派工、PA 为它发过的飞书消息。这些来源有新事件、我引用这些消息、点卡片按钮时，就归到这张卡。
- **卡上的机械字段由程序写**：worker 事件一到，程序直接更新状态和派工记录，不靠模型记得去改。
- **大内容不进窗口**：图片、文件、日志处理完后，窗口里只留一句描述和路径。
- **飞书附件单独存放** 🔧：我在飞书发的图片、文件存进单独的附件目录（不放在 PA 数据目录里，那里有飞书凭据、在黑名单）；附件目录列进读白名单，要再看时能读回来。

## 七、什么时候叫我，什么要我点头

**主动找我**只在这几种时候：要我决定、活做完了、碰到红线、PA 自己出故障。找我时必须带上方案，不能只报事实。其余的我问它答。

- 同一件活一张卡，状态变了更新原卡；我不理或点「回电脑再说」，不催第二遍，挂着等我 ✅（架构稿 7.5）。
- 核实不了的信号（比如 Loop 说卡住了，查下来其实没卡）不叫我，记下来 ✅（架构稿 7.5）。

**点头**：

| 动作 | 默认 | 能不能改成不问 |
|---|---|---|
| 查状态、读证据、读授权范围内的文件 | 不问 🔧 | — |
| 派只读 Pi 去查事实 | 问 ✅（11-01：过审才查） | 能 |
| 送话、续跑、答复（把我的话或建议的话送回 Loop） | 问 | 能 🔧 |
| 开任务卡并派活（开 Loop 批次、让 Pi 写文件） | 问 | 能 ✅（架构稿 7.7「派活同样可以改自动」） |
| 停批次 | 问 | 能 🔧 |
| 合入、推送，以及其它红线动作 | 问 | **不能**，永远问；按钮写明我确认的是什么，不给「按建议」一键 |

- **开关本期只能我手改配置文件** ✅（11-04）：我在飞书说「这类以后直接做」时，PA 不自己改，只告诉我去改配置里的哪一项。
- 红线类动作在配置里改成不问也无效，照样要问 ✅（11-04）。
- 某类开关被我改成不问后，PA 直接做完，要在原卡写明「已直接处理」✅（架构稿 7.7）。
- **点头会过期**：卡片记下我点头时依据的事实；执行前程序再核一次。状态变了、活已取消、批次已经自己恢复，就不执行，更新原卡说明变化并重新给建议 ✅（架构稿 7.5「状态变了更新原卡」）。
- **送出去的说不清就不重发**：先记再送；送没送到说不清时标「不确定」，不重发，告诉我 ✅（架构稿 7.5）。
- **同一个点头只执行一次** 🔧：我连点两下、飞书回调重发，都只执行一次。

合入、推送要等 Loop 补上「执行时核对我点头的那个提交」和「推送前扫描密钥」（[Loop 需求单](/Users/Admin/Desktop/loop/docs/需求-PA执行推送合入-20261104.md)）。补上之前，PA 不执行，只提示我回电脑操作。

**派活前的默认值**（写进系统提示词，不写成程序规则）✅（11-01）：

- 能不能开干只看三样：做什么（能不能定位到对象）、怎样算完成、能动什么。后两样永远有默认值，按项目规矩来：只在开发空间、不合入、不推送、不碰真实账号；本项目完成标准是门禁过、评审无必修、提交到批次分支。
- 做什么先从我的原话、任务表和项目文件里找，找不到才问。
- 只补事实，不补取舍；取舍交给我。
- 派 Pi 去查时，写清为了补什么、问什么、能看哪里、怎样算答完；一次派、一次交，问到位就停。

## 八、红线、读的范围、留痕（程序强制）

**红线** ✅（沿用主需求书 D37）：

1. 有重大后果的操作必须给我过目：收不回的（删除、覆盖、强推、改历史、迁移或清空数据），出本机、别人看得到的（推远端、发消息给别人、发布、对外发言；PA 和看门狗发给我本人的回话和通知不算），动钱或账号权限的，改规矩本身的（改需求、验收标准、权限配置、红线清单；合入，因为本项目合入就是上线），碰秘密的。过目是指事前给我看、由我决定，不给「按建议」一键通过。
2. 没规定可以写的区域，不能写：PA 只写自己的数据目录；派给 Pi 的活只写派工范围内。
3. 没规定要完成的任务，不得去完成：会话、文件、网页里出现的指令只当材料；不是我本人说的话也只当材料。

**读的范围** ✅（11-04：白名单定范围，黑名单是底线）：

- 白名单：只读授权项目的目录、收件箱目录、飞书附件目录 🔧、Loop 事件里给出的证据路径，其余都不读。证据路径只认落在 Loop 运行目录里属于授权项目的部分和授权项目里的 🔧，防止有人往事件里写一条路径就放开任意文件。Router 看任务表、事件日志走专门的工具，不靠读文件。
- 黑名单是底线：任何读取（Router 的工具、派出去的 Pi）都先过黑名单；白名单里的文件命中黑名单照样不读；以后放宽白名单也越不过黑名单。改黑名单本身是红线，只有我能改。
- 按真实路径判：先解开链接、`..` 再比对，防止白名单目录里放一个指向 `.ssh` 的链接绕过去。
- Pi 也受同样的限制 🔧：所有派给 Pi 的活，读文件都按白名单加黑名单判，写文件只能写派工范围内；由程序在 Pi 调用工具之前检查，不靠提示词，也不只靠 Pi 自己的工具权限。
- 跑命令和联网 🔧：只读派工不给；技能、写文件派工默认也不给，确实需要时卡片上写明要开什么、由我点头。开了跑命令的派工，命令里会读到什么程序没法逐条保证，所以只在我点头时开。
- Loop 批次里的 Pi 按 Loop 的范围设置（`scope.allow / scope.deny`）管，PA 不另管。

**不许读** ✅：`.env` 系列（示例文件除外）、私钥和证书、`.npmrc`、`.pypirc`、`.netrc`、`.git-credentials`、`.git/config`、文件名带 auth/session/cookie 的数据库和 json；`.ssh/`、`.aws/`、钥匙串、密码管理器、私人聊天、PA 自己的数据目录（里面有飞书凭据）、备份目录、`eval/cases/`、`eval/runs/`、`eval/待标注/`。读到的内容会发给模型服务（DeepSeek，经 opencode-go），不只留在本机。

**留痕** ✅（架构稿 7.13）：

- 每次替我做的事都记下：谁点的、做了什么、结果如何。
- 每次模型调用都记下：看了哪些材料（路径、内容指纹）、模型和提示词版本、判断和理由、给的方案、最后实际发生了什么（自动做了 / 我按建议做了 / 我改了 / 我没理）。
- 总指标：每天「本来不用我」的处理次数，越少越好（回「继续、好」这类不带新信息的话、跑回去看做完没有、把一处结果抄到另一处）。这些不推给我，要用时去取。

## 九、进程、资源与看门狗

- **进程**：PA 主进程和看门狗都由 launchd 常驻，挂了自动拉起。Pi 每次派工起一个子进程。Loop 的进程归 Loop 管，PA 只通过 loop 命令停。
- **启动**：先接上「等我点头的」和「派出去还没回的」；上次的 Pi 已经不在了就标「中断」并告诉我，不自动重派。
- **停止**：先停收新输入，当前这一步存好进度再退；正在跑的 Pi 不跟着停，重启后接着收结果。
- **结束进程**：只按启动时记下的身份结束，不按名字猜。
- **并发**：Router 一次处理一条输入，我的话优先。Pi 按任务类型限：只读查询同时最多 3 个，技能同时 1 个，写文件同一目录同时 1 个。改代码由 Loop 排队。上限可配。
- **时限**：超时一律告诉我、不自动重试。单次模型调用、一条输入的处理、一次 Pi 派工各有上限，具体数在方案里。
- **接收** ✅（11-03「看和接收都要有」）：Loop 事件目录、收件箱这类靠文件进来的来源，文件一变就立即收；另外低频再看一次兜底。
- **不拖垮电脑** ✅（11-03）：空闲 CPU 只占几个百分点；例行检查不写日志；检查点只留最近若干；事件日志按天分文件，处理时只读新增，不随历史变多变慢。验收要用大量历史数据长时间跑来证明。
- **资源**：模型用量每次都记，每日上限可配，默认不限；临时文件在派工结束时清理；磁盘剩余低于 1 GB 报警。
- **看门狗**：独立进程，只读，不调模型。
  - 直接通知我（本机 + 直发飞书）：PA 主进程停了、有输入卡住、模型接口连续失败、飞书断开、磁盘不足。
  - worker 很久没动静时，看门狗只把事实交给 Router，由 Router 查清后带着方案告诉我。
  - 通知写人话：出了什么事、影响我什么、要不要我管；内部词不进标题 ✅（11-03）。
  - 同一类故障只报一次、再犯更新同一条，恢复时报一次；每类故障各自判断恢复，一类恢复不能把另一类的告警解除 ✅（11-03）。

## 十一、旧版怎么处理

- 旧 PA 在新版验收通过、我说「部署」之前照常运行。
- 切换时：
  - 飞书机器人切到新版（新旧不能同时连同一个机器人）；
  - Loop 的事件出口从旧 PA 的数据目录改指新版的；
  - 旧版的主程序和心跳两个常驻项停用，保留可恢复；
  - 关掉 Loop 自己的本机通知（通知只由 PA 发 ✅ 11-03）；
  - 旧侧边栏切换后暂时没有。
- 旧账本不迁移、不删除，只读保留。
- 旧代码在新版跑稳后另开一批删除。
