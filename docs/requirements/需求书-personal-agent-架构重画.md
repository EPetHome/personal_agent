# 需求书：personal agent 架构重画（讨论稿）

资料核对：2026-11-01。状态：**讨论稿，未拍板**。来源：研读 DeepSeek Super-agent（下称 S-A）的公开原型文档，再对照本项目代码、[主需求书](需求书-personal-agent.md)和[第二阶段需求书](需求书-personal-agent-第二阶段.md)。本文件不替代这两份需求书，乙「放出智能」照常进行。标记：✅ 用户定的；🔧 协调方暂定，用户可改；❓ 要用户定。路线图里的「以后」都是布局，不是开工计划。

## 一句话

从「扫会话、看到状态就发卡片」的监视器，变成**按事情记账、替我搬运、只在该问的时候带着选项来问我**的中枢。

## 为什么重画

两类问题，根子都在结构上，不在规则上。

**一是打扰。** 「叫与不叫」改了很多批：在场判断、等 5 分钟、合并提醒、按我在哪分三种、卡片格式改 5 批，结果仍有 98% 是无效提醒。协调方核对代码，原因如下：

| # | 根子 | 代码里的样子（协调方核实） | 后果 |
|---|---|---|---|
| 1 | **状态等于卡片** | `judge.ts` 的 `planNotices`：会话状态是在等我、疑似跑偏、停滞、loop 暂停或完成，就直接对应一种卡片 | 看出一个状态就发一张。「值不值得叫我」没有一层专门判断，只能事后打补丁 |
| 2 | **单位是会话，不是事情** | 记录按「工具 + 项目 + 会话」组织；意图卡只写在需求里，还没有这个对象 | 一件事跨几个会话就是几张卡；没有「这件事要的是什么」，就判断不了欠不欠我 |
| 3 | **把我在驾驶的会话当成托付出去的活来盯** | 甲用「最后一句话离 AI 停下不到 10 分钟」来近似区分 | 我正在聊的会话也会叫我。S-A 盯的是托管出去的活，几乎没有这个问题 |
| 4 | **一个循环包办所有事** | `agent.ts` 的 `detect()` 每轮串行做完：全量扫文件、和 hook 推送对账、规则判断、发卡片、模型判断、再发卡片、维护 | 每轮 85～196 秒；对账部分的代码最复杂；改一处牵动全身 |
| 5 | **信号靠猜** | 「在等你」主要从会话文本、最后一句回复推断 | S-A 明确否决「从自由文本推断在等人」，要求执行方用结构化字段提问 |

**二是没减负。** 第二阶段起因（D34）就是这一条：personal agent 只是流水线上的传递工，卡片陈述了事实，搬运还得我自己来。基线那一周（10-25 至 31）里，「粘贴材料」31 次、「同样开头的状态转述」18 次，很可能就是我在会话之间人工搬运；「不带新信息的短回复」33 次。只会研判、不会搬运，减不了负。

### 数据：存什么、放在哪、给谁用（🔧 协调方暂定）

按「跟着谁走」分四类。意图卡**跟着事情走**，存在账本里，不在全局记忆中。

```
┌─ A 账本：每件事的数据，随事情生灭（ledger）
│
│   事情 ─┬─ 意图卡（1 张，有版本）      我要什么：7 栏
│         ├─ 状态                      在做 / 等你 / 完成……从派工和事件推出
│         ├─ 待你决定（0～n 个）        要我回答的具体问题，带选项
│         ├─ 派工（1～n 次）── 会话     谁在做、驾驶还是托付
│         └─ 线索（1～n 条）── 事件     和这件事有关的会话、材料、IM 对话
│   事情 ── 上级事情                   子卡继承上级卡的总目标（第二阶段第 3 件）
│
├─ B 全局记忆：跨所有事情、长期有效，只有我确认过的才进
│   规则参照：我的标准、我对同类问题的回法、wiki 里确认过的经验 [现]
│   偏好、我在忙什么、人 [后]
│
├─ C 围栏配置：只有我能改，改它本身就是红线
│   红线清单、不许读名单、每一类动作的档位
│
└─ D 观测记录：只增不改，用来证明和找问题
    研判记录（看了什么、怎么判的）、影子记录、对照与标注、拦下的读取、送达记录
```

| 数据 | 谁写 | 谁读 | 用来做什么 |
|---|---|---|---|
| 意图卡 | assessor 起草，我确认 | assessor、guard、router | 这件事的标准：欠不欠我、有没有跑偏、动作在不在范围内 |
| 待你决定 | assessor 提出，gate 决定何时给我看 | gate、channel | 全系统唯一能打扰我的东西 |
| 派工 | worker-adapter | ledger、router、watchdog | 写入的对象；谁在做 |
| 线索、事件 | intake | ledger、assessor | 事实依据 |
| 规则参照 | 协调方归纳，我确认 | assessor | 跨事情的判断依据：同类问题我以前怎么定的 |
| 偏好、在忙什么、人 | 以后再定 | assessor、gate | 以后用来排优先级、选时机 |
| 红线、不许读、档位 | 只有我 | guard | 硬边界 |
| 观测记录 | 各部件追加 | 我、协调方、评测 | 放权的证据：影子和我一致几成 |

**意图卡和规则参照的区别**：意图卡回答「**这件事**我要什么」，事情结束它就归档；规则参照回答「**一贯以来**我怎么定」，跨事情、长期有效。比如「这批只改测试、不碰产品代码」写在意图卡上；「合入前必须给我过目」写在规则参照里（这一条同时也是红线）。

**数据怎么流动**：观测记录里攒下的对照结果，由协调方归纳成规则候选，经我确认后进入规则参照（第二阶段第 4 件）。意图卡不会自动变成规则，影子结论也不会自动写进任何长期数据。

### 层级与依赖（🔧 协调方暂定）

上面那张图讲的是「有什么」，这一节讲「谁依赖谁、谁能碰谁」。

```
 第 0 层  外部        你 · IM · 指定目录 · worker（CC / Codex / Pi / loop / skills）
          ─────────────────────────▲──────────────────────────────▲─────────────
                         读 │       │ 写给你                  读 │ │ 写给 worker
                            ▼       │                            ▼ │
 第 1 层  接入（程序）  intake ── channel                 worker-adapter
          只有这一层碰外部                 ▲                       ▲
          ──────────────│──────────────────┼───────────────────────┼─────────────
                        │ 记成事件          │ 取「待发」             │ 取「待写」
                        ▼                  │                       │
 第 2 层  账本（程序）  ledger：事件 · 线索 · 事情（意图卡） · 派工 · 待你决定 · 档位 · 待发 / 待写
          唯一存状态的地方
          ──────────────│──────────────────▲───────────────────────▲─────────────
                        │ 读               │ 写结论 / 写指令          │
                        ▼                  │                       │
 第 3 层  决策          assessor（模型）── 结论 ──┘                    │
          不存状态，      gate（程序）────── 打扰 / 陈列 / 汇总 → 待发    │
          彼此不直接调用   router 行动（程序）── 转达 / 代答 / 接力 → 待写 ┘

 横切     guard：第 3 层产出的每条「待发」「待写」，在第 1 层发出前都要过它（红线、档位、留痕）
          watchdog：读第 1、2 层的机械事实，只写回账本；不发消息
```

**五条规矩**：

1. **状态只存在账本里。** 其他部件都不存状态，重启后从账本恢复（S-A 也一样：研判不持有状态）。
2. **只有接入层碰外部。** 决策层不直接调用外部；例外是 assessor 可以只读会话原件和项目文件，但要受不许读名单约束。
3. **决策层之间通过账本通信，不互相调用。** assessor 把结论写进账本，gate 再去读，这样「想」和「说」在结构上就是分开的。
4. **对外只有两个口：channel（给你）、adapter（给 worker）。** 决策层只能往账本里写「待发」「待写」，由接入层取出发送：先存后做，发出前一律过 guard。
5. **依赖只能向下。** 第 3 层依赖第 2 层，第 2 层依赖第 1 层；下层不知道上层的存在。所以加一个新来源，只改第 1 层；换一个模型，只改 assessor。

| 部件 | 读谁 | 写谁 | 不能碰 |
|---|---|---|---|
| intake | 外部来源 | 账本（事件） | worker、你 |
| ledger | 自己 | 自己 | 外部 |
| assessor | 账本；只读的原件 | 账本（结论） | 外部写入、channel |
| gate | 账本 | 账本（待发） | 外部 |
| router 行动 | 账本、档位 | 账本（待写） | 外部 |
| guard | 待发、待写，意图卡，红线 | 放行或拦下，留痕 | — |
| channel | 待发（已过 guard） | 你 | worker |
| worker-adapter | 待写（已过 guard）；worker 的信号 | worker；账本（派工状态） | 你 |
| watchdog | 第 1、2 层的事实 | 账本（事实） | 外部 |

**建设上的依赖**（前一样没有，后一样就做不了）：

```
事件 [现] ─→ 线索 ─→ 派工（认领）─→ 事情 + 意图卡（你确认）─→ gate 按事情把关
                       │                    │
约定标记 ──────────────┘ 派工状态不靠猜      └─→ 代答、接力（要有标准才能放权）─→ 派活
assessor（乙）──→ 欠不欠我 ──→ gate
独立心跳：不依赖任何部件，随时可以单做
```

## 设计尺子

借用 S-A 的第一原则：**用尽量少的我的注意力，换尽量多的价值。**

- **举证倒置**：每种卡片、每个设置、每段卡片内容、每个信号源、每个新功能，都要证明「给的价值 > 花掉的注意力或复杂度」。证明不了就删掉，不再往里投入。
- **多一层就多一个维护点**：没有需求证明，不加层。
- **概念要少**：新需求先变成已有概念的一个属性或一段提示词，不新增概念。
- **嫌吵就删**：不用新消息去解释噪音。

## 命名（🔧 协调方暂定）

规则：**只有替我干活的才叫 worker**。名字按「做什么」取，不按「用什么实现」取。

| 名称 | 是什么 | 能不能对外写或发 |
|---|---|---|
| intake（感知层） | 把各种来源记成事件 | 不能 |
| ledger（事情账本） | 事件 → 线索 → 事情，推出状态 | 不能 |
| assessor（研判 agent） | 按需启动的只读 Pi，想清楚这件事 | 不能，结论只写回账本 |
| gate（闸门） | 全系统唯一能决定打扰我的地方 | 只能交给交互面 |
| hub（中枢） | 现在的中枢：ledger + assessor + gate | — |
| router（路由中枢） | 以后的中枢：hub 再加 relay、handoff、answer、dispatch、dialog | 经 worker-adapter 写给 worker，过 guard |
| relay / handoff / answer / dispatch / dialog | 转达 / 接力 / 代答 / 派活 / 对话 | 见「中枢的职能」 |
| channel（交互面） | 本机通知、飞书、以后的微信和侧边栏 | 只发闸门交来的 |
| worker（执行 agent） | CC、Codex、Pi、loop、skills、LLM Wiki | 是我的工具，personal agent 不管它内部 |
| worker-adapter（执行适配器） | 程序，对接中枢和 worker：认领、收报告、送话、接续，以后加启动、停止；维护派工 | 只做中枢交给它的写入 |
| 派工（assignment） | 一件事和一个 worker 会话的绑定：谁在做、驾驶还是托付 | — |
| guard（围栏） | 红线、不许读、权限档位、留痕、撤回 | 只拦截 |
| watchdog（盯防） | 只认机械事实：派工停了、看不见、话送不到；也盯 personal agent 自己 | 不能，事实写进账本，交闸门 |

「研判」沿用 S-A 的叫法（Assessment）。不叫 judge，因为代码里已经有 `judge.ts`（规则判断）。router 这个名字留给中枢真正开始搬运、派活的时候；S-A 的 router 是 agent，我们现在的中枢以程序为主，提前叫 router 容易误解。

## 核心概念（六个）

| 概念 | 是什么 | 对应 S-A | 规则 |
|---|---|---|---|
| 事件 | 某时某处发生了一件事，写下就不改。比如「CC 会话 X 在 10:03 停下」「我在会话 Y 说了一句话」「收件箱里多了一份录音」 | Trigger | 状态都从事件推出来；事件本身不做判断 |
| 线索 | 一个来源里的一串东西：一个 AI 会话、一份材料、一段 IM 对话 | Thread | 靠来源自带的身份归并（会话 ID、文件路径、IM 话题），不靠模型猜 |
| 事情 | 我要的一件事 = 意图卡（第二阶段第 3 件的 7 栏）+ 关联的线索 + 状态 + 待你决定的问题 | Ticket + Mandate | 状态由事情自己定义，不跟着某条线索走；线索结束了，事情可以还没完 |
| 待你决定 | 挂在事情上、需要我的一个具体问题，带选项 | Attention | **全系统唯一能打扰我的东西**；一次一个，写清楚要我做什么 |
| 派工 | 一件事交给某个 worker 会话来做的一次绑定：哪个 worker、哪个会话、驾驶还是托付、状态 | Assignment | 一件事可以前后有多次派工；派工结束不等于事情结束；**写入只能指向一条明确的派工** |
| 档位 | 某一类动作现在是影子、建议还是自动 | 主动接活的三种模式 | 按「来源 × 动作」分别计（D15）；升级慢，降级快 |

一件事可以有多条线索：loop 的开发和评审、换了一个会话接着做、相关的会议录音。一条新线索第一次出现、还不知道属于哪件事时，才需要 assessor 判断。

线索和派工的区别：**线索是「看」**，凡是和这件事有关的都算，包括只拿来参考的材料；**派工是「谁在做」**，是转达、代答、接力能写进去的唯一对象。S-A 也是这样分的：订阅只给上下文，派工才承担执行。这样分开，就不会把话送进只是被参考的会话里。

以工作区为例：

规则 🔧：

- 能自己判断的不问；要问就带 2～4 个选项，加上「先放着」。
- 问的时机由闸门决定，见下一节。

## 闸门：打不打扰、何时、用什么方式

### 只有「待你决定」能打扰我

| 来源 | 例子 | 方式 |
|---|---|---|
| 红线 | 要推送、删除、合入 | 马上打断（第二阶段第 6 件，不变） |
| 盯防出故障 | 某个来源看不见了 | 马上打断 |
| 托付的事情卡住了，且 assessor 判断欠我 | loop 暂停等我定；托付的会话停下来问我 | 按第二阶段第 9 件的等候时间和渠道 |
| 新材料、新线索要我选怎么处理 | 上面的录音 | 陈列，空档时再提 |

其余的都不打扰，进每日汇总，或者什么都不发。

### 三种方式

| 方式 | 是什么 | 用在哪 |
|---|---|---|
| 打断 | 本机通知、飞书推送 | 红线、故障、托付的事卡住且我不在 |
| 陈列 | 放在那里，我想看时看，不响 | 带选项的问题、进展；以后放在侧边栏 [后] |
| 汇总 | 每天一条 | 替我挡掉的、做完的、影子和我一致几成 |

侧边栏的价值就在于「看得见但不打断」：很多现在只能二选一（叫我 / 不叫我）的事，可以先放到陈列里。

## 驾驶和托付

| | 驾驶 | 托付 |
|---|---|---|
| 是什么 | 我正在和它来回聊 | 交出去让它自己干：loop、后台 agent、我说「你去做」以后就走开的会话 |
| 谁在看 | 我自己 | 没人在看，这才需要 personal agent |
| 停下时 | **不打扰**，没有「在等你」 | 按「待你决定」处理 |
| personal agent 做什么 | 记账（事情、意图卡草稿）；红线照旧马上叫 | 盯进度、判欠不欠我、能消化就消化 |

驾驶和托付是**派工的一个属性**，不新增概念：同一个会话可以先驾驶、我走开后转为托付。

❓ 怎么认托付：

- A. 明确标记：loop 天然是托付；其他会话由我说一句「你去做吧」，或者打一个约定标记。
- B. 自动推断：我在这个会话沉默超过一段时间，就转为托付（和甲现在的近似一样）。
- C. 两者结合：明确标记的直接算托付；没标记的按 B 推断，只走影子，不打扰我。

🔧 协调方倾向 C：明确的部分不用猜，推断的部分先不打扰我。

## worker 和 worker-adapter（✅ 2026-11-01）

| 做法 | 样子 | 判断 |
|---|---|---|
| 再套一层 agent | 中枢 → 一个 Worker agent（比如 Pi）→ 再去驱动 CC、Codex | 一般不要：多一个模型的费用和等待；我的意思要多传一手，会走样；CC 自己就会规划、开子 agent，这一层是重复的；驾驶会话里我直接和 CC 说话，这一层插不进去 |
| 套一层程序 | 中枢 → 每种工具一个 worker-adapter（启动、接续、送话、收报告）→ worker | **默认用这个**：多一层就多一个维护点。S-A 的执行器、Sig 的 PiAdapter 和 ClaudeAdapter 都是程序 |
| 一件事要跨几个工具接力 | 比如调研 → 写作 → 做 PPT，或者开发 → 评审 → 验收 | 这时才值得有一层专门负责这件事的编排。loop 就是开发这件事的编排层，所以 loop 是一个整体 worker |

## 派工：事情和 worker 的绑定（🔧 协调方暂定）

### 派工记什么

| 字段 | 例子 | 用途 |
|---|---|---|
| 事情 | 「personal agent 第二阶段乙」 | 这次派工替哪件事干活 |
| worker | CC / Codex / Pi / loop / 某个 skill | 决定用哪个 adapter |
| 会话身份 | 会话 ID 和工作目录；loop 用批次名 | 送话、接续都靠它找到对方 |
| 怎么来的 | 认领：我自己开的会话，adapter 发现后挂到事情上；派出：中枢派的 [后] | 第二阶段只有认领 |
| 模式 | 驾驶 / 托付 | 闸门据此决定打不打扰 |
| 状态 | 在做 / 停下等你 / 交回结果 / 结束 / 看不见 | 由 adapter 上报的结构化事实推出，不从文字猜 |
| 最近报告 | 【状态】约定标记、loop 事件、hook 事件 | assessor 和 watchdog 的依据 |
| 能力 | 能不能送话、能不能接续 | 不能送话的，router 只能建议，不能代答 |

### 规则

- 一件事同一时间可以有多次派工，比如 loop 在开发，我在另一个 CC 里调研同一件事；但每次写入（转达、代答、接力）只能指向其中明确的一条，指不清就问我。
- 派工结束不等于事情结束；事情结束，派工一并结束。
- 换个会话接着做：结束旧派工，开一个新派工。handoff 生成交接简报（目标、做到哪、关键决定、遗留问题、代码位置），新会话自己去读细节，不复制全部历史。这是参照 Sig 的做法。
- 认领的会话属于哪件事：同一个会话 ID 靠结构身份直接挂；新会话由 assessor 判断，拿不准就先不挂，不猜。

### adapter 在派工上做什么

| 动作 | 是什么 | CC | Codex | Pi | loop | skills |
|---|---|---|---|---|---|---|
| 认领 | 发现一个新会话，交给 ledger 挂到事情上 | [现] hook | [现] hook | [现] 扩展 | [下] 状态事件 | [后] |
| 收报告 | 把 worker 的信号翻成派工状态 | [现] | [现] | [现] | [下] | [后] |
| 送话 | 把转达、代答、接力的内容送进会话 | [现] 转达第一格 | [下] | [下] | 不送：loop 有自己的返修流程 | [后] |
| 接续 | 在原会话上继续 | [下] | [下] | [下] | 不适用 | [后] |
| 启动、停止 | 派出新活、停掉 | [后] | [后] | [后] | [后] | [后] |

写入的可靠性（参照 Sig）：先把「要送什么、送给哪条派工」记进账本，再送，送达后确认；进程崩了、说不清送没送到，就记成「不确定」交给闸门，**不盲目重发**，免得同一句话进两次，或者一个有副作用的动作做两次。

## watchdog 盯防（🔧 协调方暂定）

watchdog 只认机械事实，不做语义判断，自己也不发消息：它把事实写进账本，由闸门决定打不打扰我。

| 盯什么 | 机械事实 | 怎么得到 | 交给闸门后 |
|---|---|---|---|
| 派工停了 | 托付派工「在做」，但超过一段时间没有任何事件 | 低频巡检（见「节奏」） | 按举证：「停滞」卡片我没处理过，就只进汇总 |
| 来源看不见 | 某个来源读不了、hook 不再推送 | 已有的失明检测 | 马上打断（第二阶段第 9 件，不变） |
| 话送不到 | adapter 送话失败，或送达不确定 | adapter 的写入记录 | 打断：我以为送到了，其实没有 |
| 会话没了 | 托付派工的会话消失，事情还没完 | adapter | 进陈列：这件事没人在做了 |
| personal agent 自己 | 进程挂了、检测失败、磁盘满、渠道连续失败 | launchd 常驻、失败留痕 [现]；独立心跳 [下] | 已有：渠道失败 5 次停发并提醒 |

**为什么要独立心跳**：personal agent 挂了，它自己没法报告自己挂了。设计成 launchd 下的另一个极小的定时任务，只看 personal agent 最近一次心跳有多久了，太久就直接发一条本机通知。它不依赖主进程，也不依赖飞书。

**跑偏不归 watchdog。** 「进程活着」和「事情在推进」不是一回事：watchdog 只回答前一个问题；后一个问题，也就是「方向对不对」，由 assessor 对照意图卡来判，判得准之前只走影子。

## assessor 和影子（✅ 2026-11-01）

不是一回事：assessor 是「谁来想」，影子是「想出来的结论怎么用」的一个档位。影子属于 guard 的权限档位，挂在闸门和 router 的行动上，不是一个单独的部件。

| assessor 的结论 | 现在怎么用 |
|---|---|
| 这件事怎样了（卡片上的「这件事」） | 直接用：写错了我一眼能看出来 |
| 欠不欠我 → 挡不挡提醒 | 我在别的会话忙时直接生效；哪都不在时先走影子（第二阶段方案要点 5） |
| 建议怎么回 → 代答 | 影子 → 建议 → 自动 |
| 接力：交给谁、交什么 | 影子 → 建议 → 自动 |
| 意图卡草稿 | 影子，直到我确认 |
| 新材料的处理选项 | 陈列，我来选 |
