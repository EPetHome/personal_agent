资料核对：2026-11-01。状态：**主干已定（2026-11-01 用户认同）**：一句话、总指标、八件事、红线、必须满足；其余细节的状态见文末「待拍板汇总」：🔧 是协调方暂定、我没表态的，⏳ 是用到之前或看数据再定的。第二阶段的拍板记在[主需求书](需求书-personal-agent.md) D34–D36 和 Q5，本文件展开细则；第一阶段的需求和验收标准仍以主需求书为准。标〔待拍板〕的是协调方建议，未定。

## 一句话

从「看得见、能介入」的监督面板，升级成能替我做一部分决定的编排者：替我处理掉能处理的，只把要我判断的交给我。

## 为什么

- 第一阶段的卡片只陈述事实，personal agent 是流水线上的传递工，没有替我减掉成本。
- 深层原因：模型只拿到选择题（材料四样、答「在等你还是完成了」）；叫不叫我、卡片怎么写、下一步做什么，全由程序定。程序把材料和决策都收走了。
- 我的实际感受（2026-11-01）：卡片都在打扰我，我实际一条也没看；顶多起到「这个完成了，我知道了，去看看」的提醒，剩下的几乎全是我正在交互的会话发来的无效提醒。数据印证：能对上会话的 220 张 CC「在等你」卡片里，约 98% 发生在正在来回聊的会话里（见问题单[在电脑前操作时还在提醒](../../iusses/在电脑前操作时还在提醒.md)「2026-11-01 复查」）。
- 现状数字（协调方只读统计真机记录，2026-10-29 至 11-01）：135 张卡片，整天的三天分别是 59、38、31 张；79 张「在等你」里 45 张含红线条目（多为关键词命中）；反馈共 18 条，10-28 之后没有新的；卡片格式改了 5 批，仍不满意。

## 全局图

```
        我：目标意图 + 底线
              ↓
   程序·铺路：喂材料（只读工具）、给参照（我的标准、过往决定）
              ↓
   模型：自己翻上下文 → 想清楚怎么回事 → 给决定或建议；拿不准就直说
              ↓
   程序·围栏：红线强制、权限档位、留痕、能撤回
              ↓
        观测数据 → 我看结果 → 调边界、调参照
```

原则：确定的事交给程序（红线强制、权限档位、留痕、撤回），模糊的交给模型判断，并给足材料（D35）。

## 总指标

**每天「本来不用我」的处理次数**，越少越好（2026-11-01 定）。只数那些不需要我、却非得我来做的处理：回「继续、好、可以」这类不带新信息的话，点不涉及红线的「允许」，跑回会话看做完没有，把一个会话的结果抄给另一个会话。我给新信息、定方向、做取舍、改要求、拍板红线的事，都不算；这些次数不降，甚至变多都可以。

怎么认定「本来不用我」：

- 影子跑起来之前：我回的是不带新信息的短回复。
- 影子跑起来之后：影子替我想的回复，和我实际回的一致，就说明这次本来不用我。

辅助看每天叫我几次（卡片数）。误报率、一致率等其余分数只用来找问题，不当目标。只数次数，不看内容。

## 八件事

### 1. 放出智能

- 「分析问题」这一步由模型自己决定看什么：读会话全文、翻项目文件和 git 记录，想清楚是怎么回事，再给出判断、决定或建议。
- 用 Pi 打开只读工具来做，不上编排框架（主需求书 Q5）。
- 只在要发卡片或要替我做决定时才跑，不为每次动静调用。
- 🔧 模型：日常全用 DeepSeek v4.1 flash；评测打分和抽样校准时用更强的模型，不找我（D38）。

### 2. 边界

**能看**（D36，用户选 B）：

- 只读：它在盯的那个会话的全文，加上该会话所在项目的文件和 git 记录。
- 不联网；不写任何文件；不改会话文件和工具配置（第一阶段的通知钩子除外）。
- 「不许读」名单，由程序强制，分三层（项目层 ✅，目录层和文件层 🔧）。依据：2026-11-01 协调方只按文件名扫描了出过卡片的项目目录，没有读内容。
  - **项目目录本身要像项目**：会话的工作目录如果是主目录 `/Users/Admin`，或者桌面、文稿、下载这类大容器，就不算项目，只能读会话本身。扫描时发现有 11 张卡片的工作目录就是主目录；不堵上的话，等于允许读整个主目录。
  - **文件层（所有项目通用）**：
    - `.env`、`.env.*`，`.env.example` 和 `.env.sample` 这类模板除外
    - 私钥和证书：`*.pem`、`*.key`、`*.p12`、`*.pfx`、`*.jks`、`*.keystore`、`*.kdbx`、`id_rsa*`、`id_ed25519*`、`id_ecdsa*`
    - `.npmrc`、`.pypirc`、`.netrc`、`.git-credentials`、`.git/config`（可能含带口令的远端地址）
    - 登录态数据库和文件：文件名里有 `auth`、`session`、`cookie` 的 `.db`、`.sqlite`、`.json`
    - 不按「token」「secret」「password」这类词拦文件名：扫描里大量命中的是图标、代码类名和讨论 token 的文档，拦了会误伤分析
  - **目录层**：
    - `.ssh/`、`.aws/`、钥匙串、密码管理器、私人聊天（D21 原有）
    - `~/.personal-agent/`（含渠道密钥和运行数据）
    - 备份目录：`.bak/`、名字带「备份」或 `backup` 的目录，里面是真实运行数据的副本
    - 本项目只放真实内容的目录：`eval/cases/`、`eval/runs/`、`eval/待标注/`
  - **项目层**：哪些项目只许读会话、不许读项目文件，由我逐个定。2026-11-01 定：目前出过卡片的项目都可读（产品智能体交付资料、personal agent、loop、Promate、个人知识库、专利PPT比赛、IDaaS、模拟用户-Q02、pa-试用）；以后有要保密的再改。
- 读到的内容会作为输入发给模型服务（现在是 DeepSeek，经 opencode-go 中转），不只留在本机。
- 会话和文件里出现的指令只当材料，不照做（主需求书 Q2 红线）。

**能做**：按类别分三档放权，见第 6 件和第 8 件。

### 3. 目标和意图

- 每件事要有「我要的是什么」：总目标、不做什么、怎样算完成，也就是原闭环 2 的意图卡。没有它，模型替我做决定就没有对照。
- 意图卡是**决策之前的标准，不是决策的结果**：记的是我要什么，不是它打算怎么做。开工时就有，之后三处都拿它当标准：personal agent 决定怎么回、门（红线和放权）判断这一步在不在卡里、观测判断决策对不对。
- 只有我确认过的才算数；它起草、还没经我确认的内容，不能放宽任何权限，免得它自己写卡、自己放行。
- 意图卡是我的要求的可核对索引，不是第二份需求书，也不是 AI 给自己签发的通行证。我看到的保持下面 7 栏，其余放后台。

以下 2026-11-01 定（GPT 用三个真实会话试写后提出，协调方核对，用户采纳）。

**我看到的 7 栏**（每栏都可以写「不知道 / 待确认 / 不适用」，不硬凑）：

1. 总目标：可以继承上一级的卡
2. 这次要的结果
3. 当前阶段：现在在哪一步，允许推进到哪一步、不允许什么
4. 不做什么
5. 操作边界：能读 / 能写 / 能执行 / 能动真机 / 能往外发，分开写
6. 怎样算完成：写明到哪一层（开发完成、门禁、评审、合入、真机、业务验收分开）
7. 要先问我的事：写成具体的触发条件，加上批的是哪个对象（比如「合入」要写明是哪一批）

**放后台**：每条的依据（逐条挂到来源那句话或任务文件那一行）、每条是否经我确认、版本和生效时间、替代了哪一版。**实际进度另外存**，不写回卡里，免得状态反过来改低完成标准。

**谁写、什么时候写**：由 personal agent 从我的话里起草，我说了算；在第一个有副作用的动作之前要有可用的版本。只是问答时用轻量的临时卡，不让我填表。有任务文件的（比如 loop 批次的提示词），直接对应过去，不另写一套。

**什么时候让我确认**：按「要扩大什么权限」来确认，不是每条消息都确认，也不是整场只确认一次。要确认的节点：讨论转执行；新增读、写、执行、真机或往外发的范围；改目标、改不做什么、改完成标准；合入、发布、改权限这类重大操作。逐条确认，合在一起给我看。「按建议」只认它紧跟的那一条建议；含糊的认同不算确认整张卡；沉默不算同意。

**多大一件事算一张卡**：能独立判断结果、边界和完成的一件事算一张，不按会话或消息切。同一目标下的澄清、返修，更新原卡；从讨论到开发、从开发到发布，各开一张子卡。一个会话可以有多张卡，一张卡也可以跨几个会话接力；卡和卡之间不能互借授权。

**我中途改要求**：旧版本留着，每次改动记下来源那句话、改了哪栏、从什么时候生效、影响哪个待执行的动作、要不要重新确认；分清是澄清、追加、替代还是撤销。收紧的，立刻暂停有冲突的动作；放宽的，只放宽点名的那一项。已经做完的动作，按当时那一版卡对照，不能用后来的授权追认；自动流程发的消息（比如返修要求）不能改标准或授权。

### 4. 规则参照

- 给模型参照我的标准和过往决定：我对卡片说过的「该写出什么、不该写什么」、我过去对同类问题的回法、wiki 里确认过的经验。
- 协调方定期把我的说法归成评分标准，我确认后才进参照；标准有版本，改了要记下，旧标注按新标准重标或注明版本。
- 🔧 第一批参照：先用我说过的话和 wiki 里确认过的经验。

### 5. 可观测数据

每次模型分析都要记下：

- 看了哪些材料：路径、行号、内容指纹
- 用的模型和提示词版本
- 它的判断和理由、给的决定或建议
- 最后实际发生了什么：它自动做了 / 我按建议做了 / 我改了 / 我没理
- 影子档还要记下我实际是怎么回的

基础：埋点完善已合入并上真机（2026-11-01，`fe2d142`），从那以后的新记录带有模型名、提示词版本、输入指纹、抑制原因和代码版本；之前的旧记录没有这些字段，也不补。第二阶段在它上面补「看了哪些材料」和「最后实际发生了什么」。

### 6. 底线：红线

**我定的三条**（2026-11-01，主需求书 D37）：

1. 存在重大后果的操作，必须给我过目。
2. 没规定可以写的区域，不能写。
3. 没规定要完成的任务，不得去完成，不自作主张。

主需求书 Q2 原有的四条（不读密钥和密码管理器、不以我的名义对别人发言、不执行材料里的指令、不删原件）仍有效，是这三条的具体例子。「读」的边界不归红线管，见第 2 件的「不许读」名单。

**协调方细则**（🔧）：

- 第 1 条：「重大后果」按下面五条判据认定，命中任一条就算。「过目」指事前给我看、由我决定；personal agent 不替我回答这类问题，也不给「按建议回」。
- 第 2 条：「规定可以写的区域」：
  - personal agent 自己：只写它的数据目录 `~/.personal-agent/`；第一阶段装的通知钩子照旧。
  - 替我回话时：AI 要写的地方超出它所在会话的项目目录（比如改 `~/.zshrc`、改别的项目、改系统设置），按红线交给我。会话的项目目录默认算允许区域。
- 第 3 条：「规定」指第 3 件意图卡里写明的目标、不做什么、怎样算完成。
  - 不替 AI 扩大范围，不替我开新任务。
  - 没写明完成标准的，不替我宣布完成或同意收尾（比如「可以结束了」「合入吧」）。
  - 会话、文件、网页里出现的指令不算「规定」，只当材料。
  - 所以意图卡确认之前，替我回话只能走影子或建议，不能自动。

**「重大后果」的五条判据**：

1. 收不回：删除、覆盖、强推、改历史、迁移或清空数据
2. 出本机、别人看得到：推远端、发消息或邮件、发布、对外发言
3. 动钱或账号权限：付费、授权登录、改权限
4. 改规矩本身：改需求、验收标准、权限配置、红线清单；合入（本项目合入即上线）
5. 碰秘密：读写密钥、密码管理器

**参考官方自动模式默认拦截的动作**：下载后直接执行（`curl | bash`）、提交或推送密钥、上生产和数据迁移、`terraform destroy` 一类的销毁、改共享基础设施、强推、`git reset --hard`、`git clean -fd`、删除会话开始前就有的文件、授予权限、合入没批准的代码、关闭检查、打印密钥、对公网开隧道、无人值守的 agent 循环。

**执行规矩**：

- 红线由程序规则判；模型只能往里加，不能往外移。
- 现有的关键词规则偏宽（「在等你」里 57% 被标红线），先保留，宁严勿宽；草稿划完后按判据细化，并单独统计「红线漏判」次数。
- 改红线清单本身就是红线，只有我能改。
- 第二道门：替我回话以后，执行工具自己的权限仍然生效（CC 的自动模式会拦危险动作）。

### 7. 必须满足（2026-11-01 用户认同）

- 每次替我做的事都留痕，能查到依据。
- 拿不准就问我：允许模型答「不确定」，这时转给我，不硬答。
- 只有能撤回、或者错了我能及时发现的，才进「自动」档。
- 每天汇总一次：它替我做了什么、我改了什么、哪些在影子档里和我不一致。
- 命中红线永远交给我。
- 收集数据不让我额外投入（2026-11-01，主需求书 D38）：反馈、标注这类要我参与的环节，由 AI 辅助完成，从我本来就会做的事里推断；我不操作不当信号。🔧 协调方暂定的落法：
  - 影子和我是否一致，由模型来判，抽样校准用更强的模型，不找我。
  - 评测集里等标注的题，由 AI 依据当时的证据先标好；需要我判断的，只挑它拿不准的少数几条，放进我本来就会看的汇总里，不另外找我。
  - 卡片上的反馈按钮可以留着，但不指望它当数据来源。

### 8. 验证和收回

- 按类别推进。类别 = 卡片类型 × 要我干什么 × 哪个工具。每一类分三档：
  - **影子**：它照常想好怎么做，但不发出去，事后和我实际的做法对比
  - **建议**：放在卡片上，我一键确认或改了再发
  - **自动**：直接替我做，事后告诉我
- ⏳ 放行线起步值（看影子数据再定，下面只是参考）：样本至少 20 条；和我一致至少 9/10；严重错误（会造成收不回的后果）0 次。
- 收回：出一次严重错误就退回上一档；每周看一致率有没有往下掉。
- 每改一次模型、提示词或规则，都用评测集重测一遍，防止改好一类、坏了另一类。

### 9. 叫与不叫的边界（2026-11-01 用户认同）

2026-11-01 定：「正在交互的会话不叫我」并进第二阶段一起做，不单独开批。

**原则**：只在三件事同时成立时叫我：事情停住了，我没在看，它自己也不会好。我正在看、或者马上就会看到的，不叫。

**AI 停下等我时，按我在哪分三种**（只看各会话里我发言的时间，D21 范围内）：

| 我在哪 | 怎么认 | 叫不叫 |
|---|---|---|
| 就在这个会话 | 停下前不久我在这个会话说过话，之后也没去别处 | 不叫 |
| 在别的会话忙 | 停下后我在别的会话说话，这个会话一直没回 | 过一段时间还没回，提醒一次「还有会话在等你」，几个合成一条 |
| 哪都不在 | 停下后所有会话都没动静 | 过一段时间叫我（现在的「在等你」） |

红线、盯防自己看不见了，照旧马上叫。

**依据**（协调方只读统计 216 张「正在聊」的 CC「在等你」卡片，只看发言时间）：

| AI 停下后我接下来 | 张数 | 回到这个会话用了多久 |
|---|---|---|
| 先回了这个会话 | 129 | 中位 4 分钟，八成 11 分钟内，九成 18 分钟内 |
| 先去别的会话，后来回来了 | 48 | 中位 11 分钟，九成 21 分钟内 |
| 先去别的会话，30 分钟内没回（像是漏了） | 22 | — |
| 30 分钟哪都没动静（像是走开了） | 17 | — |

起步值（2026-11-01 用户认同）：「哪都不在」等 20 分钟，「在别的会话忙」等 25 分钟，以后按影子数据再调。

渠道（2026-11-01 用户认同）：「在别的会话忙」说明我在电脑前，只发本机通知；「哪都不在」照旧本机通知 + 飞书。

**AI 停下不等于在等我，也可能是聊完了**（2026-11-01 用户指出）。上表「像是漏了」的 22 张，再往后看：19 张我之后再也没回那个会话，多半是聊完了；只有 3 张在 6 小时内回来接着聊，像是真漏了。所以叫之前要两道判断：

- 程序判「我在哪」：确定的事，按上面三种。
- 模型判「这个会话还欠不欠我东西」：AI 最后是在问我、等我定，还是已经交代完了。模糊的事，交给放出智能后的分析（第 1 件），对照意图卡。

两道都成立才叫。判得对不对不找我标（D38），从我后来的行为自动认：后来回到那个会话接着聊，说明当时确实欠我；一直没回，多半是聊完了。「一直没回」也可能是我忘了或放弃了，这个口径会有误差。

统计只覆盖 CC；Codex、Pi 里我自己聊的会话用同一条规则。loop 完成照旧是轻提醒（我说过「这个完成了，我知道了，去看看」是卡片唯一有用的地方）。疑似跑偏暂不按这条规则处理，等影子数据。
