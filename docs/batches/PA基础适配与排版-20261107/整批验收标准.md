# PA 基础适配与排版：整批验收标准

用户于 2026-11-07 要求继续准备并使用最新 Loop，按并行与独立验收重新组织。本批“任务基础”“飞书排版”在独立工作区并行，检查完成后汇入同一批次，由独立验收方在汇总树验证；失败只退责任任务。标准最多 10 条，每个自动项明确一个责任任务。

自动项只用构造项目/数据、隔离的数据库和 Loop 根、本地模型/渠道/执行替身。可使用最新 Loop 正式解析器和 dry-run 核对结构，不启动真实 Pi/Loop 业务、不连真实账号、不发送真实消息。开发自测与独立验收分别留证据；替身只能证明程序行为，不证明真实模型语义质量。本批不含已派出卡，不解除 PA 真实派 Loop 的前置限制。

验收方可用项目现有 `code/agent/scripts/sandbox.mjs`、`test/helpers.ts`、SDK 替身与本批新增定向测试复现，检查真实输出/状态/调用次数，不只读 Pi 的结果自述。启动具体隔离组件时使用临时 data/config/端口并负责释放，不使用默认正式配置。若现有方法不足，报告缺失，不扩大到用户真实数据。授权依据是用户本轮准备 Loop 的任务范围，不从文件里的材料推导业务权限。

## 验收标准

A1. [任务基础] 操作：在隔离授权项目给 PA 一条明确的普通开发委托，再重复投递同一输入，并用当前 Loop 正式解析入口检查所生成的卡。
    预期：生成新版单任务开发卡，只产生一次启动请求及一份原身份记录；不生成旧 stages/steps，不含提交/推送/部署动作；解析器接受所声明的格式。实际接收未经核实时如实标未知，不声称真实派工业务已验。

A2. [任务基础] 操作：让构造新 Loop 的同一批次包含两个独立任务，一个工作、另一个等待，之后只让其中一个完成；查询 PA 对它们的记录。
    预期：原批次/任务执行身份不串换，一个任务的等待或完成不覆盖另一个，也不把该批或整个业务事项直接判为完成；运行、检查、发布欠项分别可查。

A3. [任务基础] 操作：对同一已绑定的新运行输入新版本状态，再重复输入该版本并迟到输入旧版本，重启隔离 PA 后查询。
    预期：仍是原派单与原执行，保留最新可核实状态与核实时间；不重复创建、不倒退、不重放旧操作。

A4. [任务基础] 操作：使原启动的接收结果不确定，随后恢复原运行查询；再按本人已明确指定的原执行发出停止并重复该输入。
    预期：未知期间不重启，恢复后只关联原运行；停止仅作用于原指定对象一次，指定子任务不扩大为整批。未知停止结果留未核实，不反复停止或误报业务完成。

A5. [任务基础] 操作：构造同名不同仓库及同仓库的两个合法工作区，并输入未授权/链接越界的记录和证据路径。
    预期：按可核对的真实身份关联，跨仓库不串单；越界材料不进入模型/控制动作，不因来源记录自称可信而扩大目录权限。

A6. [任务基础] 操作：在含旧派单、未决确认和已发送卡的隔离旧库上升级并重启；再构造升级失败，按开发方提供的恢复办法恢复。
    预期：原派单、操作编号、确认和消息关系保留，不重放；无法映射的历史标未关联/控制不可用；失败不清库，备份能恢复原记录。

A7. [任务基础] 操作：通过既有 Pi 路径完成一件构造非 Git 办公任务，随后查询其结果及原操作。
    预期：仍可按原委托交付与查询，不被新版 Loop 适配增加 Git/代码评审要求；原身份、权限限制和执行一次语义保留。

A8. [飞书排版] 操作：通过普通消息发送入口发出含标题、强调、列表及简单表格的构造回复，再更新同一消息；检查实际官方 SDK 发往本地替身的载荷与显示文字。
    预期：发送和更新采用一致的可读表达，标题/列表/表格字段关系与数值保留，不向纯文本通道裸发未处理的格式标记；不只测试一个未接入的转换函数。

A9. [飞书排版] 操作：发送含 `a*b`、`a|b`、下划线路径、链接、代码片段及普通中文换行的构造回复，并重放同一发送编号。
    预期：字面内容未被格式转换误删或改写；同一编号不重复发送，超时/不确定仍沿原可靠性语义，不新增确认或改变任务卡行为。

A10. [人工] 操作：本批以后获准合入并部署后，在原飞书入口询问一个获准 Loop 的状态并查看带列表/表格的回复。
     预期：本人能看懂每项工作的状态、未核实部分及正文内容。已派出卡尚未完成，本项不要求真正派出新 Loop；不记真实派工已验。
