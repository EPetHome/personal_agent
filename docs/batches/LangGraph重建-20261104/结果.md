### 实施

- 新建独立 TypeScript package：LangChain `createAgent` + `humanInTheLoopMiddleware` + LangGraph SQLite 检查点。用 `BaseChatModel` 实现原生 OpenAI wire 适配，保留 `reasoning_content`，没有搬旧账本或关键词路由。
- 飞书收发与官方 SDK 适配：只接本人私聊；原文、附件、引用、按钮交 Router；附件放独立目录；不保留可能含验证 token 的 SDK 传输头。当前工具仅回复、查卡、搜已关卡、只读查 Loop、读文件/图片/证据、专用事件查询；不能开卡、派工、执行命令、合入或推送。
- SQLite 持久输入队列、本人优先、一次一条、超时“在处理”；发送前记账，已确认回复不重发；正常停止保存未完成输入，强杀后按检查点续接。
- 原话滑动窗口、任务表与订阅匹配骨架；Loop 事件先更新机械状态/派工记录再附整张卡；聊天不建卡。图片/文件/工具大内容不进入原话窗口。
- 真实路径白名单、内置黑名单底线、配置追加拒读范围；证据须登记且落在对应项目/专属 Loop 运行目录。链接、`..`、黑名单内的白名单文件都不能越权。数据/凭证/配置文件不能由普通文件工具读取。
- 原始输入与模型/工具实际结果按天只追加留痕，记录提示词版本、材料路径/指纹、简短依据/方案与用量；来源有持久增量游标；例行检查不追加日志。
- 主进程/独立看门狗两个入口；心跳、五类机械故障、两路直接通知、每类独立恢复、持续故障去重和再犯更新。看门狗不调模型、不写主数据库，另存自己的去重状态。
- 提供模型、飞书/本机通知、Loop 查询、自动拉起替身；提供只生成不加载的 launchd 脚本及可直接运行的临时沙盒。

### 保守落地与限制

1. 窗口按 UTF-8 字节数加每条开销计算 token 的保守上界，不以字符数/4低估中文/emoji；因此实际可保留的历史可能少于模型精确分词的 100K token。超大单条整条退出窗口，不截断/摘要；原文留日志。超限淘汰到不高于 60%。
2. `readAllow` 只能收窄项目/收件箱/附件/已登记证据的范围，不能扩到任意目录；黑名单不可由配置关闭。多硬链接文件、常见私钥/证书及 PEM 标记保守拒绝。全局 Loop 目录不能代替配置中“属于本项目的部分”。
3. 网络发送处于 sending、无法确认成功时不重发，明确返回/记录“不确定”；不声称能在任意断电点同时保证无限期严格 exactly-once 和必送达。正常停止/恢复及已确认 sent 的去重已经测试。
4. HITL 中间件已接入，但甲段只有无需点头的只读/本人回复工具，全部配置为不暂停；派工审批、过期重核、worker 动作由乙、丙段实现，当前不提供可绕过的占位执行工具。
5. 并发/审批预留项可配但本段不执行派工；Router 并发固定 1，红线永远问。配置只在启动时读，修改后需正常重启，PA 不写回配置。
6. 检查点保留最近 8 个已完成输入线程（可配），每线程还有工具轮数上限；未完成线程保留。日志按天只追加，队列/游标/事件索引不整本回读；每日用量默认不限。
7. 未增加许可外运行依赖。直接运行依赖仅 LangChain/LangGraph、其 SQLite 检查点包及飞书官方 SDK；开发依赖仅 TypeScript/Node 类型，精确版本与 lockfile 均已提供。SQLite 原生安装的 prebuild-install 弃用提示、Node 22 SQLite experimental warning 仍会出现，不影响本次检查通过。

- `src/loop.ts`：在配置指定批次目录排他写提示词与 `批次.json`；复制配置的 scope（allow 只能在 `code/` 下，追加规矩/需求/eval 等 deny），核对独立开发空间与项目 Loop 映射，调用官方开工、核对搬运后批次身份/范围，再独立启动。已有运行批次不并行开工，已有目录/分支不覆盖。送话保留原文/换行，限定原批次原段；续跑、停止均走固定官方动作，不开放任意命令。子命令撤掉 PA 宿主的 Loop、飞书及 Git 身份环境，不把本开发会话误当目标。
- `src/router.ts` / `app.ts`：HITL 根据只读配置决定暂停，点头组/工具参数留在 SQLite 检查点；waiting 输入不占队列，不因等用户触发输入卡住。正常重启可直接点原卡，用户消息仍优先。执行过的工具即使被模型同轮重复请求也只返回原结果，不重发。
- 点头和执行账放在现有 KV：依据包含任务定义、取消状态、批次状态/提交/路由/事件代次。回调须本人私聊、不可猜的 token、原任务已发消息订阅三者匹配。worker 层有进程内并发合并及 SQLite 条件领取；**执行意图先持久化为 executing，再做任何 worker 副作用**。过期/取消不执行，原卡写变化并交 Router；中断、超时、未知或身份不符回执标不确定，不自动换编号重发。
- Loop 事件仍经文件通知加低频兜底。订阅归卡后，程序先只读查询核实、更新状态和派工记录，才把整卡交 Router。暂停/需决定/完成对不上只记“核实不了，没叫你”，不调模型、不发卡；有可比事件序号时拒绝过期事件。done 另核对查询中的分支/完整提交及 Git 分支确实含提交；门禁/评审/验收未知或有欠项不得冒充全过。兼容单段及原生多段 gate/review 形状。
- `src/cards.ts` / `channel.ts`：同任务只发一张交互卡，后续 PATCH 原消息；卡和任务相关回复均登记消息订阅。完成卡带分支、提交、核实记录、人工欠项与证据路径；没全过/卡住卡带原因、真假判断和建议，续跑点头带“按建议/再给它一轮”。合入、推送（含“仍要合入”）由程序固定禁用并写“当前不可用，请回电脑操作”；真实 SDK 序列化时不可用项根本不生成可点击按钮，伪造回调也没有执行入口。
- 开关为 `approval.dispatch/send/stop`；红线请求始终问且没有“按建议”捷径，红线配置 false 无效。直接成功会在原卡标“已直接处理”。配置只在启动时读，不写回；系统提示词给出应手改的完整键。增加 `loop.actionTimeoutMs`（默认 5 分钟，另受输入时限约束）；只读查询/Git 核实仍用 `loop.timeoutMs`（默认 15 秒）。
- 取消、补充定义由模型根据本人来话选任务；程序强制作废旧依据，worker 材料不能取消或改定义。取消不谎称停止了外部正在跑的 Loop。用户忽略不催，选择“回电脑再说”后挂起，不由 worker 事件另提同类操作。
