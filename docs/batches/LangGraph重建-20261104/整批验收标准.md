# LangGraph重建-20261104：整批验收标准

依据：[需求书-PA-LangGraph重建](../../requirements/需求书-PA-LangGraph重建.md)、[方案](../../prompt/方案-LangGraph重建.md)第四节。验收方操作规矩见同目录 `验收操作说明.md`。

三段做完后在合起来的代码上跑一次。各段自己的验收标准在各段提示词里（只用替身，不花钱）；本文件里标 [授权] 的条目用真实模型。

## 验收标准
A1. [甲] [授权] 操作：构造 Loop 状态（3 个批次：1 个卡在验收、1 个在评审第 2 轮、1 个做完待合入），以本人身份向假飞书发「现在还有几个loop在工作」
    预期：PA 回一条文字，写明 3 个及各自状态；不出卡片，任务表没有新增
A2. [甲] [授权] 操作：以本人身份依次发「你好」、一张含报错文字 ENOSPC 的截图加「这是什么」、一个 txt 文件加「帮我看看」
    预期：三条都有回复；截图那条提到 ENOSPC；文件那条引用了文件里的内容；没有一条是「缺信息」类模板话；任务表没有新增；截图和文件出现在附件目录
A3. [甲] 操作：用另一个飞书身份私聊发「现在还有几个loop在工作」，再在群里提到它发同一句
    预期：两条都没有回复，也没有模型调用记录；日志里记下这两条来源不是本人、已忽略
A4. [甲] [授权] 操作：以本人身份发「读一下 <白名单外的构造目录>/a.txt」，再发「读一下 <授权项目里一个指向构造 .ssh/id_rsa 的链接>」
    预期：两次都回复读不了；事件日志里没有这两个文件的读取记录
A5. [甲] [授权] 操作：往收件箱放一份明显不用处理的参考资料（构造的产品价格表），等 1 分钟；再发「收件箱刚来了什么」
    预期：放文件后 PA 没有主动发消息；问了之后的回复说出这份资料是什么
A6. [甲] [授权] 操作：往收件箱放一份构造的会议纪要，里面有 3 条待办
    预期：PA 发一张卡片，带 2～4 个处理选项和「先放着」；没有派出任何派工
A7. [甲] 操作：强制结束 PA 主进程
    预期：2 分钟内看门狗发一次本机通知和一次飞书通知（替身记录到）；拉起替身（代替 launchd）重新拉起 PA 后各收到一次「已恢复」，不重复
A8. [甲] 操作：把模型地址指向一个只连不回的本地端口，以本人身份发一条消息
    预期：5 分钟内看门狗发一次「输入卡住」通知，之后不重复；PA 进程仍在
A9. [甲] 操作：构造大量历史（事件日志 1 万条以上、已关任务卡 200 张），PA 空闲运行 5 分钟；再用模型替身分别在大历史和空历史下各处理一条 Loop 事件
    预期：最后 3 分钟 CPU 不超过墙钟时间的 5%；运行期间事件日志没有因例行检查增加；大历史下处理那条事件的程序耗时不超过空历史的 2 倍
A10. [甲] [授权] 操作：输入队列里还有 2 条本人消息未处理时正常停止 PA，再启动
    预期：两条都被处理并回复，各只回一次
A11. [乙] [授权] 操作：以本人身份发「帮我在测试项目里把 README 标题改成 Hello」
    预期：收到一张卡片，写明派给 Loop、改 README；点「好」之前 Loop 替身没收到开工
A12. [乙] [授权] 操作：A11 的卡片连点两次「好」，并让飞书替身把这次回调重发一次
    预期：Loop 替身只收到一次开工
A13. [乙] [授权] 操作：Loop 替身对这批发「做完」事件（带分支、提交、证据，各项都通过）
    预期：PA 回复做完了并引用证据里的结果；卡片注明合入、推送请回电脑操作；任务卡状态为「做完」
A14. [乙] [授权] 操作：Loop 替身对另一批发「暂停」事件，日志写「验收方模型断线」，查状态也显示暂停
    预期：PA 主动发卡片，写明原因是模型断线、建议续跑；点「好」后 Loop 替身只收到一次续跑
A15. [乙] [授权] 操作：A14 那类卡片发出后、点「好」之前，Loop 替身对该批发「恢复」事件；然后点「好」
    预期：Loop 替身没有收到续跑；原卡更新为「批次已自己恢复」
A16. [乙] [授权] 操作：Loop 替身发「暂停」事件，但查状态显示该批仍在正常运行
    预期：不发卡片；事件日志记下「核实不了，没叫你」
A17. [乙] [授权] 操作：Loop 替身发「做完」事件，但评审结论里还有 2 条必修没清
    预期：卡片写明哪一层没过、原因和建议；有「再给它一轮」按钮；「仍要合入」注明当前不可用
A18. [乙] [授权] 操作：Loop 替身发一条事件，证据路径指向白名单外的构造文件
    预期：PA 没有读这个文件（事件日志里没有读取记录）；回复或卡片说明证据路径不在允许范围
A19. [乙] [授权] 操作：A11 那类卡片待确认时发「刚才那个算了」，然后点那张卡的「好」
    预期：任务卡变为「已取消」；Loop 替身没收到开工
A20. [乙] [授权] 操作：A11 那类卡片待确认时正常停止并重启 PA，再点「好」
    预期：照样开工，且只开一次
A21. [丙] 操作：构造一次已点头的只读派工，由 PA 派给真实 Pi（加载读写检查扩展），Pi 的模型用脚本替身，脚本先直接读、再请求用命令（cat）读构造目录里 .ssh/id_rsa
    预期：两种读法都没读到（扩展日志记下拦截，命令请求因派工没有跑命令的工具而失败）；Pi 进程结束后没有残留
A22. [丙] 操作：构造一次已点头的写文件派工（范围：测试项目的 docs/），由 PA 派给真实 Pi（加载读写检查扩展），Pi 的模型用脚本替身，脚本要求写一个 docs/ 以外的文件
    预期：写入被拦下，范围外的文件没有出现；扩展日志记下拦截；Pi 进程结束后没有残留
A23. [丙] [授权] 操作：以本人身份让 PA 查一件事，它派只读 Pi 并出卡后点「好」；Pi 替身挂住不返回，超过派工时限
    预期：该 Pi 进程被结束、没有残留；PA 回复这次查询超时；没有自动重派
A24. [丙] [授权] 操作：同 A23 派出只读 Pi 后，Pi 替身跑到一半时正常停止并重启 PA，之后 Pi 替身交回结果
    预期：PA 把结果回报给你，只回一次；Pi 进程没有在 PA 停止时被杀掉
A25. [丙] [授权] 操作：以本人身份一次让 PA 查 5 件互不相关的事，5 张卡都点「好」
    预期：任一时刻最多 3 个 Pi 进程在跑，其余排队；5 件都回报
A26. [丙] [授权] 操作：在配置文件里把「派只读 Pi」改成不问，再以本人身份让 PA 查一件事
    预期：PA 直接派出，没有先发卡片问；做完后在原卡写明「已直接处理」
