# 返修：真实数据回放没达标

## 目标

本批 A1–A9 已通过，但协调方用本机真实数据只读回放（原 A10）时有两项没达标，并暴露两个会让用户被提醒淹没的问题。请在本会话里接着修。

回放结果（只有统计）：没有来源整体失明；每轮约 15 秒；空跑第二轮只增加 32 KB。但：

- 读不了的比例：Codex 6/182（3.3%），loop 31/178（17%），超过 2%。原因：loop 有 31 份总结（CC 跑 loop 生成的）没有轮次时间；Codex 有空会话（一条消息都没有），还有 1 份大文件整份读进内存时报 `Invalid string length`；CC 和 Pi 读不了的也都是没有会话身份的非会话文件（验收器、子代理产物、只有元数据的文件）。
- 第一轮就发了 291 条提醒，几乎全是历史上的事。
- 141 个「停滞」里 139 个最后动静在一天以前。
- 另外发现：loop 总结里的轮次时间是本机当地时间（`America/New_York`，10 月 20 日为 UTC-4），程序当成 UTC 读了，差 4 小时。

## 已拍板（补充，其余沿用本批提示词）

- loop 轮次时间按本机当地时间解析；没有轮次时间的总结，最后动静用该文件的修改时间。
- 取不到会话身份、或一条消息都没有的文件，算「不是会话」：跳过并计数，不算读不了；只有某个来源跳过的比例明显高于平时才报看不见。大文件逐行读，不整份读进内存。
- 首次接入（数据目录为空时的第一轮）：最近 1 小时内发生的照常提醒，更早的只进总览、不补发。
- 已搁置：超过 24 小时没动静、也没结束的会话，状态叫「已搁置」，只进总览，不提醒；30 分钟到 24 小时之间的仍按停滞提醒。

依据：需求书「第一个闭环」判断状态和输出两节、方案第 12 节末尾「第一次真实回放之后的补充」。

## 边界

- 样本有改动：两批样本里 loop 总结的轮次时间已改为当地时间写法（各 README 末尾有说明），本批新增场景 `R10-首次接入`、`R11-已搁置`。样本仍只读，相关测试按新样本更新。
- 门禁照旧同时跑两批场景测试，不得有跳过。
- 其余边界同本批提示词，仍不得读写真实数据目录；真实回放仍由协调方在你交付后再做一次。

## 验收标准

A1. 操作：用场景「R1-Codex新格式」跑一轮检测后要一份总览
    预期：只有两行 Codex：/demo/api「进行中」、意图「给订单导出加一个 CSV 格式」；/demo/web「已完成」、意图「把首页按钮颜色改成蓝色」；子代理不单独占一行；意图里没有 environment_context；没有「看不见了」提醒
A2. 操作：分别用场景「R2-CC噪音与旧版」和「R3-Pi老格式」跑一轮检测后要总览
    预期：R2 两行 Claude Code 都是「已完成」，意图分别是「把购物车按钮文字改成「加入购物车」」和「给博客加一个归档页」；R3 一行 Pi「已完成」，意图「给博客首页加最近 5 篇文章」，loop 返修消息不算追加要求；两个场景都没有「看不见了」提醒，v1 老格式文件被跳过
A3. 操作：用场景「R4-loop目录」跑一轮检测
    预期：发件记录只有两条 loop 提醒：完成的一条「有空看」交代，暂停的一条「现在就要你」；其余文件不当总结读；没有「看不见了」提醒
A4. 操作：用场景「R5-一份坏文件」跑一轮检测后要一份总览
    预期：四个会话「已完成」；一条提醒写「Claude Code 有 1 份会话读不了」，例子不超过 3 个，正文不超过 4 KB；Claude Code 没有被判成整体看不见
A5. 操作：用场景「R6-来源目录不存在」，把 Codex 来源配置成该场景下不存在的 `codex-sessions-missing` 目录，跑一轮检测
    预期：一条「现在就要你」提醒写明 Codex 看不见了、原因是目录读不了；Claude Code 会话照常出现在总览里
A6. 操作：用场景「R7-表情与长文本」跑一轮检测和总览，都加 `--json`，再逐行检查数据目录里的每个文件
    预期：两次输出都能被标准 JSON 解析器完整读出；数据目录里每一行都是合法 JSON；总览里的意图没有乱码
A7. 操作：用场景「R8-临时目录会话」，先不配忽略目录跑一轮总览，再配置忽略 `/private/tmp` 和 `/var/folders`，用新的数据目录再跑一轮
    预期：第一次总览三行；第二次只剩 /demo/shop 一行
A8. 操作：用场景「R9-空跑不膨胀」，按卡片里的三个当前时间各跑一轮检测
    预期：第 2、3 轮各自让数据目录增加不超过 10 KB，发件记录不增加
A9. 操作：用场景「R10-首次接入」，用新的空数据目录，先以 2026-10-20T18:00:00Z、再以 2026-10-20T18:10:00Z 各跑一轮检测
    预期：第一轮发件记录正好两条：/demo/shop 的 Claude Code 等授权、/demo/blog 的 loop 暂停；总览里四条都在（/demo/api 显示「在等我」，昨天跑完的 loop 显示完成）；第二轮不新增发件
