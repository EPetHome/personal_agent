## 实现

### 1. 换目录仍对得上

- `code/src/sources/{cc,codex,pi}/index.ts` 收集会话文件中明确的结构化 cwd，保存为可选 `cwdHistory`，按原件路径分开；项目仍显示起始目录。
- `code/src/core/sessions.ts` 统一按工具、会话号、原件路径及该原件出现过的目录对账。不能借父/兄弟成员或同号另一份文件的目录通过。
- `code/src/core/normalize.ts` 和成员快照保留目录历史；规则等待、模型等待与重放继续共用同一匹配逻辑。
- 同号同路径、仅 cwd 尚未落盘时，按既有推送早到规则宽限最多两轮；会话号/路径归属冲突、配置外路径仍立即报错。

### 2. 严格区分空会话与丢失的旧会话

- 仅当推送为 `session_end`、会话号从未在已扫描文件中出现、两轮宽限后原件仍不存在时，追加一条 `push_empty` 及固定说明，不生成会话或提醒。
- `SourceReader` 通过来源组件的 `sessionIdOf` 保留“曾见身份”线索；无正文、目录字段不可用、侧链产物或损坏文件中的已见身份也不因文件后来消失而被当成空会话。身份线索不授权推送对账。
- 历史 `session_observed`（含子成员）自动计入已见身份；新发现的非正常会话身份只追加 `session_seen`，查询/重建不消耗宽限轮数。
- 新推送只与**本轮成功读取**的原件验证，修掉了文件已删除却仍能借缓存通过对账的路径。现存空文件、已见会话丢失、缺文件的 waiting_permission/turn_end 仍报警。

### 3. 不再盯 loop 自己的 AI 会话，旧误报能结束

- CC/Codex/Pi 的 `autoreview-` 前缀会话、推送、可识别身份的损坏原件均过滤；读不到身份时只以工具固定内部会话文件名兜底。loop 总结来源不受此过滤影响。
- 感知和历史投影两处都过滤，已有内部会话及未交付提醒不会被查询/重建/后续检测重新带出来，不调用其会话判断器。
- 历史换目录推送恢复验证时记录可选 `push_validated.recovered`，允许状态恢复，但不补发旧等待提醒；空会话按新规则解除失明健康状态。
- 已结束故障轮次的失明/读不了提醒不再重试渠道；以后出现真正的新故障，也不会复活旧故障队列。历史事件、发件、反馈原样保留。

### 4. 飞书失败可查，连接状态可见

- `code/src/channels/feishu/transport.ts` 同时覆盖启动 Promise 拒绝、SDK `onError` 和只记 SDK 日志的失败；初次启动结果及对应状态写入完成后再进入常驻检测，避免启动状态写入与首轮检测争锁。
- 上游错误仅在内存中分类；只输出固定类别 `credentials` / `permission` / `network` / `configuration` / `unknown` 与固定短说明，不记录凭证、请求、URL 或上游原文。
- 连接变化追加 `feishu_connection` 事件；失败在 `service.log.jsonl` 中为 `feishu_connection_failed`。同一连续状态去重。
- 只有 SDK 握手/重连成功回调才算已连接；连接中、重连中、失败、停止及假渠道有明确区分。文本总览、JSON 总览和派生状态提供连接信息，查询/重建不联网。
- 常驻新增渠道替身注入入口，只用于离线集成测试；真实飞书初始化失败不吞原因，也不阻止其他来源继续检测。
