## 记录约定

### 1. 完整模型输入与回放

`replay.input` 为 `{ systemPrompt, prompt }`：保留程序自有系统指令、提示词模板和外部材料引用；恢复后得到当次实际传给 Pi 判断进程的完整系统指令和 stdin。保留原有截断、格式及起草材料，实际送模内容、调用次数和判断规则未改。

- `model`：实际 `--model` 参数。
- `promptVersion`：`judgment-v1` / `snapshot-v1`；`templateSha256` 同时覆盖对应提示词函数、共用起草指令及系统指令。
- `inputSha256`：对**恢复后的** `JSON.stringify({ systemPrompt, prompt })` 按 UTF-8 计算 SHA-256，字段顺序如上。
- **外部材料全部引用，不再通过「凭据正则未命中」决定可以明文保存。** 开工要求、追加要求、摘要、步骤、回复和四项快照都引用已有会话事件、推送、先前判断摘要或同条起草快照的字段；包括看起来普通、没有已知认证前缀的正文。
- 引用包含事实键、字段路径、值哈希和 JSON 字符串编码后的区间。仅程序生成的固定模板、结构键、事实状态常量及原有压缩/截断引入的空白和省略号可直接保留；其余字符必须来自可信引用。额度/本轮时限阻止调用时仍不伪造 replay。
- `code/src/core/replay.ts` 的 `restoreReplayInput` 接受旧事实值的解析器，先校验引用，再校验完整输入哈希。解析示例在 `code/test/telemetry.test.ts` 的 `restoreFromEvents`；归档后可先用既有 `restoreEventLog` 恢复完整事件流。无需读取来源会话文件。
- 材料结构未知或无法构造引用时明确记 `unavailable: input_reference_unavailable`，不回退原文、不阻止原判断，也不冒充可完整回放。旧原文/局部引用及旧 `credential_reference_unavailable` 记录仍可读取、不迁移。Basic、普通 token、无认证特征正文、转义/换行材料的实际 stdin 与恢复哈希已验证；没有用真实凭据测试。

### 2. 固定抑制原因

`scope=notice` 表示提醒候选未计划；`scope=model_check` 表示判断未启动，**不等于一定没有规则兜底提醒**。原有 `suppressedNotices` 仍只承担历史不补发索引；新增埋点去重索引与业务决策隔离。同一事实、作用域和原因只追加一次，重建/封存保留去重状态。

| reason | 依据/原实现路径 |
|---|---|
| `duplicate_notice` | 「什么时候叫我」去重、停滞每会话只叫一次 |
| `waiting_interval` | 在等你/跑偏/loop 暂停先等五分钟 |
| `user_replied` | 目标会话已接话，不再叫；保留接话引用与窗口长度 |
| `loop_resumed` | loop 自己恢复，不再发尚未发出的暂停提醒 |
| `model_daily_limit` | 「额度用完」；只表明模型阶段受限，旧 `check.error` 仍保留 |
| `first_connection_history` | 首次接入一小时以前的事实不补发/不新判断 |
| `feedback_false_positive` | 需求「反馈」/D31 对应的既有同会话、同原因误报抑制，不是新增推送规则 |
| `recovered_push` | 需求未直接规定的既有保护：对账恢复的等待事实不补发，独立于首次接入原因 |
| `model_cycle_timeout` | 需求未直接规定的既有单轮模型预算保护 |
| `drift_cooldown` | 需求未直接规定的既有十分钟跑偏检查间隔 |
| `model_evidence_24h` | 既有模型旧证据保护；与「超过 24 小时只进总览」有关，不混作首次接入 |
| `missing_trigger_member` | 需求未直接规定的既有保护：找不到跑偏触发成员，不能发该候选 |

接话可能让候选完全消失，因此在候选筛选前留痕。第 1 轮返修新增只供埋点的 `waitingWindows` 索引：从已有 `waiting_interval` 事件重建，按会话成员/作用域保留原 `evidenceAt`；即使下次扫描已经是 AI 的新回复，也先结算原窗口的接话原因，再独立记录新窗口。无接话的新输出可结清旧窗口，后续模型检查或提醒计划也会结束对应等待阶段；每个成员/作用域至多保留一份未结算事实。检查点保留该索引，旧检查点缺字段按空读取；不参与模型候选、推送、额度或等候规则。

卡片已经发出后的接话仍走既有 `notice_reply_observed`，不误算成「未发出」的抑制。

### 3. 代码、规则与反馈引用

- `codeVersion={commit,dirty}` 从本程序代码所在仓库取得一次，不受调用者 cwd 或 `GIT_DIR` 等覆盖影响，不读取个人 Git 配置/凭据。启动后切分支不改进程身份；无 Git/取号失败明确为 null，不伪造提交。开发自测为启动时 HEAD + dirty 标记，不是尚未提交的本批最终提交号。
- 规则编号覆盖进行中、来源不可用、报信不匹配、24 小时搁置、loop 暂停/完成、授权等待、成员不可用、全部完成、30 分钟停滞。事实含成员结束/答完/未返回工具数量、活动时间、可用性、报信类型/时间及相关阈值；模型失败问题兜底与旧模型事实搁置也有独立编号。原模型判定仍由 `model_checked` 表达。
- `Feedback.context` 含 `asOf/eventId/capturedAt/sessions`。会话引用含 key、工具/会话号、状态、最后活动时间、原件指纹/范围，以及可用的规则/判断键。`eventId` 是完整事件流的已提交边界，不是活动文件行号，封存后仍可定位。
- `asOf` 是最近一次已提交检测的时间，`capturedAt` 是反馈处理时的取样时间；均不冒充两次检测之间的实时状态，也不把当前状态投射成迟到反馈原时间的状态。没有检测或状态不可用时明确未知，原反馈仍正常落盘。重投不改第一次上下文。
- 在模型/渠道等待前原子发布已有检测视图，收反馈不获取检测锁、不重放增长中的事件日志；复用已有判定，避免为埋点多做一次完整投影。

### 4. 原件范围

`Original.span={startLine,endLine,byteLength}`，一基、闭区间。范围选本次完整读取的原件前缀（第一行到最后已读取行），覆盖开工意图、追加要求和后续动作，不声称是最小证据片段；同一次流式读取计行、计字节，不为发卡片重读来源。

SHA-256 直接复用已有 `fingerprint`，按原始字节计算，包含 CRLF/LF、空行及当时末行，不重新序列化 JSON。原文件随后追加且旧末行无换行时，以 `byteLength` 限定原末行边界。旧记录缺范围不猜测补齐。

通常现有 `content.evidence.originals` 就是依据，不重复复制；若模型先判断、等待窗口后原件又增长，`sourceEvidence` 保存判断时范围，旧证据字段仍保留最新所见。读取故障有最后可见原件时同样补引用；完全没有读到的原件用空集合，不伪造指纹。所有这些字段不进入卡片显示。

## 每条记录的体积

自己用临时构造的「给商品列表加缓存」短会话测量；UTF-8 紧凑 JSON，表中字段增量包含相应键/逗号，不是固定配额。路径/正文/成员数、凭据引用数和数值位数会影响大小，gzip 后另计。

| 记录 | 本次样例增量 |
|---|---:|
| 每个事件的 `codeVersion` | 81 B（40 位提交号、dirty=true；false 多 1 B） |
| 一次 waiting 判断的 replay + 原件引用 + 事件版本 | 4337 + 250 + 81 = **4668 B**（返修后的全材料引用） |
| 一次 drift 判断的同上三项 | 4978 + 250 + 81 = **5309 B** |
| 每处已有 Original 新增的 span | **52 B**；复用 fingerprint，没有重复的 SHA-256 字段 |
| 一条变化规则附加到 scan_completed 的 ruleDecisions | **338 B**，另有事件版本；稳定状态不重抄规则事实 |
| 一条新增 duplicate_notice 抑制事件 | **522 B**，含整条事件及换行；相同抑制不每轮追加 |
| 普通单原件卡片 | 发件版本 81 + 既有证据新增范围 52 = **133 B**；仅依据不同才另加 sourceEvidence（该样例约 255 B） |
| 一条漏报反馈，一份会话引用 | context 596 + 版本 81 = **677 B**；会话引用数量增长时线性增加 |
| 待结算等待窗口的检查点索引，1 个成员/作用域 | 整个 waitingWindows 字段 **247 B**；不是每次扫描追加一份 |

普通未调用的额度/延期判断没有 replay 与判断原件副本；独立起草 replay 大小同样取决于完整实际提示词。`state.json` 和检查点中的派生索引会序列化相应新增字段副本，不能把上述事件增量当作整个数据目录的固定增长率；会话差量还包含既有差量指令封装。
