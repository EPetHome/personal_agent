## 实施

1. **三路反馈随点随记**：飞书按钮、飞书文字、本机命令统一使用独立 `.feedback.lock`，不再获取整轮检测的 `.detect.lock`。读取、核验历史、按渠道/事件去重和追加均在反馈短锁内；同步落盘后才确认「已记下」。检测/统计/复盘读取反馈也使用同一短锁，不读取追加中的半行。
2. **安全核对提醒**：发件读取和幂等追加使用 `.outbox.lock` 短锁，不涵盖通知/API；仍核对反馈指向的真实盯防提醒，不接受不存在提醒、错误按钮或未知引用。兼容原反馈文件，既有顺序、日期、渠道、关联和去重键不变，没有搬迁或重复导入。
3. **飞书确认不被慢卡片挡住**：卡片 API 与反馈确认分开发送锁，共享消息映射另以短锁保护。原消息幂等键不变。已有全部处理记录（包括失败、仅含 id、人工核销）均跳过，不补记旧失败；确认投递失败仅重试确认。
4. **失败按原因说人话**：处理记录区分提醒缺失、反馈格式、锁占用/超时、记录损坏、不安全文件、存储空间/权限/只读/读写错误、未知问题；保留原有按钮/经验不匹配类别。只存受控类别和固定短说明，不存凭证、模型原文、上游原始错误。确认投递的 `replyCategory` 不再覆盖处理失败类别。
5. **只量检测持锁**：服务每轮 `scan_completed / scan_failed` 追加 `durationMs`、`storeLockHeldMs`，分别为整轮耗时、该轮各阶段累计持有 `.detect.lock` 的时长（毫秒）。包含规则、结果落盘和复盘阶段；不含等锁及锁外模型等待。**未改 `agent.ts`，检测主流程原有加锁范围、判断和交付顺序保持不变**。新独立锁沿用可信 owner/PID 恢复规则，不清未知锁或活锁。
6. **卡片内容**：意图跳过结构化图片和文本里的图片/附件占位，取首条有文字的本人消息；全无文字时显示「意图不明」。Pi 在原有长度限制之前排除占位，避免超长占位挤掉真人文字。动作引子和后续列表作为整体选取并压成一行，允许截断但不只留引子。时间后加空格，每条复盘标题只显示一次、审阅按钮保留。会话错配文案明确同工具所有会话状态暂不能确认，其他工具继续检测；只改文案，不改规则。

使用与恢复说明在 `code/使用说明.md`「反馈与卡片批：升级与回退」；渠道说明同步更新。
