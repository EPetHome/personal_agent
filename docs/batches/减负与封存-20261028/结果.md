1. 停止指向该数据目录的全部旧版常驻、检测、收件/反馈写者，保留现场，不混跑版本。新版首次写入会自动生成上述整目录备份；从 `store_format.backup` 可查备份绝对位置。代码不清理人工升级前备份。
2. **整目录回退**：先停新版全部写者，再完整保留升级后目录。由获准协调方按批次流程回退代码（合入后为 `git revert -m 1 <本批合入提交>`），把升级前整目录备份复制到新的独立目录、令旧版配置指向副本；或由获准运维用该备份整目录替换运行目录。旧版不能直接读取新版差量/检查点；升级后新增事件和反馈仍保存在新版现场，不能冒称已恢复进旧副本。
3. **当前版本用归档还原日志**：活动检查点可读、归档齐全时，停写并保留整个当前目录，在独立恢复目录创建新输出：

   ```sh
   RECOVERY=$(mktemp -d "${TMPDIR:-/tmp}/personal-agent-recovery.XXXXXX")
   node code/src/cli/main.ts restore-events --config "$CONFIG" --output "$RECOVERY/events-restored.jsonl"
   ```

   按检查点列出的已提交顺序解压，核对 SHA256，接活动事件并排除派生检查点；输出含完整新版原始事件，拒绝覆盖已有文件。若需要启用，将当前完整数据目录再复制到独立副本，用输出替换**副本**中的 `events.jsonl`，同版配置指向副本后 `rebuild` 核对。其他发件/反馈/学习文件不回退、不混拼；原目录与所有归档保留。该完整日志仍含新版差量，不能给旧版使用。
4. 活动检查点不可读时使用完整备份，不猜归档链；归档缺失/损坏时恢复命令失败并清理本次不完整输出，不改原日志。正常检测不依赖归档可读，但这不等于归档可以删除。
