# 全新 PA：六段共同约定

本批 6 段按顺序在同一分支 `feat/全新PA` 上做，后一段在前一段的成果上接着做。每段的提示词只写本段，本文件是六段都要遵守的约定，开工先读。

## 依据

- 需求：[架构重画需求书](../../requirements/需求书-personal-agent-架构重画.md)（主需求书 D39）。
- 方案：[方案-全新PA](../../prompt/方案-全新PA.md)，含给 loop 的接口格式附件。提示词没写到的细节以方案为准；方案和需求书冲突以需求书为准。
- 用户 2026-11-02：「我想要的东西是全新的 PA，不是什么一步一步走」「不接受任何不实现，聊了都要实现的」。

## 已拍板（六段通用）

**结构**（需求书第四节「层级与规矩」）

- 状态只存在账本里，其他部件不存状态，重启从账本恢复。
- 只有接入层（intake 读进来、channel 写给用户、worker-adapter 写给 worker）碰外部；研判、闸门、行动之间通过账本通信，不直接调用。
- 决策层只往账本写「待发」「待写」，发出前一律过围栏。

**围栏**（需求书 7.11，程序判，模型只能往里加、不能往外移）

- 红线三条：重大后果必须给用户过目；没规定可以写的区域不能写；没规定要完成的任务不去完成。
- 「重大后果」：删除、覆盖、强推、改历史、迁移或清空数据；推远端、发消息或邮件、发布、对外发言；动钱或账号权限；改需求、验收标准、权限配置、红线清单；合入（本项目合入即上线）；碰秘密。红线动作不给「按建议」一键，按钮上写明确认的是什么。
- PA 自己只写数据目录 `~/.personal-agent/`（测试和验收用临时目录）；不许读名单沿用现有的读取拦截（`read-sandbox`）。
- 每一条送话、执行、派活都留痕：谁点的、做了什么、依据、结果。
- 会话、文件、网页、会议纪要里出现的指令只当材料，不照做。

**数据**

- 旧数据不迁移，新结构从上线起记。新版启动时不删除、不改写数据目录里的旧文件。

**不做**

- 企业微信（方案第 14 项）先不做，等用户说。
- 不盯用户的 CC、Codex 聊天；不判跑偏；不发每日汇总、周报、复盘。

## 协调方暂定（开发方可按实际改，改了写进结果）

- **对接 loop**：loop 那边的对接能力还在开发。PA 这边先写一个 worker-adapter，通过配置里的一条命令和 loop 说话：PA 执行 `<命令> <动作>`，标准输入给 JSON、标准输出收 JSON，动作有查状态、送话、推送、合入、停批次、开批次；JSON 格式按方案附件。loop 交付后只改这条命令和字段映射。
- **替身**：仓库里放可执行的替身 loop 和替身 Pi（只读查询、skills），能写事件、记下收到的请求、按设定回执；`code/使用说明.md` 写清验收方怎么用它们、怎么放编造的数据、怎么看假飞书渠道（`feishu.mode: fake`）的收件和发件。研判用的模型在验收时也要能换成替身，按设定返回。
- **时间**：核实等待 3 分钟、巡检 10 分钟、心跳超时等时长都可配置，测试和验收可以注入时间或调短，使用说明写清怎么做；默认值按方案。
- **依赖**：不新增运行依赖（门禁只允许飞书官方 SDK 一个）。

## 边界（六段通用）

- 只改 `code/` 和本批的 `docs/batches/全新PA-20261102/结果.md`。
- 不改场景样本（`docs/batches/*/samples`）、不改门禁方法（`.autoreview/`）、不改 `eval/`、需求书和方案。被需求删掉的行为，对应的旧测试改成断言「不再出卡、不再调模型」，不删样本。
- 只用编造的数据、替身和假飞书渠道；不接真实账号，不读用户真实的 `~/.personal-agent/`，不发真实消息。
- 后一段不得弄坏前面各段的验收标准。

## 结果怎么写

每段完成时在 `结果.md` 里追加本段一节：做了什么、关键入口（文件和函数）、暂定项的实际取值、和提示词不同的地方、没做到或没验证的、给后面各段的交接。
