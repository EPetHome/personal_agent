## 开工核实与实施

以下为开发方自行核实，不是协调方推断或独立评审结论。

1. **自动返修误算真人确实存在**：修改前用构造 Pi 树消息分别输入三种前缀，`isHuman` 均返回 `true`，解析后均新增一条 `humanRequestRefs`。修改后「【自动评审 · 第 N 次返修】」「【门禁 · 第 N 次返修】」「【自动验收 · 第 N 次返修】」均不算真人，即使带 human 元数据也排除；真人正文中提到这些字样不排除。另核实 Pi 原解析器会让自动 user 消息清掉 `assistantFinished`，现一并修正，避免自动消息取消旧等待或重置其计时。
2. **原入口核实有效**：`interaction.ts` 管五分钟门槛和渠道，`model-checks.ts` 也在模型候选阶段用同一旧门槛，因此不能只改 `planNotices`。现普通等待在候选、发件和埋点三个入口共用 `decideWaiting`。
3. **新规则**：停下前本成员最近真人输入严格小于10分钟，算正在聊；未在其他会话发言，等满20分钟才叫；停下后在其他会话发过言，等满25分钟且只走本机。其他会话仍等5分钟，渠道同样按停下后的跨会话活动分流。同成员接话取消未发普通等待。一次等待的跨会话活动锁存到事件投影/检查点，其他会话消失、后来安静或重启不会降回离场。
4. **合并通知**：同轮到点的普通等待只弹一条本机通知，列项目、会话号和回看命令；已缓存判断与本轮新判断也一起结算。**发件仍逐会话留事实**，以新增 `localBatch` 关联同一条通知，逐事实记投递成功/失败。这避免改变原有字段含义、去重、反馈和 CC 转达身份。飞书仍是原单会话卡片和原按钮；「在别处忙」的普通等待不发飞书。
5. **红线核实差异**：提示词说「照旧马上叫」，但原实现的授权推送也会等5分钟。本批按已拍板要求，等待中的授权推送及原红线规则命中的回复当轮双发，不套20/25/5分钟普通等候。盯防失明仍当轮叫；疑似跑偏、loop 暂停/完成、停滞的规则及卡片正文/按钮不变。
6. **兼容**：只新增配置和可选事件/通知字段；`delivery` 等旧字段不改义，旧卡已选出口不重算，不补飞书、不重弹成功通知。`notice_suppressed.waitingDecision` 留分类和实际间隔；检查点增加可缺省的 `waitingActivity`，旧检查点缺字段以空索引读取。无本批数据库迁移、无新数据文件、不改写旧事件/发件行。

关键代码：`code/src/core/{interaction,model-checks,judge,telemetry,events,agent,config,types,utils}.ts`、`code/src/sources/pi/index.ts`、本机渠道与通知文本。使用说明同步在 `code/使用说明.md`。

## 配置怎么改

在原来显式指定的配置 JSON 中加入以下 `waiting` 对象；也可以只填要改的一项。**正整数，单位分钟，缺省使用表中默认值；正常重启服务后生效。** 这些配置只影响普通「在等你」，不改跑偏/loop 暂停的五分钟。

```json
"waiting": {
  "awayMinutes": 20,
  "otherSessionMinutes": 25,
  "inactiveMinutes": 5,
  "activeConversationMinutes": 10
}
```

| 配置项 | 含义 |
|---|---|
| `waiting.awayMinutes` | 正在聊但停下后所有会话都没真人消息：等多久双发 |
| `waiting.otherSessionMinutes` | 正在聊但去过其他会话：等多久只叫本机 |
| `waiting.inactiveMinutes` | 其余会话：普通等候时间 |
| `waiting.activeConversationMinutes` | 最后一句真人输入距停下严格小于此值，才算正在聊 |

例如只改离场为10分钟：`"waiting": { "awayMinutes": 10 }`。实际发出为阈值后的下一轮检测/判断完成时，不承诺精确到秒。
