## 已实施

- `code/src/core/managed-loop.ts`：发卡先读一个快照，内存索引渠道历史，只为发送、更新、重试或遗留 sending 核销开事务。会议前后复核、版本/围栏、防重、不确定不新发、五次上限保留。旧 episode 故障卡优先沿用已送达者；其余旧卡只作历史，不补发、不改写历史。
- `code/src/core/managed-actions.ts`、`task-actions.ts`：预筛 pending/sending；已结束待写不逐项开事务，尚待原卡送达且原因未变的派工不反复开事务。实际派出前仍重核全部围栏和预算。
- `code/src/core/ledger.ts`：进程内保存不可变已校验快照、位置、文件身份/纳秒时间、原边界行和校验链尾；只解析新增事务，本进程 fsync 成功后按实际 JSON 字节推进缓存。按需复制变更表，失败事务不污染缓存；缓存与完整重放的字段省略、表原型及各表内容一致。截短（包括删掉完整末行）、替换、原地修改、坏行、断链回全链校验；损坏不返回旧缓存、不截断或追加。
- `code/src/core/source-intake.ts`：轮询节拍只在内存，重启立即查，不再写 poll 回执；相同日程且已知窗口仍覆盖当前时间时不重复落账。假日程文件未变时不重复预读/写读审计。
- `code/src/core/runtime-state.ts`、`code/src/service/heartbeat.ts`：`runtime-state.json` 覆盖保存 `startedAt/runId/completedAt/inspectedAt`；启动不伪造已完成，只有主流程成功完成一轮才刷新 completedAt。独立心跳不碰账本锁，通知尝试/去重覆盖写 `heartbeat-alert.json`；并发、通知未确认和重启不重复通知，恢复后报健康。两个小文件均经安全普通文件检查、临时文件 fsync 和原子替换发布。
- `code/src/core/managed-health.ts`、`watchdog.ts`：按处理、派工、送话、执行及各类来源故障归并；复发和恢复沿原卡更新。标题/事实写明故障、影响和要不要用户处理，内部类别仅放依据。请求级失败事实保留，迟到旧成功不能冲掉后来的失败；正常服务恢复也能核销故障，重启风暴须稳定经过原重启窗口才恢复。
- `code/src/service/daemon.ts`：每轮日志新增 `ledgerFullReads`，按该异步主轮统计整本解析重放次数。`code/使用说明.md` 补充小状态、缓存校验、回退及构造长跑入口。

### 有意保留的边界

1. 跨进程追加除了接新增校验链，还核对旧前缀的**原字节摘要**，不重解析旧事务。只检查末行无法发现“改中段后再追加”，因此这里额外读旧字节，不能把它说成所有场景完全不碰旧字节；正常空轮和本进程追加无需这步。`ledgerFullReads` 统计重放，不把字节摘要冒充重放。
2. 旧行、旧表和旧卡保留，不做数据迁移。业务仍只以账本为准，小文件仅存获准的运行信号。原生本机通知没有更新接口：同类故障不再重复弹，恢复可提示一次；飞书沿同一 messageId 更新。
