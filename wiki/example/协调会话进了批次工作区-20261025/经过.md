# 协调会话进了批次工作区（2026-10-25）

- 场景：闭环 1 第一批 loop 完成后，协调方（Claude Code）为了复核，在批次工作区 `.worktrees/闭环1-感知与总览/` 里执行命令。Claude Code 把会话主工作目录切到了该工作区。
- 现象：从下一条用户消息起，每条都带上 loop 插件注入的开发方约定，开头是「【自动评审约定】交付时最后一行写【交付完成】……」，以及门禁约定「交付后由程序统一执行完整门禁：bash code/deploy/check.sh」。说明 loop 的 Claude Code 插件在工作区里找到了 `.autoreview.json`，把协调会话当成开发会话。
- 风险：协调方若在工作区里改文件（如补结果），loop 会对协调会话发起评审，账目混乱，还会多跑一轮评审。
- 处理：没有在工作区里改文件；合入并删除工作区后，主工作目录回到项目根，注入消失。
- 来源：本次协调会话（用户在场）。
