# 协调方不进批次工作区

> ⚠️ 失效（2026-10-25）：loop 自 `5faf8f1`（宿主插件按启动方式生效）起，只有通过 `bin/pi-dev` / `bin/loop` 启动、带 `AUTOREVIEW_DEV_ROOT` 的会话才进自动评审。协调会话即使 `cd` 进工作区，也不会被当成开发会话。新版 `bin/loop 开工` 还要求工作区放在运行版目录外，不再嵌在项目根里。仍然有效的只有 AGENTS.md 那条：批次进行中不改工作区里的文件。

**原做法**：协调方核对批次时，命令一律用绝对路径从项目根发出（如 `git -C <工作区>`、`bash <工作区>/code/deploy/check.sh`），不要 `cd` 进 `.worktrees/<批次>/` 后继续干活；需要改批次结果，等合入后在项目根改。

**原因**：当时工作区里有 `.autoreview.json`，Claude Code 会把会话主目录跟着切过去，loop 插件随即把协调会话当成开发会话：注入开发方约定，协调方一改文件就可能触发评审。

**失效条件**：loop 插件改为按启动方式识别开发会话。上面写明已经满足。
