# 调研：让 AI 实机操作电脑的现成工具

调研基准日：2026-10-26，America/New_York。面向 macOS 本机运行的 personal agent，以及将来像真实用户一样操作软件的端到端验收。

本次只读取公开网页、GitHub、官方文档、公开论文摘要和评测材料；没有安装、启动、调用被调研软件，没有登录账号，也没有执行模型、桌面操作或业务测试。本文件是调研快照，不代表项目已选型、已接入或验收通过。

## 1. 结论

📍 **直接答案：现成组件已经能覆盖大部分需求，优先选“可控的桌面驱动＋macOS 虚拟机＋结构化证据”，没有必要先换掉个人助理的智能体框架；但尚不能把任一项目视为已经验证可靠的高权限全自动执行与验收成品。**

最推荐以下两个组合，第一项优先：

1. **Cua Driver＋Lume＋Driver 自带动作记录/状态检查，网页保留 Playwright Test/Trace。** 理由：同一驱动提供 macOS AX/截图、窗口绑定、能力白名单、有限时批处理，以及动作前后 JSON/截图，最接近“既执行又能由程序检查”的要求；Lume 提供真正的 macOS VM。[驱动][A3d]、[权限][A3g]、[证据与时限][A3r]、[虚拟机][D1]
2. **Peekaboo＋Lume＋capture action / verify_state，网页仍用 Playwright Trace。** 理由：macOS 专用 CLI/MCP 易于交给现有编程智能体，capture action 已明确描述超时、进程组清理、截图及文件校验，适合范围明确的短步骤；单次 capture 最长 180 秒，长任务和业务断言仍需上层组织。[MCP][B1m]、[留证据][B1c]、[执行轨迹][B1a]

这些是**基于文档的推荐组合，未做组合实测**。Cua Driver 的默认 standard 模式允许普通点击和输入，不会自动理解每一次“发送、删除、授权”的业务后果；要用于高权限软件，仍需将具体业务动作的授权、停止条件和结果检查写在执行流程中。bounded 模式能限制工具与应用范围，却不能把允许应用里的所有点击都变成安全动作。Peekaboo 的前台授权也不等同于业务授权。[Cua 权限边界][A3g]、[Peekaboo MCP][B1m]

**验收侧另有两个值得看的补充：Midscene 已支持 macOS 桌面，适合视觉操作和报告；Appium Mac2 适合用 XCTest 元素属性做稳定的桌面检查。** 前者的 aiAssert 仍是模型判断，后者需要 Xcode/Appium 环境，均不必因为本次调研就全部引入。[Midscene][F1d]、[Mac2][B6start]

本轮最影响选择的事实：

- **Terminator 当前核心只支持 Windows；browser-use/macOS-use 已归档。** 另一个 Mediar macos-use MCP 是不同项目，许可证是 BSL，有使用限制。[Terminator][B2]、[归档项目][B4]、[Mediar 许可][B3lic]
- **Cua 已调整产品和接口。** 当前应看 Driver、SDK、Lume/Spaces；主仓库明确旧 cua-agent、cua-computer 等停止维护，不能照旧文章选型；Spaces 等也不是统一 MIT。[Cua 当前 README][A3]
- **AutoCua 文档称会自动同意 macOS 权限弹窗。** 对本项目的高权限操作，这使它不适合作为默认执行底座；这是公开文档中的行为声明，本轮未运行复现。[AutoCua][A5]
- **官方桌面产品已经能操作 Mac，但“我能在 Claude/Codex 里用”不等于“personal agent 可直接嵌入它的后端”。** 公共 API、开源样例和闭源桌面产品必须分别评估。[Claude 产品][E2]、[OpenAI 产品][E3app]、[OpenAI 样例][E3repo]

## 3. 分类详述

### A. 通用电脑操作智能体框架

**最适合我们先接的是 Cua 的驱动层，不是再套一整套自主规划框架。** personal agent 已有任务与判断流程，桌面驱动能让原有 LLM 调用观察、点击、输入和验证工具。Cua Driver 同时提供 AX 和像素路线；它明确区分“事件已发送”和“应用状态已读回确认”，对 Electron 等不能可靠读回的情况返回 unverifiable。这比只返回一个 success 更有用，但 confirmed 仍只是当前动作/属性级确认，不代表整项业务完成。[工作原理][A3d]、[平台覆盖][A3p]

**Agent S 和 UI-TARS 更适合研究规划与视觉定位。** Agent S3 有公开评测、SDK 和本机使用路径，S4 则是自动改进工具接口的研究系统，不能把 S4 当作 S3 的直接升级包。UI-TARS 的 Desktop、实验 SDK 和 Agent TARS 是同仓库内不同层次：Desktop 偏截图动作模型，Agent TARS 才扩展到 CLI、DOM 和 MCP 工具组合。二者都不是已经包含我们全部业务审批与证据验收的成品。[S3][A1s]、[S4][A1s4]、[TARS][A2]、[实验 SDK][A2sdk]

**OpenGCUA 值得跟踪，当前宜当设计参考。** 它把 AX、应用 API、脚本和 GUI 放进同一程序，减少“每点一次都问模型”的往返；公开了八种模型的轨迹。但 Mac harness 与跨设备 SDK 明确是初步版本，四个真实 Mac 任务不足以说明一般场景可靠性；它复用 CuaDriver，也不应被当成一套完全独立的底层控制方案。[项目][A4]、[论文摘要][A4paper]、[轨迹说明][A4trace]

**AutoCua 和 TuriX 都贴近个人电脑使用，但推荐顺位较低。** AutoCua 的 AX/OCR、iOS 和录制能力很丰富，然而自动允许 TCC 弹窗与本项目的授权需求冲突；它的 success 定义还是调用 done。TuriX 有 Mac 优先路线、任务恢复和多模型配置，适合观察真实工作流；其“Mac 80%+”是自建评测声明，未核实等价公开任务集、运行日志与复核条件，不能据此承诺我们的应用可达 80%。[AutoCua][A5]、[TuriX][A6]

### B. macOS 桌面控制：MCP、SDK、CLI

**Peekaboo 是最值得与 Cua Driver 对照的 macOS 专用候选。** 它把 AX、截图、菜单/窗口操作、工具过滤和执行轨迹放在同一工具中。capture action 的文档还明确了绝对时限、TERM/KILL 清理和产物校验；verify_state 允许用状态谓词轮询，不只让模型解释截图。需要保留两条边界：进程组清理不是恶意进程沙箱；截图哈希只能证明文件字节一致，不能证明“保存了正确的内容”。[记录与清理][B1c]、[状态检查][B1m]

**两种 macos-use 不要混淆。** browser-use/macOS-use 是已归档 Python 智能体项目；Mediar/mcp-server-macos-use 是 Swift MCP，官网声称有 InputGuard 和 Escape 取消，README 则主要介绍 AX 遍历和动作后差异。后者可以减少纯截图识别成本，但其“每步确认”依赖 MCP 客户端是否设置审批，且 BSL 许可不能按 MIT 理解。Terminator 虽与 Mediar 相关，当前功能表却写 Windows only，不能用它替代 Mac 驱动。[旧项目][B4]、[Swift MCP][B3]、[官网][B3site]、[许可][B3lic]、[Terminator][B2]

**AppleScript/JXA 适合有明确应用脚本接口的固定动作；Appium Mac2 适合稳定的桌面回归检查。** AppleScript MCP 能做 Calendar、Notes、Mail、Finder 等预设操作，不是任意应用都能点的工具。通过应用脚本直接改变数据可以提高执行效率，但如果本次验收要求“像用户一样点完流程”，绕过 GUI 的操作不能算覆盖了该界面。Mac2 通过 XCTest 获取元素与属性，支持脚本、截图和两种录屏路线；它比轻量 MCP 的环境要求重，却可给关键桌面结果提供程序断言。其录屏需要正确结束并取回输出，不能假设关闭会话后磁盘上一定留下视频。[AppleScript MCP][B5]、[Mac2 要求][B6start]、[扩展接口][B6exec]

### C. 浏览器操作

**继续保留 Playwright；Chrome DevTools MCP 作为诊断补充。** Playwright MCP 提供网页结构和动作，Playwright Test 才提供测试断言、报告、时限和 Trace；不能因为接了 MCP 就自动获得完整验收机制。Chrome DevTools 的优势是网络、控制台和性能诊断，它的性能 trace 不等于操作录像。Playwright 官方也提供面向编程智能体的 CLI，可以避免为了 Pi 强行再加 MCP 桥接。[Playwright MCP][C1]、[CLI][C1cli]、[DevTools][C2]

**browser-use 适合自主网页任务，Stagehand 适合“AI 找元素＋代码控制流程”。** browser-use 已明确单步及点击、导航等超时，也能保存历史并重跑；但历史里的成功字段仍需另查真实页面/数据。Stagehand 的 observe 返回 selector，可由代码接管输入与断言；本地 SDK 与 Browserbase 云端会话录像是两回事。两者都允许更换模型，却都不能解决 macOS 原生应用控制。[browser-use][C3]、[时限][C3a]、[浏览器范围][C3b]、[Stagehand][C4]

**page-agent 更适合嵌入自己的 Web 产品。** 当前仓库已提供 Chrome 扩展及 Beta MCP，不能再按“只能单页、无外部接口”的旧印象判断；但核心仍是 DOM/文本操作，不是全系统桌面控制。浏览器窗口隔离、域名限制也不应被写成完整的主机安全沙箱；Playwright MCP 明确提示部分 origin 限制不构成安全边界。[page-agent][C5]、[Playwright 安全边界][C1]

### D. 沙箱与虚拟桌面，尤其 macOS VM

**Lume 与 Tart 能提供真正的 macOS 客体系统，优先于拿 Linux Desktop 冒充 Mac 验收环境。** Lume 与 Cua SDK 集成较直接，也能通过 CLI/HTTP/MCP 管 VM；Tart 擅长镜像、克隆和 CI，仓库已从 cirruslabs/tart 转到 openai/tart，当前许可证是 FSL-1.1-ALv2。二者都依赖 Apple Silicon 路线，不能在未查本机硬件的情况下承诺直接运行。[Lume][D1]、[Tart][D2]、[Tart 许可][D2lic]

**虚拟机只提供隔离与可重置环境，不自动完成审批、录像和验收。** 驱动必须运行在实际要操作的客体会话中，TCC 权限、目标应用安装、应用账号与文件挂载需要单独配置；若将生产登录会话或真实目录传入 VM，隔离也不会让对外发送、删除或交易失去真实后果。这是根据组件边界作出的推断，不是本次做过的隔离测试。Cua Spaces 的会话迁移是另一层产品能力，不能默认开启或把它等同于纯 Lume。[Cua 分层说明][A3]、[Lume][D1]

**E2B Desktop 是 Linux 桌面，适合远端浏览器和 Linux GUI。** 它能从 Mac 客户端管理隔离桌面、截图、键鼠与直播，但不会因此变成 macOS。要验收 Preview、系统设置、Mac 专属权限弹窗或某个 Mac 原生客户端，不能用“Linux 上相似应用通过”代替。另须区别直播与录像：文档能显示实时画面，不等于每次运行都已保存可下载视频。[E2B Desktop][D3]

### E. 厂商官方能力

**Anthropic、OpenAI、Google 的 API 都是可接入的能力，执行环境和最终业务验收仍由应用负责。** Claude 当前文档有新的 computer toolset；官方还提供真正运行在 macOS 的教学示例及 JSONL/JPEG 轨迹，但该示例明确不应视为生产 SDK。OpenAI 样例现有 Playwright/JavaScript 和 PyAutoGUI/Python 两条路线，Python 代码调用有 60 秒期限与 Stop/failsafe。Gemini 当前文档已经包含桌面与移动环境；require_confirmation 必须由调用方等待真实用户，不是把字段返回 true 就完成授权。[Claude API][E1]、[Mac 教学实现][E1mac]、[OpenAI Python][E3py]、[Gemini API][E4]

**Claude 桌面版和 ChatGPT Work/Codex 的 Computer Use，可以作为现成体验入口，但公共嵌入接口不能想当然。** 官方文档已明确可操作 macOS，且支持应用权限与停止；Claude 文档还明确桌面应用之间没有沙箱。Chrome 扩展的 Manual/Auto/Skip 模式与桌面按应用权限是不同层次。当前读取的产品文档没有给出可让 personal agent/Pi 直接复用完整产品后端、导出全部证据并保障每步时限的公共接口，所以本轮不把它们列为可直接嵌入的首选底座。[Claude 桌面][E2]、[Chrome 权限][E2perm]、[Codex Computer Use][E3app]

**Fara 与 UFO 应分别按浏览器模型和 Windows/跨设备框架看。** Fara 当前已是 1.5 系列，有公开浏览器基准和开放权重；不是“微软的原生 Mac 控制 SDK”。UFO² 是 Windows 桌面路线，UFO³ Galaxy 增加跨设备编排，当前明确列出的设备支持包括 Windows、Linux、Android；架构图中画一个 Mac，不足以认定已发布可用 Mac 驱动。[Fara][E5]、[论文摘要][E5paper]、[UFO][E6]

### F. AI 驱动的端到端测试

**Midscene 是本次最值得补充了解的验收框架。** 当前支持网页、Mac/Windows/Linux 桌面及移动设备，能生成交互报告并导出截图和原始 JSON。它的步骤时限、准备/清理时限都已有文档，但超时通过取消信号传递：不响应信号的异步操作不会凭空停下。因此“配置了 120 秒”不能直接写成“120 秒后所有键鼠和子进程一定停止”。aiAssert 对外观很有价值，关键内容、文件或状态仍宜由独立代码规则确认。[桌面][F1d]、[报告][F1r]、[取消边界][F1t]

**Playwright Test Agents 值得复用，但应防止自动修测试掩盖产品错误。** planner/generator/healer 会探索、生成和修复测试；官方文档明确 healer 可能把认为功能坏掉的测试标为 skipped。因此必须检查原先要求的断言是否还在、用例是否跳过，不能只看最终退出码。固定 expect、测试结果 JSON/JUnit 与 Trace 组合，比“模型看完说通过”更适合程序验收；Electron 实验支持也不代表整个 macOS 系统都能由它操作。[Test Agents][F2a]、[时限][F2t]、[Trace][F2trace]、[Electron][F2e]

**Shortest、Octomind、QA Wolf 更适合参考不同的 Web/商业测试路线。** Shortest 是 Claude＋Playwright，可以用 after 回调补程序断言，但本次没有找到完整桌面能力。Octomind 官方组织描述标准 Playwright 的确定性执行，但公开 MCP 已归档、官网本次访问失败，服务是否仍接受新客户未核实。QA Wolf 当前已扩展移动和 Windows 原生测试，CLI 能按动作、截图、网络和日志读取证据；仍没有核实到 macOS 原生测试支持。不能把 CLI 能在 Mac 运行当作该支持。[Shortest][F3]、[Octomind][F4]、[归档 MCP][F4m]、[QA Wolf CLI][F5]、[Windows 发布][F5win]、[技术文章][F5tech]

### G. 护栏与审计

**动作约束优先放在真正执行动作的地方。** Cua Driver 的 bounded 清单能限制工具、应用、文件和生命周期；Peekaboo 可过滤工具并约束前台操作。agentgateway 适合以后集中管理多种 MCP，用 CEL 对工具和参数实施规则并留访问日志；但绕过代理的 CLI/脚本不受它保护，已发送到系统的点击也不会因代理超时被撤销。MagenticLite 提供 allow / require_approval / deny 的代码工具分类，浏览器关键点则依赖 Fara 的训练行为，不能把这套确认保证无条件套到其他模型。[Cua 权限][A3g]、[Peekaboo MCP][B1m]、[网关规则][G2auth]、[MagenticLite 说明][G1safe]

**审计平台、操作录像、结果检查器各有作用。** Langfuse 可以接入 trace、图片、代码评分，适合以后汇总多个工具的证据，但不是桌面录像机，也不会自动读取业务结果。OSWorld-V2 与 MacAgentBench 更值得借鉴的是任务专属检查器：由代码读取应用/文件状态，而不是让执行者给自己打分。前者主要是 Linux/网页长任务环境；后者确实面向 Mac，但公开启动脚本依赖 Linux KVM，不能直接当成 Apple Silicon Mac 的开箱即用 VM 方案。[Langfuse 代码评估][G3eval]、[媒体][G3media]、[OSWorld][G4]、[MacAgentBench][G5]、[KVM 脚本][G5start]

**对本项目，合格证据至少要区分三个问题。** 第一，发生了什么：执行器记录目标应用/窗口、动作参数、时间和结果，必要时附动作前后图像；第二，是否真的停了：时限到达后不能只返回 timeout 而让操作在后台继续；第三，事情是否做对：用预先确定的规则核对输出。比如让 Preview 保存一份脱敏 PDF，截图只能证明界面曾出现某内容，独立读取目标文件、页数和指定字段才能补上结果证据。这是本轮建议的验收方式，不是现有项目已经实现的功能。

下面几组现成机制与缺口尤其值得保留：

| 需要 | 已查到的现成机制 | 仍不能据此认定 |
|---|---|---|
| 人工确认与动作分级 | Cua 权限模式/清单；MagenticLite 代码分类；厂商产品应用审批 | “允许 click”不等于逐笔批准发送、删除、支付；模型提示自己询问也不是强制门禁 |
| 应用/工具白名单 | Cua capability manifest；Peekaboo allow/deny tools；agentgateway CEL | 有同权限的 Shell、AppleScript 或另一条 GUI 路径时，不能声称系统级不可绕过 |
| 急停与单步时限 | Peekaboo capture action 进程组期限；Cua 批次/脚本时限；Playwright 多层时限；Midscene 取消信号 | 超时返回、协作式取消、杀进程、停止 VM 的实际停止保证并不相同；没有本轮故障注入证据 |
| 操作留证据 | Cua 前后 AX/PNG/JSON；Peekaboo capture 产物与哈希；Midscene JSON 报告；Playwright Trace | 默认不一定录视频；可能部分捕获/截断；文件存在不等于内容与本次动作匹配 |
| 程序核对 | Cua/Peekaboo 原生属性检查；Playwright/Appium 断言；OSWorld/MacAgentBench 检查器；Langfuse 代码评分 | 模型生成的 success、aiAssert、最终总结，不自动变成独立事实 |
| 回放 | Playwright Trace 查看；Cua 轨迹重执行；browser-use 历史重跑 | “看录像”和“再次执行动作”不同；Cua 的旧 element token 不跨会话存活，重跑可能重复产生业务副作用 |

#### 补充线索：OmniParser 不是完整执行工具

OmniParser 将截图解析成文字、图标框和可定位元素，适合 AX/DOM 不可用的自绘界面。它本身不负责点击、权限、超时或业务成功检查；搭配 OmniTool 的演示也不能直接证明有可嵌入的 Mac 驱动。Cua 可选 perception 扩展使用了其中的检测能力，但并非所有 Cua 用户必须安装该扩展。[OmniParser][X1]、[Cua 可选视觉解析][A3d]

许可必须按具体内容核对：本次读取的 OmniParser 根 LICENSE 是 CC-BY-4.0，而 README 徽章显示 MIT；README 又区分新的 YOLOv9 检测器、旧 AGPL 检测器和 caption 模型。不能给整个项目统一贴 MIT，也不能把 Cua 当前使用的旧检测器许可套给所有新权重。[OmniParser README][X1]、[根 LICENSE][X1lic]

## 4. 没查到或拿不准的地方

1. **没有本机可用性结论。** 未探测本机芯片、macOS/Xcode 版本、权限、服务或已装软件；没有运行目标应用。表里的支持是来源声明，中文 UI、多显示器、Retina、自绘控件、Electron、后台窗口、锁屏与睡眠兼容性均未在这台 Mac 验证。
2. **没有任何组合的端到端可靠性测量。** 推荐组合尚未接入 personal agent；不知道具体高权限软件及其业务动作，无法宣称已经覆盖授权、异常恢复与最终结果判断。
3. **急停的“停止执行”保证仍需实测。** 公开参数足以证明有设计入口，不足以证明系统 API 卡住、网络请求挂起、子进程脱离进程组或工具崩溃时仍能及时停止。本次没有运行故障注入、超时或清理测试。
4. **全局 OS 权限与业务权限不同。** Accessibility/Screen Recording 授权不是管理员授权；能操作普通窗口不等于能处理所有受保护提示、密码、TCC、提权界面。尤其不应把自动点同意当成“有人确认”。
5. **厂商桌面产品的可嵌入性不明。** Claude/Codex 自身可操作 Mac 已有官方说明，但给第三方 personal agent 复用完整后端、逐步证据批量导出、单步硬期限的公共契约，本轮未核实。API 和示例可自行封装，不等于拥有产品内部全部保护。
6. **Pi 的具体接法未检查。** 有 CLI 的工具可由具备命令工具的 Pi 调用；仅 MCP 的项目需 Pi 相应扩展/桥接。本次未读取或运行 Pi 配置，不能声称其当前会话已经能接 MCP。Claude Code/Codex 的文档配置同样不是本机已接入证据。
7. **商业服务现状存在缺口。** Octomind MCP 归档已核实；官网一次502不证明停服，当前套餐、登录后功能、数据保留与支持状态未核实。其他 SaaS 的账号资格、价格、合同和企业权限也未登录检查。
8. **公开模型成绩不能当通用工程承诺。** 本次读取论文摘要、项目说明和公开轨迹入口，没有下载重放全部数据，也没有把不同模型、步数、样本、重试、partial/binary 结果排成统一榜单。
9. **版本与许可证存在需要固定的地方。** Cua 按组件分许可；Tart 已迁移且是 FSL；Mediar macos-use 是 BSL；Langfuse ee 目录另有许可；OmniParser README/根许可与权重许可不同。这里记录事实，未完成面向具体分发用途的许可审查。
10. **证据完整与证据可信是两件事。** 当前没有核实到一个直接可拿来用、同时保证 Mac 全应用覆盖、语义级审批、不可绕过急停、硬超时、不可篡改留档和独立业务断言的完整产品。截图/trace 的生成、哈希、保存期限、访问权限及异常时缺失状态，仍要按实际执行流程检查。
